1. Work order: base → components → sections

На уроке 29 мы уже говорили о правильном порядке CSS. Повторим: снизу вверх. Сначала атомы, потом компоненты, потом секции. Это правило ещё важнее в реальном проекте.

2. CSS reset — что убираем, что ставим

2. CSS reset — what to remove, what to set

У каждого браузера есть встроенные стили по умолчанию: h1 имеет margin, список с буллитами, ссылка подчёркнута и синяя. Эти стили разные в Chrome, Safari, Firefox — из-за этого сайт выглядит по-разному в разных браузерах.

CSS reset обнуляет эти стили, чтобы все браузеры стартовали «с одной точки». Это первое, что вы пишете в проекте.

Every browser has built-in default styles: h1 has margin, list has bullets, link is underlined and blue. These differ between Chrome, Safari, Firefox — so sites look different across browsers.

CSS reset zeroes out these styles so all browsers start "from the same point". The first thing you write in a project.

/* base.css */

/* 1. Универсальный сброс */
*, *::before, *::after {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

/* 2. Убираем маркеры у списков, стилизуем в своём коде */
ul, ol {
    list-style: none;
}

/* 3. Ссылки: без подчёркивания, наследуют цвет */
a {
    color: inherit;
    text-decoration: none;
}

/* 4. Изображения не вылезают за родителя */
img, svg {
    max-width: 100%;
    height: auto;
    display: block;
}

/* 5. Кнопки/инпуты наследуют шрифт */
button, input, textarea, select {
    font-family: inherit;
    font-size: inherit;
    color: inherit;
}

/* 6. Плавная прокрутка для якорных ссылок */
html {
    scroll-behavior: smooth;
}

/* 7. Отступ сверху, когда якорь под fixed header */
html {
    scroll-padding-top: 80px;
}

box-sizing: border-box. Самое важное правило. По умолчанию width: 300px = ширина контента. Padding и border добавляются сверху → блок становится шире. С border-box — width: 300px включает padding и border. Интуитивнее и предсказуемее. Индустриальный стандарт.

box-sizing: border-box. Most important rule. By default width: 300px = content width. Padding and border add on top → block gets wider. With border-box — width: 300px includes padding and border. More intuitive and predictable. Industry standard.

Не используйте старые reset'ы. «Meyer reset» или «normalize.css» — старая школа, сбрасывают всё включая полезное. Современный reset — минималистичный (как выше). Если нужен совсем готовый — используйте Josh Comeau's CSS Reset (поисковик найдёт).

Don't use old resets. "Meyer reset" or "normalize.css" — old school, reset everything including useful defaults. Modern reset is minimalist (like above). For a ready-made option — use Josh Comeau's CSS Reset (Google it).

3. Типографика: система h1-body

3. Typography: h1-body system

После reset заголовки и параграфы — «голый» текст одного размера. Нужно задать типографическую систему: размеры, веса, межстрочный интервал для body и всех h1-h6. Это делается один раз в base.css, и потом работает везде без дополнительных стилей.

After reset, headings and paragraphs are "naked" text of one size. You need to set up a typographic system: sizes, weights, line-height for body and all h1-h6. Do this once in base.css, and it works everywhere without extra styles.

/* base.css — после reset */

body {
    font-family: var(--font-primary);
    font-size: var(--fs-body);         /* 16px */
    line-height: 1.6;
    color: var(--color-text);
    background: var(--color-bg);
}

/* Заголовки */
h1, h2, h3, h4 {
    font-weight: 700;
    line-height: 1.2;                  /* короче для заголовков */
    color: var(--color-text);
}

h1 {
    font-size: var(--fs-h1);           /* 48px */
    letter-spacing: -0.02em;            /* -2% для плотности */
}
h2 { font-size: var(--fs-h2); }        /* 32px */
h3 { font-size: var(--fs-h3); }        /* 20px */
h4 { font-size: var(--fs-h4); }        /* 18px */

/* Параграфы */
p {
    margin-bottom: var(--space-md);     /* 16px между абзацами */
}

/* Выделения */
strong { font-weight: 700; }
em { font-style: italic; }

/* Код и маленький текст */
small { font-size: var(--fs-small); }  /* 14px */

Пояснение ключевых свойств:

Правило em для letter-spacing. Используйте em, не px. em = относительно текущего font-size. letter-spacing: -0.02em на h1 (48px) даст -0.96px. На h2 (32px) тот же код даст -0.64px. Масштабируется автоматически.

em rule for letter-spacing. Use em, not px. em = relative to current font-size. letter-spacing: -0.02em on h1 (48px) gives -0.96px. On h2 (32px) same code gives -0.64px. Scales automatically.

4. Ссылки: базовый стиль

4. Links: base style

В reset мы убрали стандартный стиль ссылок (синий + подчёркивание). Теперь нужно задать свой — для всех <a> по умолчанию. Правило: ссылки в тексте выглядят как ссылки (подчёркнуты или цветные), ссылки в навигации — просто текст.

The reset removed the default link style (blue + underline). Now set your own — for all <a> by default. Rule: links in text look like links (underlined or colored), links in navigation — plain text.

/* Базовый стиль ссылки */
a {
    color: var(--color-primary);
    text-decoration: none;
    transition: color 0.2s;
}
a:hover {
    color: var(--color-primary-dark);
    text-decoration: underline;
}

/* Ссылки внутри параграфов всегда подчёркнуты */
p a {
    text-decoration: underline;
    text-underline-offset: 3px;     /* отступ линии от текста */
}

/* Ссылки навигации — без подчёркивания */
.nav a,
.footer a {
    text-decoration: none;
}
.nav a:hover {
    color: var(--color-primary);
    text-decoration: none;
}
Контраст цвета важен. Цвет ссылки должен быть заметно отличаться от основного текста. Минимум WCAG AA: контрастность 4.5:1. Проверка: webaim.org/resources/contrastchecker.
Color contrast matters. Link color must be noticeably different from main text. WCAG AA minimum: 4.5:1 contrast. Check: webaim.org/resources/contrastchecker.

5. Контейнер: паттерн .container

5. Container: .container pattern

.container — это обёртка, которая ограничивает ширину контента и центрирует его. Используется на каждой секции: хоть header, хоть hero, хоть footer. Без контейнера на больших экранах контент растянется на 2000px — нечитаемо.

.container — a wrapper that limits content width and centers it. Used on every section: header, hero, or footer. Without it, on large screens content stretches to 2000px — unreadable.

.container {
    width: 90%;
    max-width: 1200px;
    margin: 0 auto;
    padding: 0 var(--space-md);        /* 16px по бокам */
}
На экране 1920px: ├───── 1920px (весь viewport) ──────┤ │ │ │ ┌────────────────┐ │ │ │ .container │ │ │ │ max-width: │ │ │ │ 1200px │ │ │ │ центр. │ │ │ └────────────────┘ │ │ │ │← auto →│ │← auto →│
On 1920px screen: ├───── 1920px (full viewport) ──────┤ │ │ │ ┌────────────────┐ │ │ │ .container │ │ │ │ max-width: │ │ │ │ 1200px │ │ │ │ centered │ │ │ └────────────────┘ │ │ │ │← auto →│ │← auto →│

Широкий фон, узкий контент. Если нужна секция с градиентом на всю ширину, но контент ограничен 1200px — фон ставьте на <section>, а .container внутрь:

<section class="hero">     <!-- фон на всю ширину -->
    <div class="container"> <!-- контент ограничен -->
        <h1>...</h1>
    </div>
</section>

Wide background, narrow content. If you need a full-width gradient section but content limited to 1200px — put the background on <section>, and .container inside:

<section class="hero">     <!-- full-width bg -->
    <div class="container"> <!-- limited content -->
        <h1>...</h1>
    </div>
</section>

6. Кнопки: .btn + модификаторы

6. Buttons: .btn + modifiers

Кнопка — самый частый элемент на сайте. Используется 10-30 раз на странице. Писать стиль для каждой кнопки отдельно — ад. Решение: базовый класс .btn со всеми общими стилями + модификаторы для разных вариантов.

A button is the most common element on a site. Used 10-30 times per page. Writing style for each separately — hell. Solution: base class .btn with all common styles + modifiers for variants.

/* components.css */

/* Базовый класс: общее для всех кнопок */
.btn {
    display: inline-flex;
    align-items: center;
    justify-content: center;
    gap: var(--space-sm);
    padding: 12px 28px;
    font-size: var(--fs-body);
    font-weight: 600;
    line-height: 1;
    border: 2px solid transparent;
    border-radius: var(--radius-md);
    text-decoration: none;
    cursor: pointer;
    transition: all 0.2s ease;
    white-space: nowrap;
}

/* Модификаторы цвета */
.btn-primary {
    background: var(--color-primary);
    color: white;
    border-color: var(--color-primary);
}
.btn-primary:hover {
    background: var(--color-primary-dark);
    border-color: var(--color-primary-dark);
}

.btn-outline {
    background: transparent;
    color: var(--color-primary);
    border-color: var(--color-primary);
}
.btn-outline:hover {
    background: var(--color-primary);
    color: white;
}

.btn-ghost {
    background: transparent;
    color: var(--color-text);
    border-color: transparent;
}
.btn-ghost:hover {
    background: var(--color-bg-alt);
}

/* Модификаторы размера */
.btn-sm { padding: 8px 16px; font-size: var(--fs-small); }
.btn-lg { padding: 16px 36px; font-size: 18px; }

/* Модификатор ширины */
.btn-full { width: 100%; }

Использование:

<a href="#" class="btn btn-primary">Заказать</a>
<button class="btn btn-outline">Подробнее</button>
<button class="btn btn-primary btn-lg">Большая CTA</button>
<button class="btn btn-ghost btn-sm">Малая ссылка</button>
<button class="btn btn-primary btn-full">На всю ширину</button>

Два класса — и получаете любую нужную кнопку. Это и есть component pattern.

Usage:

<a href="#" class="btn btn-primary">Order</a>
<button class="btn btn-outline">Learn more</button>
<button class="btn btn-primary btn-lg">Large CTA</button>
<button class="btn btn-ghost btn-sm">Small link</button>
<button class="btn btn-primary btn-full">Full width</button>

Two classes — any button you need. That's the component pattern.

7. Состояния кнопок

7. Button states

Кнопка должна реагировать на взаимодействие: hover (курсор навёлся), focus (в фокусе, например с клавиатуры), active (нажата), disabled (неактивна). Каждое состояние визуально отличается.

A button must react to interaction: hover (cursor over), focus (focused, e.g., via keyboard), active (pressed), disabled (inactive). Each state visually distinct.

.btn {
    /* базовые стили */
    transition: all 0.2s ease;
}

/* hover — курсор наведён */
.btn:hover {
    transform: translateY(-2px);
    box-shadow: var(--shadow-md);
}

/* focus — в фокусе (клавиатура) */
.btn:focus-visible {
    outline: none;
    box-shadow: 0 0 0 3px rgba(59, 130, 246, 0.4);
}

/* active — нажата */
.btn:active {
    transform: translateY(0);
    box-shadow: var(--shadow-sm);
}

/* disabled — неактивна */
.btn:disabled,
.btn.disabled {
    opacity: 0.5;
    cursor: not-allowed;
    transform: none;
    box-shadow: none;
}
.btn:disabled:hover {
    transform: none;
    box-shadow: none;
}
:focus-visible вместо :focus. :focus срабатывает всегда (даже при клике мышкой — появляется ненужная рамка). :focus-visible — только при клавиатурной навигации. Правильный выбор для accessibility.
:focus-visible instead of :focus. :focus triggers always (even on mouse click — unwanted ring). :focus-visible — only on keyboard navigation. The right choice for accessibility.

Не убирайте outline без замены! outline: none без box-shadow — катастрофа для доступности. Люди с клавиатуры не видят, где они находятся. Всегда замена: outline: none; box-shadow: 0 0 0 3px color;.

Don't remove outline without replacement! outline: none without box-shadow — accessibility disaster. Keyboard users can't see where they are. Always replace: outline: none; box-shadow: 0 0 0 3px color;.

8. Карточки: компонент .card

8. Cards: .card component

Карточка — второй по частоте компонент после кнопки. Товары, фичи, команда, отзывы — всё это карточки. По той же схеме: базовый класс + внутренние элементы + модификаторы.

Card is the second most common component after button. Products, features, team, testimonials — all cards. Same pattern: base class + inner elements + modifiers.

/* components.css */

.card {
    background: var(--color-bg);
    border-radius: var(--radius-lg);
    box-shadow: var(--shadow-sm);
    overflow: hidden;               /* обрежет картинку под скругление */
    transition: transform 0.3s, box-shadow 0.3s;
}

.card:hover {
    transform: translateY(-4px);
    box-shadow: var(--shadow-lg);
}

/* Элементы карточки */
.card-image {
    width: 100%;
    height: 240px;
    object-fit: cover;
}

.card-body {
    padding: var(--space-md);
}

.card-title {
    font-size: var(--fs-h4);
    font-weight: 700;
    margin-bottom: var(--space-sm);
    color: var(--color-text);
}

.card-text {
    color: var(--color-text-muted);
    margin-bottom: var(--space-md);
}

.card-footer {
    display: flex;
    align-items: center;
    justify-content: space-between;
    padding: var(--space-md);
    border-top: 1px solid var(--color-border);
}

.card-price {
    font-size: var(--fs-h3);
    font-weight: 700;
    color: var(--color-primary);
}

/* Модификаторы */
.card-outlined {
    box-shadow: none;
    border: 1px solid var(--color-border);
}

Использование:

Usage:

<article class="card">
    <img src="cake.jpg" alt="Торт Наполеон" class="card-image">
    <div class="card-body">
        <h3 class="card-title">Наполеон</h3>
        <p class="card-text">Классический многослойный торт с заварным кремом</p>
    </div>
    <div class="card-footer">
        <span class="card-price">450 TMT</span>
        <a href="#" class="btn btn-primary btn-sm">В корзину</a>
    </div>
</article>

overflow: hidden — обязательно. Без него картинка с прямыми углами «вылезет» за скруглённые углы карточки. overflow: hidden на родителе — картинка обрезается по форме родителя.

overflow: hidden — mandatory. Without it, a rectangular image "breaks out" of the card's rounded corners. overflow: hidden on parent — image clips to parent's shape.

9. Формы: input, textarea, focus-ring

9. Forms: input, textarea, focus-ring

Дефолтные стили input/textarea отличаются в Chrome/Safari/Firefox, да ещё и на мобильных. Надо их привести к единому стилю. Особенно важен focus-ring — визуальное обозначение фокуса.

Default input/textarea styles differ in Chrome/Safari/Firefox, and on mobile too. Bring them to a uniform style. Especially important — focus-ring, visual indication of focus.

/* components.css */

/* Общий контейнер поля формы */
.form-group {
    margin-bottom: var(--space-md);
}

/* Label */
.form-label {
    display: block;
    font-size: var(--fs-small);
    font-weight: 600;
    margin-bottom: var(--space-xs);
    color: var(--color-text);
}

/* Input и textarea — общий стиль */
.form-input,
.form-textarea {
    width: 100%;
    padding: 12px 16px;
    font-size: var(--fs-body);
    color: var(--color-text);
    background: var(--color-bg);
    border: 1px solid var(--color-border);
    border-radius: var(--radius-md);
    transition: border-color 0.2s, box-shadow 0.2s;
}

/* Focus state */
.form-input:focus,
.form-textarea:focus {

10. BEM-именование (опционально)

10. BEM naming (optional)

BEM (Block-Element-Modifier) — система именования CSS-классов, которую используют во многих командах. Делает код предсказуемым и самодокументируемым.

BEM (Block-Element-Modifier) — a CSS class naming system used by many teams. Makes code predictable and self-documenting.

ТипСинтаксисПример
Block.block.card, .btn, .header
Element.block__element.card__title, .btn__icon
Modifier.block--modifier.btn--primary, .card--outlined
TypeSyntaxExample
Block.block.card, .btn, .header
Element.block__element.card__title, .btn__icon
Modifier.block--modifier.btn--primary, .card--outlined
<!-- С BEM -->
<article class="card card--outlined">
    <img class="card__image" src="...">
    <h3 class="card__title">...</h3>
    <p class="card__text">...</p>
</article>

<!-- Без BEM (что мы делали выше) -->
<article class="card card-outlined">
    <img class="card-image" src="...">
    <h3 class="card-title">...</h3>
    <p class="card-text">...</p>
</article>
BEM — опция, не обязательство. Если вам нравится — используйте __ и --. Если нет — дефис-разделитель (card-title) тоже работает. Главное — единообразие в проекте.
BEM is optional, not mandatory. If you like it — use __ and --. If not — hyphen separator (card-title) works too. Main thing — consistency within the project.
