1. Зачем нужны таблицы

1. Why we need tables

Таблицы — это способ организовать данные в строки и столбцы. Они идеально подходят для отображения структурированной информации: расписаний, прайс-листов, статистики, сравнений.

Tables are a way to organize data into rows and columns. They are perfect for displaying structured information: schedules, price lists, statistics, comparisons.

Организация данных — одна из фундаментальных потребностей человечества. Вспомните школьный журнал: строки — это ученики, столбцы — даты, а ячейки — оценки. Или расписание поездов на вокзале, банковские выписки, меню в ресторане. Все это — таблицы. HTML даёт нам инструмент, чтобы представить такие данные в интернете.

Organizing data is one of humanity's fundamental needs. Think of a school gradebook: rows are students, columns are dates, and cells are grades. Or train schedules at a station, bank statements, restaurant menus. All of these are tables. HTML gives us a tool to present such data on the web.

Таблица в HTML — это как таблица в Excel. Есть строки (ряды), столбцы (колонки), и в каждой ячейке — данные. Только вместо Excel мы используем HTML-теги.

An HTML table is like a spreadsheet in Excel. There are rows, columns, and data in each cell. But instead of Excel, we use HTML tags.

Где вы видите таблицы каждый день:

Where you see tables every day:

  • Amazon / Wildberries — сравнение характеристик товаров (экран, батарея, процессор)
  • Авиакомпании — расписание рейсов (время вылета, прилёта, цена)
  • GitHub — списки репозиториев (звёзды, форки, язык)
  • Спорт — турнирные таблицы (команда, очки, голы)
  • Банки — история транзакций (дата, описание, сумма)
  • Расписание уроков / поездов / сеансов
  • Amazon — product specification comparisons (screen, battery, processor)
  • Airlines — flight schedules (departure, arrival, price)
  • GitHub — repository lists (stars, forks, language)
  • Sports — league standings (team, points, goals)
  • Banks — transaction history (date, description, amount)
  • Class / train / showtime schedules

Таблицы — один из старейших элементов HTML. Тег <table> появился в стандарте HTML 3.2 в 1997 году. В те времена таблицы использовались не только для данных, но и для вёрстки всей страницы! Сейчас для вёрстки используют Flexbox и Grid, а таблицы остались только для табличных данных.

Tables are one of the oldest HTML elements. The <table> tag appeared in the HTML 3.2 standard in 1997. Back then, tables were used not only for data but for laying out entire pages! Today we use Flexbox and Grid for layout, and tables are reserved for tabular data only.

2. Базовая таблица: table, tr, td

2. Basic table: table, tr, td

Для создания таблицы нужны три тега:

To create a table, you need three tags:

ТегРасшифровкаЧто делает
<table>tableСоздаёт таблицу (контейнер)
<tr>table rowСоздаёт строку
<td>table dataСоздаёт ячейку с данными
TagStands forWhat it does
<table>tableCreates a table (container)
<tr>table rowCreates a row
<td>table dataCreates a data cell

Эти три тега образуют иерархию вложенности: <table> содержит <tr>, а <tr> содержит <td>. Нельзя поставить <td> напрямую внутрь <table> без <tr> — браузер запутается, и таблица отобразится неправильно.

These three tags form a nesting hierarchy: <table> contains <tr>, and <tr> contains <td>. You cannot place <td> directly inside <table> without <tr> — the browser will get confused and the table will render incorrectly.

Электронная таблица (Excel / Google Sheets):

Spreadsheet (Excel / Google Sheets):

  • <table> = весь лист (Sheet1)
  • <tr> = одна строка (ряд 1, ряд 2, ряд 3...)
  • <td> = одна ячейка (A1, B1, C1...)
  • <table> = the entire sheet (Sheet1)
  • <tr> = one row (row 1, row 2, row 3...)
  • <td> = one cell (A1, B1, C1...)

Точно так же, как вы не можете ввести данные в ячейку, не выбрав строку — <td> всегда живёт внутри <tr>.

Just like you can't enter data in a cell without selecting a row — <td> always lives inside <tr>.

Situation: a beginner creates a table with 3 <td> cells in the first row but only 2 in the second. Result? The table breaks — columns won't align and everything looks crooked.

    </tr>

Rule: the number of <td> in each <tr> must be the same (unless using colspan/rowspan). If there's no data, use an empty cell: <td></td>.

3. Headers: th

Тег <th> (table header) — это ячейка-заголовок. Браузер автоматически делает текст в <th> жирным и центрированным.

The <th> tag (table header) is a header cell. The browser automatically makes text in <th> bold and centered.

th vs td: <th> — заголовок (жирный, центрированный). <td> — обычные данные. Используйте <th> в первой строке таблицы для названий столбцов.
th vs td: <th> — header (bold, centered). <td> — regular data. Use <th> in the first row for column names.

Доступность (Accessibility): тег <th> — не просто визуальное украшение. Он сообщает скринридерам (программам для слабовидящих), что эта ячейка является заголовком. Когда незрячий пользователь перемещается по таблице, скринридер произносит: «Фрукт: Яблоко, Цвет: Красный, Цена: 50 тг». Без <th> пользователь услышит просто «Яблоко, Красный, 50 тг» — без контекста.

Accessibility: the <th> tag is not just visual decoration. It tells screen readers (software for visually impaired users) that this cell is a header. When a blind user navigates the table, the screen reader says: "Fruit: Apple, Color: Red, Price: 50 tg". Without <th>, the user would hear just "Apple, Red, 50 tg" — with no context.

td (no header)
<tr>

  <td>Цвет</td>
</tr>

Визуально — обычный текст. Скринридер не знает, что это заголовки.

Visually — plain text. Screen reader doesn't know these are headers.

th (header)
<tr>
  <th>Фрукт</th>
  <th>Цвет</th>
</tr>

Жирный, центрированный. Скринридер понимает структуру.

Bold, centered. Screen reader understands the structure.

4. colspan — объединение столбцов

4. colspan — merging columns

Атрибут colspan позволяет ячейке занять несколько столбцов:

The colspan attribute allows a cell to span multiple columns:

Как объединение ячеек в Excel. Вы выделяете несколько ячеек в одной строке, нажимаете «Объединить» — и они превращаются в одну широкую ячейку. В HTML вместо кнопки «Объединить» мы пишем атрибут colspan="3", который означает: «эта ячейка занимает место трёх столбцов».

Like merging cells in Excel. You select several cells in one row, click "Merge" — and they become one wide cell. In HTML, instead of a "Merge" button, we write the attribute colspan="3", which means: "this cell takes up the space of three columns."

<table>
    <tr>
        <th colspan="3">Меню кафе</th>
    </tr>
    <tr>
        <th>Блюдо</th>
        <th>Порция</th>
        <th>Цена</th>
    </tr>
    <tr>
        <td>Плов</td>
        <td>300г</td>
        <td>45 TMT</td>
    </tr>
    <tr>
        <td>Шурпа</td>
        <td>350мл</td>
        <td>35 TMT</td>
    </tr>
</table>

Ситуация: новичок добавляет colspan="3", но оставляет все 3 ячейки <td> в этой же строке. Результат — в строке оказывается 5 столбцов вместо 3, и таблица «расползается».

Situation: a beginner adds colspan="3" but keeps all 3 <td> cells in the same row. Result — the row has 5 columns instead of 3, and the table breaks apart.

<!-- НЕПРАВИЛЬНО / WRONG -->
<tr>
    <th colspan="3">Заголовок</th>
    <td>Лишняя 1</td>  <!-- Убери! -->
    <td>Лишняя 2</td>  <!-- Убери! -->
</tr>

<!-- ПРАВИЛЬНО / CORRECT -->
<tr>
    <th colspan="3">Заголовок</th>
    <!-- Всё! Одна ячейка занимает место трёх -->
</tr>

Правило: когда используете colspan="N", уберите N - 1 ячеек из этой строки. Ячейка с colspan="3" заменяет 3 обычные ячейки, поэтому остальные 2 нужно удалить.

Rule: when using colspan="N", remove N - 1 cells from that row. A cell with colspan="3" replaces 3 regular cells, so the other 2 must be removed.

5. rowspan — merging rows

Атрибут rowspan позволяет ячейке занять несколько строк:

The rowspan attribute allows a cell to span multiple rows:

Самая коварная ошибка с rowspan: вы добавляете rowspan="2" к ячейке в первой строке, но забываете убрать соответствующую ячейку из следующей строки. В результате таблица «съезжает» — лишняя ячейка выталкивает остальные вправо.

The trickiest rowspan mistake: you add rowspan="2" to a cell in the first row but forget to remove the corresponding cell from the next row. The table shifts — the extra cell pushes others to the right.

<!-- НЕПРАВИЛЬНО / WRONG -->
<tr>
    <td rowspan="2">Понедельник</td>
    <td>09:00</td><td>HTML</td>
</tr>
<tr>
    <td>Понедельник</td>  <!-- ЛИШНЯЯ! rowspan уже занял это место -->
    <td>10:00</td><td>CSS</td>
</tr>

<!-- ПРАВИЛЬНО / CORRECT -->
<tr>
    <td rowspan="2">Понедельник</td>
    <td>09:00</td><td>HTML</td>
</tr>
<tr>
    <!-- Здесь НЕТ первой ячейки — rowspan её заменил -->
    <td>10:00</td><td>CSS</td>
</tr>

6. Структура: thead, tbody, tfoot

6. Structure: thead, tbody, tfoot

Для семантичности таблицу разделяют на три части:

For semantic clarity, a table is divided into three parts:

ТегРасшифровкаЧто содержит
<thead>table headШапка — строки с заголовками столбцов
<tbody>table bodyТело — основные данные
<tfoot>table footПодвал — итоги, суммы
TagStands forContains
<thead>table headHeader — rows with column titles
<tbody>table bodyBody — main data
<tfoot>table footFooter — totals, summaries

Зачем разделять таблицу на части, если визуально это ничего не меняет? Потому что семантическая структура помогает:

Why split a table into parts if it looks the same visually? Because semantic structure helps:

  • Браузеру — при печати длинных таблиц <thead> повторяется на каждой странице
  • Скринридерам — незрячие пользователи понимают, где заголовки, где данные, где итоги
  • CSS — можно стилизовать шапку, тело и подвал по-разному
  • JavaScript — легче обращаться к отдельным секциям таблицы
  • Browser — when printing long tables, <thead> repeats on each page
  • Screen readers — visually impaired users understand where headers, data, and totals are
  • CSS — you can style the header, body, and footer differently
  • JavaScript — easier to access specific table sections

Таблица — это как книга:

A table is like a book:

  • <thead> = оглавление — сразу видно, какие данные в каждом столбце
  • <tbody> = главы — основное содержание, ради которого мы открыли книгу
  • <tfoot> = приложение / итоги — выводы, суммы, общие результаты
  • <thead> = table of contents — immediately see what data is in each column
  • <tbody> = chapters — the main content we opened the book for
  • <tfoot> = appendix / summary — conclusions, totals, overall results

По умолчанию <caption> отображается сверху таблицы. Но с помощью CSS-свойства caption-side: bottom его можно переместить под таблицу — это удобно, когда подпись выглядит как сноска. Просто добавьте:

8. CSS: базовая стилизация

8. CSS: basic styling

Why do tables need styling? Because a default HTML table looks terrible — no borders, no padding, no background. Text merges together, data is hard to read. A few lines of CSS transform this "bare" table into a readable, professional component.

Почему separate — значение по умолчанию, а не collapse? Потому что стандарт CSS был написан в конце 90-х, когда таблицы использовались для вёрстки страниц. В те времена зазоры между ячейками были нужны для создания отступов в макете. Сегодня это наследие прошлого — почти все разработчики сразу добавляют border-collapse: collapse.

Why is separate the default value instead of collapse? Because the CSS standard was written in the late 90s when tables were used for page layout. Back then, gaps between cells were needed to create spacing in layouts. Today it's a legacy — almost all developers immediately add border-collapse: collapse.

Если вам нужны зазоры между ячейками (например, для карточного дизайна), используйте border-collapse: separate вместе с border-spacing: 8px. Это даёт контролируемые равномерные зазоры.

If you do need gaps between cells (e.g., for a card-style design), use border-collapse: separate together with border-spacing: 8px. This gives controlled, even gaps.

10. CSS: полосатая таблица (zebra)

10. CSS: striped table (zebra)

«Полосатая» таблица чередует цвет фона строк — это улучшает читаемость:

A "striped" table alternates row background colors — this improves readability:

/* Каждая чётная строка — серая / Every even row is gray */
tbody tr:nth-child(even) {
    background: #f8fafc;
}

/* Или каждая нечётная — серая / Or every odd row */
tbody tr:nth-child(odd) {
    background: #f8fafc;
}
Псевдокласс :nth-child(even) выбирает каждый чётный элемент (2-й, 4-й, 6-й...). :nth-child(odd) — каждый нечётный (1-й, 3-й, 5-й...).
Pseudo-class :nth-child(even) selects every even element (2nd, 4th, 6th...). :nth-child(odd) — every odd one (1st, 3rd, 5th...).

13. Когда НЕ использовать таблицы

13. When NOT to use tables

Таблицы — только для табличных данных! Не используйте <table> для:
  • Раскладки страницы (вёрстки) — используйте Flexbox или Grid
  • Создания колонок — используйте CSS
  • Навигации — используйте <nav> + <ul>
  • Карточек товаров — используйте <div> + Flexbox/Grid
Tables are only for tabular data! Do NOT use <table> for:
  • Page layout — use Flexbox or Grid
  • Creating columns — use CSS
  • Navigation — use <nav> + <ul>
  • Product cards — use <div> + Flexbox/Grid

История табличной вёрстки. В 1990-х и начале 2000-х сайты строились целиком на таблицах. Шапка сайта — строка таблицы, боковое меню — ячейка, основной контент — другая ячейка. Это было единственным способом создать многоколоночную раскладку. Посмотрите web.archive.org — там можно увидеть, как выглядели сайты Amazon, Yahoo, NASA в те времена. Все они были на таблицах!

History of table-based layout. In the 1990s and early 2000s, entire websites were built with tables. The site header was a table row, the sidebar was a cell, the main content was another cell. This was the only way to create multi-column layouts. Check web.archive.org — you can see how Amazon, Yahoo, NASA websites looked back then. They were all built with tables!

Ситуация: новичок хочет расположить 3 карточки товаров в ряд и использует таблицу: каждая карточка — ячейка <td>. Карточки вроде бы стоят в ряд, но:

Situation: a beginner wants to arrange 3 product cards in a row and uses a table: each card is a <td> cell. The cards seem to be in a row, but:

  • На мобильном телефоне таблица не адаптируется — карточки будут крошечными
  • Скринридер объявит «таблица» — незрячий пользователь будет искать табличные данные, а не карточки
  • Код становится запутанным — куча вложенных тегов
  • On mobile the table won't adapt — cards will be tiny
  • Screen reader will announce "table" — a blind user will expect tabular data, not cards
  • Code becomes confusing — lots of nested tags

Решение: используйте display: flex или display: grid на контейнере <div>. Это правильный, современный подход.

Solution: use display: flex or display: grid on a <div> container. This is the correct, modern approach.

Простое правило: спросите себя: «Эти данные имеют строки и столбцы с заголовками?» Если да — таблица. Если нет — используйте другие элементы.
Simple rule: ask yourself: "Does this data have rows and columns with headers?" If yes — table. If no — use other elements.
