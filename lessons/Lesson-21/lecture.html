1. Адаптивные единицы: %, vw, vh, rem, em

1. Responsive units: %, vw, vh, rem, em

До сих пор мы чаще использовали px — фиксированные пиксели. Написали width: 300px — блок всегда будет 300px, хоть на телефоне, хоть на мониторе. Это как носить одежду одного размера — на ком-то сидит идеально, а кому-то тесно.

Для адаптивного дизайна нужны относительные единицы — они подстраиваются под экран, родительский элемент или настройки пользователя.

So far we've mostly used px — fixed pixels. Wrote width: 300px — the block is always 300px, whether on a phone or a monitor. It's like wearing one-size clothes — fits some perfectly, too tight for others.

Responsive design needs relative units — they adapt to the screen, parent element, or user settings.

Линейка vs резинка. px — это жёсткая линейка: всегда одного размера. %, vw, rem — это резинка: растягивается и сжимается в зависимости от ситуации. Для адаптивного дизайна нужны «резинки»!

Ruler vs rubber band. px is a rigid ruler: always the same size. %, vw, rem are rubber bands: they stretch and shrink depending on the situation. Responsive design needs "rubber bands"!

2. % — проценты

2. % — percentages

Проценты — самая интуитивная относительная единица. width: 50% = половина ширины родителя. Родитель стал шире — блок тоже. Родитель сузился — блок сузился. Идеально для контейнеров!

Percentages are the most intuitive relative unit. width: 50% = half the width of the parent. Parent got wider — block did too. Parent narrowed — block narrowed. Perfect for containers!

.container {
    width: 90%;        /* 90% ширины родителя */
    max-width: 1200px; /* но не больше 1200px */
    margin: 0 auto;    /* центрирование */
}

img {
    width: 100%;       /* заполняет контейнер */
    height: auto;      /* сохраняет пропорции */
}
Классический паттерн контейнера: width: 90% + max-width: 1200px + margin: 0 auto. Работает на любом экране! На маленьком — контейнер занимает 90% ширины. На большом — останавливается на 1200px и центрируется.
Classic container pattern: width: 90% + max-width: 1200px + margin: 0 auto. Works on any screen! On small screens — container takes 90% width. On large — stops at 1200px and centers.

Где используют %: Почти все сайты оборачивают контент в контейнер с width: 90% (или 85%, или 95%) + max-width. Откройте любой сайт и посмотрите в DevTools — вы найдёте этот паттерн. YouTube, GitHub, Amazon — все используют его.

Where % is used: Almost all sites wrap content in a container with width: 90% (or 85%, or 95%) + max-width. Open any site and check in DevTools — you'll find this pattern. YouTube, GitHub, Amazon — all use it.

% от чего? Новички пишут height: 50% и удивляются, что ничего не работает. Помните: % считается от родителя. Если у родителя нет заданной высоты, то 50% от «ничего» = ничего. Для высоты используйте vh вместо %.

% of what? Beginners write height: 50% and wonder why nothing works. Remember: % is calculated from the parent. If the parent has no defined height, then 50% of "nothing" = nothing. For height, use vh instead of %.

3. vw и vh — единицы viewport

3. vw and vh — viewport units

% считается от родителя, а что если нужно занять весь экран — независимо от вложенности? Для этого есть vw (viewport width) и vh (viewport height). 1vw = 1% ширины окна браузера. 1vh = 1% высоты окна.

% is calculated from the parent, but what if you need to fill the entire screen — regardless of nesting? That's what vw (viewport width) and vh (viewport height) are for. 1vw = 1% of the browser window width. 1vh = 1% of the window height.

/* Hero-секция на весь экран */
.hero {
    width: 100vw;      /* вся ширина окна */
    height: 100vh;     /* вся высота окна */
}

/* Шрифт, который растёт с экраном */
h1 {
    font-size: 5vw;    /* 5% ширины экрана */
    /* 1440px экран: 5vw = 72px */
    /* 375px экран: 5vw = 18.75px */
}

/* Ограничение с clamp() */
h1 {
    font-size: clamp(1.5rem, 4vw, 3rem);
    /* мин 1.5rem, идеал 4vw, макс 3rem */
}

Телевизор. vh и vw — как размер телевизора. 100vh = весь экран телевизора. 50vh = ровно половина экрана. Не важно, 32 дюйма или 65 — 50vh всегда ровно половина. Так же и vw с шириной.

TV screen. vh and vw are like the TV size. 100vh = the entire TV screen. 50vh = exactly half the screen. Doesn't matter if it's 32" or 65" — 50vh is always exactly half. Same with vw for width.

clamp(min, ideal, max) — волшебная функция! Шрифт плавно масштабируется между минимумом и максимумом. Без clamp() шрифт 5vw на маленьком экране будет крошечным, а на огромном мониторе — гигантским. clamp() ставит рамки: «не меньше 1.5rem и не больше 3rem».
clamp(min, ideal, max) — a magic function! Font smoothly scales between min and max. Without clamp(), a 5vw font would be tiny on a small screen and giant on a huge monitor. clamp() sets boundaries: "no less than 1.5rem and no more than 3rem."

clamp() появился в CSS в 2020 году и быстро стал одной из самых популярных функций. До него разработчики писали по 3-4 media queries только для шрифтов! Теперь одна строка заменяет всё: font-size: clamp(1rem, 2.5vw, 2rem). Поддержка — 96%+ браузеров.

clamp() was added to CSS in 2020 and quickly became one of the most popular functions. Before it, developers wrote 3-4 media queries just for fonts! Now one line replaces everything: font-size: clamp(1rem, 2.5vw, 2rem). Support — 96%+ browsers.

Осторожно с 100vw! На десктопе 100vw включает ширину скроллбара (обычно 15-17px). Результат — горизонтальный скролл. Решение: используйте width: 100% вместо 100vw для контейнеров. vw оставляйте для фонов и hero-секций.

Be careful with 100vw! On desktop, 100vw includes the scrollbar width (usually 15-17px). Result — horizontal scroll. Solution: use width: 100% instead of 100vw for containers. Use vw for backgrounds and hero sections.

Откройте DevTools (F12) и в Console введите:

document.documentElement.clientWidth   // ширина без скроллбара
window.innerWidth                       // ширина со скроллбаром (= 100vw)

Разница — это ширина скроллбара. Вот почему 100vw создаёт горизонтальный скролл!

Open DevTools (F12) and in Console type:

document.documentElement.clientWidth   // width without scrollbar
window.innerWidth                       // width with scrollbar (= 100vw)

The difference is the scrollbar width. That's why 100vw creates horizontal scroll!

4. rem и em — относительные размеры шрифта

4. rem and em — relative font sizes

Для шрифтов px работает, но есть проблема: если пользователь в настройках браузера увеличит базовый шрифт (например, слабое зрение), все ваши px останутся прежними. rem решает это — он привязан к размеру шрифта <html>, который пользователь может менять.

For fonts, px works, but there's a problem: if the user increases the base font in browser settings (e.g., poor eyesight), all your px values stay the same. rem solves this — it's tied to the <html> font size, which the user can change.

/* rem = относительно html (обычно 16px) */
html { font-size: 16px; }     /* по умолчанию */

h1 { font-size: 2rem; }       /* 2 × 16px = 32px */
p  { font-size: 1rem; }       /* 1 × 16px = 16px */
.small { font-size: 0.875rem; } /* 0.875 × 16px = 14px */

/* em = относительно родителя */
.card {
    font-size: 16px;
    padding: 1.5em;            /* 1.5 × 16px = 24px */
}
.card h3 {
    font-size: 1.25em;         /* 1.25 × 16px = 20px */
}
em

Относительно родителя. Может накапливаться (em в em = путаница).

Relative to parent. Can compound (em in em = confusion).

.parent { font-size: 20px; }
.child  { font-size: 1.5em; }
/* child = 30px */
.grandchild { font-size: 1.5em; }
/* grandchild = 45px!!! */
rem ✅

Относительно html. Всегда предсказуемо. Рекомендуется для шрифтов!

Relative to html. Always predictable. Recommended for fonts!

html { font-size: 16px; }
.parent { font-size: 1.25rem; }
/* parent = 20px */
.child { font-size: 1.25rem; }
/* child = 20px (тоже!) */

Валюты. rem — как доллар: курс один для всех (привязан к html). em — как местная валюта: зависит от того, в какой «стране» (родительском элементе) вы находитесь. В одном блоке 1em = 20px, в другом = 14px. С rem всё предсказуемо.

Currencies. rem is like the dollar: one rate for everyone (tied to html). em is like local currency: depends on which "country" (parent element) you're in. In one block 1em = 20px, in another = 14px. With rem everything is predictable.

Когда em всё-таки полезен: для padding и margin внутри компонента. Если у кнопки padding: 0.5em 1em, то отступы масштабируются вместе с текстом. Увеличили шрифт кнопки — отступы автоматически увеличились. Это удобно для кнопок разных размеров:

.btn-sm  { font-size: 0.875rem; padding: 0.5em 1em; }
.btn-md  { font-size: 1rem;     padding: 0.5em 1em; }
.btn-lg  { font-size: 1.25rem;  padding: 0.5em 1em; }
/* Одинаковый padding в em — пропорции сохраняются! */

When em is still useful: for padding and margin inside a component. If a button has padding: 0.5em 1em, then padding scales with the text. Increased button font — padding automatically increased. Handy for buttons of different sizes:

.btn-sm  { font-size: 0.875rem; padding: 0.5em 1em; }
.btn-md  { font-size: 1rem;     padding: 0.5em 1em; }
.btn-lg  { font-size: 1.25rem;  padding: 0.5em 1em; }
/* Same em padding — proportions preserved! */

5. Когда какую единицу использовать

5. When to use which unit

Столько единиц — легко запутаться! Но на практике всё просто. Есть чёткие правила, какую единицу где использовать. Выучите эту таблицу — и больше не будете сомневаться.

So many units — easy to get confused! But in practice it's simple. There are clear rules for which unit to use where. Learn this table — and you'll never doubt again.

Простое правило: rem для всего, что связано с текстом (шрифты, отступы вокруг текста). % для ширин контейнеров. vh для полноэкранных секций. px для мелочей (border, shadow, gap). clamp() для заголовков.

Simple rule: rem for everything text-related (fonts, padding around text). % for container widths. vh for full-screen sections. px for small things (border, shadow, gap). clamp() for headings.

6. Адаптивные изображения

6. Responsive images

Изображения — главный враг адаптивности. Картинка 1200x800 на экране шириной 375px вылезет за границы и создаст горизонтальный скролл. Одно CSS-правило это чинит — и его нужно запомнить навсегда.

Images are the main enemy of responsiveness. A 1200x800 image on a 375px screen will overflow and create horizontal scroll. One CSS rule fixes this — and you need to remember it forever.

/* Базовое правило — изображение не шире контейнера */
img {
    max-width: 100%;
    height: auto;
}

/* Заполнить контейнер с обрезкой */
.card img {
    width: 100%;
    height: 200px;
    object-fit: cover;   /* заполнить + обрезать */
}

/* Круглый аватар, адаптивный */
.avatar {
    width: 15vw;
    max-width: 120px;
    min-width: 60px;
    aspect-ratio: 1;     /* квадрат */
    border-radius: 50%;
    object-fit: cover;
}
Правило #1: Всегда добавляйте max-width: 100%; height: auto; ко всем img. Без этого изображения выходят за границы на мобильных! Многие разработчики ставят это правило в самом начале CSS (в reset/normalize).
Rule #1: Always add max-width: 100%; height: auto; to all img. Without it, images overflow on mobile! Many developers put this rule at the very beginning of CSS (in reset/normalize).

Рамка для фото. object-fit: cover — как рамка для фото. Фотография может быть любого размера, но рамка обрежет её, чтобы заполнить пространство без искажений. cover = «заполни рамку, обрезав лишнее». contain = «влезь в рамку целиком, даже если будут пустые полосы».

Photo frame. object-fit: cover is like a photo frame. The photo can be any size, but the frame crops it to fill the space without distortion. cover = "fill the frame, crop the excess." contain = "fit entirely in the frame, even if there are empty bars."

aspect-ratio — относительно новое свойство (2021). До него, чтобы сделать квадратный блок, использовали хак с padding-top: 100%. Теперь просто aspect-ratio: 1 (квадрат), aspect-ratio: 16/9 (видео-пропорции), aspect-ratio: 4/3 (фото). Поддержка — 95%+ браузеров.

aspect-ratio is a relatively new property (2021). Before it, to make a square block, developers used a hack with padding-top: 100%. Now just aspect-ratio: 1 (square), aspect-ratio: 16/9 (video proportions), aspect-ratio: 4/3 (photo). Support — 95%+ browsers.

Эксперимент:

  1. Создайте файл с <img> без max-width: 100%. Откройте на мобильном в DevTools — картинка вылезет за экран
  2. Добавьте img { max-width: 100%; height: auto; } — картинка подстроится
  3. Попробуйте object-fit: cover и contain на картинке с фиксированной высотой

Experiment:

  1. Create a file with <img> without max-width: 100%. Open on mobile in DevTools — image will overflow
  2. Add img { max-width: 100%; height: auto; } — image will adapt
  3. Try object-fit: cover and contain on an image with fixed height

7. Бургер-меню — зачем и как

7. Burger menu — why and how

На десктопе навигация отлично помещается в одну строку: «Главная | О нас | Услуги | Контакты». Но на мобильном экране шириной 375px эти 4 ссылки уже не влезают — текст переносится, кнопки слипаются, выглядит ужасно. Решение, которое используют все сайты: бургер-меню.

On desktop, navigation fits perfectly in one row: "Home | About | Services | Contact." But on a 375px mobile screen, these 4 links don't fit — text wraps, buttons overlap, looks terrible. The solution used by all sites: the burger menu.

Мы сделаем бургер-меню на чистом CSS с помощью скрытого чекбокса! Никакого JavaScript — только HTML и CSS.

We'll build a burger menu with pure CSS using a hidden checkbox! No JavaScript — just HTML and CSS.

Иконку бургер-меню (☰ три полоски) придумал дизайнер Норм Кокс в 1981 году для интерфейса компьютера Xerox Star. Она стала повсеместной только в 2009-2012 годах, когда мобильные сайты стали массовыми. Сегодня это самая узнаваемая иконка в мире — пользователи инстинктивно знают, что за ней скрыта навигация.

The burger menu icon (☰ three lines) was designed by Norm Cox in 1981 for the Xerox Star computer interface. It became ubiquitous only in 2009-2012 when mobile websites went mainstream. Today it's the most recognizable icon in the world — users instinctively know that navigation is hidden behind it.

8. Бургер-меню: HTML

8. Burger menu: HTML

Хитрость в том, что мы используем <input type="checkbox"> — элемент, который может быть включён и выключен. В CSS есть селектор :checked, который определяет, включён ли чекбокс. Сам чекбокс мы скроем, а вместо него покажем красивую иконку через <label>.

The trick is that we use <input type="checkbox"> — an element that can be on and off. CSS has a :checked selector that detects if the checkbox is on. We'll hide the checkbox itself and show a beautiful icon via <label>.

<header class="header">
    <a href="#" class="logo">MySite</a>

    <!-- Скрытый чекбокс (переключатель) -->
    <input type="checkbox" id="menu-toggle" class="menu-toggle">
    <label for="menu-toggle" class="burger">
        <span></span>
        <span></span>
        <span></span>
    </label>

    <!-- Навигация -->
    <nav class="nav">
        <a href="#">Home</a>
        <a href="#">About</a>
        <a href="#">Services</a>
        <a href="#">Contact</a>
    </nav>
</header>
Как это работает: 1. <input checkbox> ← скрыт (display: none) ↓ 2. <label> (бургер) ← пользователь кликает СЮДА ↓ (label привязан к checkbox через for="...") 3. checkbox toggle ← checkbox включается/выключается ↓ 4. :checked ~ .nav ← CSS показывает/скрывает nav
How it works: 1. <input checkbox> ← hidden (display: none) ↓ 2. <label> (burger) ← user clicks HERE ↓ (label linked to checkbox via for="...") 3. checkbox toggle ← checkbox turns on/off ↓ 4. :checked ~ .nav ← CSS shows/hides nav
Важно! Порядок элементов в HTML имеет значение:
  1. <input> (чекбокс) — должен быть до <nav>
  2. <label> (бургер-иконка) — должен быть до <nav>
  3. <nav> — должен быть после чекбокса
Потому что CSS-селектор ~ (general sibling) работает только с элементами, которые идут после в HTML. .menu-toggle:checked ~ .nav = «nav, который идёт после checked чекбокса».
Important! The order of elements in HTML matters:
  1. <input> (checkbox) — must be before <nav>
  2. <label> (burger icon) — must be before <nav>
  3. <nav> — must be after the checkbox
Because the CSS ~ (general sibling) selector only works with elements that come after in HTML. .menu-toggle:checked ~ .nav = "nav that comes after a checked checkbox."

«Бургер не работает!» Три самых частых ошибки:

  • label for не совпадает с id чекбокса: <input id="menu-toggle"> и <label for="menu-toggle"> — id и for должны быть одинаковыми
  • nav стоит перед checkbox: селектор ~ работает только вперёд. Переставьте nav после checkbox
  • Забыли скрыть чекбокс: без .menu-toggle { display: none; } на странице будет видна галочка

"Burger doesn't work!" Three most common mistakes:

  • label for doesn't match checkbox id: <input id="menu-toggle"> and <label for="menu-toggle"> — id and for must be the same
  • nav is before checkbox: the ~ selector only works forward. Move nav after checkbox
  • Forgot to hide checkbox: without .menu-toggle { display: none; } a checkbox will be visible on the page

9. Бургер-меню: CSS

9. Burger menu: CSS

Теперь самое интересное — CSS. Мы напишем стили в два этапа: сначала десктоп (бургер скрыт, навигация видна), потом мобильный через @media (навигация скрыта, бургер виден, :checked показывает навигацию).

Now the fun part — CSS. We'll write styles in two stages: first desktop (burger hidden, nav visible), then mobile via @media (nav hidden, burger visible, :checked shows nav).

/* Скрыть чекбокс */
.menu-toggle { display: none; }

/* Скрыть бургер на десктопе */
.burger { display: none; }

/* Навигация на десктопе */
.header {
    display: flex;
    align-items: center;
    padding: 0 24px;
    height: 60px;
    background: #fff;
    border-bottom: 1px solid #e2e8f0;
}

.nav {
    display: flex;
    gap: 20px;
    margin-left: auto;
}

.nav a {
    text-decoration: none;
    color: #475569;
    font-weight: 500;
}

/* ========== МОБИЛЬНЫЙ ========== */
@media (max-width: 768px) {
    /* Показать бургер */
    .burger {
        display: flex;
        flex-direction: column;
        gap: 5px;
        cursor: pointer;
        margin-left: auto;
        padding: 8px;
    }
    .burger span {
        width: 24px;
        height: 3px;
        background: #1e293b;
        border-radius: 2px;
        transition: 0.3s;
    }

    /* Скрыть навигацию */
    .nav {
        position: absolute;
        top: 60px;
        left: 0;
        right: 0;
        background: #fff;
        flex-direction: column;
        padding: 16px 24px;
        border-bottom: 1px solid #e2e8f0;
        display: none;  /* скрыта по умолчанию */
    }

    /* Показать при checked */
    .menu-toggle:checked ~ .nav {
        display: flex;
    }

    /* Анимация бургера → крестик */
    .menu-toggle:checked ~ .burger span:nth-child(1) {
        transform: rotate(45deg) translate(5px, 6px);
    }
    .menu-toggle:checked ~ .burger span:nth-child(2) {
        opacity: 0;
    }
    .menu-toggle:checked ~ .burger span:nth-child(3) {
        transform: rotate(-45deg) translate(5px, -6px);
    }
}
Как это работает пошагово:
  1. Чекбокс скрыт (display: none) — пользователь его не видит
  2. Label (бургер-иконка) связан с чекбоксом через for="menu-toggle" — клик по label = клик по чекбоксу
  3. :checked ~ .nav — когда чекбокс включён, nav с display: none переключается на display: flex
  4. Анимация: три полоски бургера через transform: rotate() превращаются в крестик (✕)
  5. На десктопе: бургер скрыт (display: none), nav видна всегда
How it works step by step:
  1. Checkbox is hidden (display: none) — user doesn't see it
  2. Label (burger icon) is linked to checkbox via for="menu-toggle" — clicking label = clicking checkbox
  3. :checked ~ .nav — when checkbox is on, nav switches from display: none to display: flex
  4. Animation: three burger lines turn into X (✕) via transform: rotate()
  5. On desktop: burger is hidden (display: none), nav is always visible

Селектор ~ (general sibling combinator) — выбирает все элементы-братья, которые идут после указанного элемента на том же уровне вложенности. Это ключевой селектор для checkbox hack:

.menu-toggle:checked ~ .nav     /* nav после checked чекбокса */
.menu-toggle:checked ~ .burger  /* burger после checked чекбокса */

Без ~ этот трюк невозможен!

The ~ selector (general sibling combinator) — selects all sibling elements that come after the specified element at the same nesting level. This is the key selector for the checkbox hack:

.menu-toggle:checked ~ .nav     /* nav after checked checkbox */
.menu-toggle:checked ~ .burger  /* burger after checked checkbox */

Without ~ this trick is impossible!

Паттерн 3: Sticky footer

Pattern 3: Sticky footer

Footer должен быть внизу страницы, даже если контента мало:

Footer should stay at the bottom, even when there's little content:

body {
    display: grid;
    grid-template-rows: auto 1fr auto;
    min-height: 100vh;
}
/* header = auto, main = 1fr (растягивается), footer = auto */

Сэндвич. Sticky footer — как сэндвич: верхний хлеб (header) и нижний хлеб (footer) фиксированы, а начинка (main) занимает всё оставшееся пространство. Даже если начинки мало — хлеб остаётся сверху и снизу.

Sandwich. Sticky footer is like a sandwich: top bread (header) and bottom bread (footer) are fixed, and the filling (main) takes all remaining space. Even if there's little filling — bread stays on top and bottom.
