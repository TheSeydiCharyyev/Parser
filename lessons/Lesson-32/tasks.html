🎯 Lesson 32.1: HOME PAGE + HEADER/FOOTER

Задание 31.1: Свёрстайте HTML главной страницы Task 31.1: Build HTML of the home page
Среднее Medium 45 минут 45 min
Написать полный HTML главной страницы со всеми секциями
Write complete HTML of the home page with all sections

Условие:

Instructions:

  1. <head>: Заполните все meta-теги (title, description, viewport, OG, favicon), подключите Google Fonts и все 4 CSS-файла.
  2. Header: Логотип, навигация (3-5 ссылок), CTA-кнопка. На главной странице первая ссылка в меню имеет класс .active.
  3. Main: Все секции из wireframe. Для каждой — свой <section> с классом (.hero, .features, .gallery и т.д.) и заголовком <h2>.
  4. Hero-секция: <h1> (главный заголовок страницы), подзаголовок, кнопка CTA.
  5. Повторяющиеся блоки: карточки оберните в <article class="card">. Фичи — <article class="feature">.
  6. Footer: 2-3 колонки (<div class="footer-col">), копирайт внизу.
  7. Контент: реалистичный текст темы (не Lorem ipsum!). Картинки — через placeholder (picsum.photos) или из вашего images/.
  8. Проверка: открыть в браузере — все секции видны (хоть и уродливо).
  1. <head>: Fill all meta tags (title, description, viewport, OG, favicon), connect Google Fonts and all 4 CSS files.
  2. Header: Logo, navigation (3-5 links), CTA button. On home page the first menu link has .active class.
  3. Main: All sections from wireframe. Each gets its own <section> with a class (.hero, .features, .gallery etc.) and <h2> heading.
  4. Hero section: <h1> (main page heading), subheading, CTA button.
  5. Repeating blocks: wrap cards in <article class="card">. Features — <article class="feature">.
  6. Footer: 2-3 columns (<div class="footer-col">), copyright at bottom.
  7. Content: realistic theme text (not Lorem ipsum!). Images — via placeholder (picsum.photos) or from your images/.
  8. Check: open in browser — all sections visible (though ugly).

🎯 Lesson 32.2: REMAINING PAGES + NAVIGATION

Задание 31.2: Свёрстайте все остальные страницы Task 31.2: Build all remaining pages
Среднее Medium 45 минут 45 min
Создать HTML для всех остальных страниц проекта, настроить навигацию
Create HTML for all other project pages, set up navigation

Условие:

Instructions:

  1. Копирование: Для каждой оставшейся страницы (about.html, menu.html, contact.html и т.д.) — скопируйте весь HTML из index.html.
  2. Обновите <head>:
    • Уникальный <title>: «О нас | Sladko», «Меню | Sladko»
    • Уникальный <meta name="description"> — описание именно этой страницы
    • Обновите OG-теги (og:title, og:description, og:url)
  3. Замените <main>: удалите секции главной и добавьте секции текущей страницы по wireframe.
  4. Активная ссылка: в навигации класс .active должен быть на ссылке текущей страницы (на about.html класс стоит на ссылке About, не Home).
  5. На контактной странице — добавьте форму (name, email, message) с правильными <label> и type.
  6. Проверка навигации: откройте главную → кликните на About → должна открыться about.html. Кликните на Home → вернуться на главную. Проверьте все ссылки.
  7. Проверка .active: на каждой странице правильная ссылка подсвечена (пока в HTML, в CSS стилизуем на 32-м).
  1. Copy: For each remaining page (about.html, menu.html, contact.html etc.) — copy entire HTML from index.html.
  2. Update <head>:
    • Unique <title>: "About | Sladko", "Menu | Sladko"
    • Unique <meta name="description"> — description for this specific page
    • Update OG tags (og:title, og:description, og:url)
  3. Replace <main>: delete home sections and add current page sections per wireframe.
  4. Active link: in navigation the .active class must be on the current page link (on about.html the class is on About link, not Home).
  5. On contact page — add a form (name, email, message) with proper <label> and type.
  6. Navigation test: open home → click About → about.html should open. Click Home → return to home. Test all links.
  7. .active test: on each page the correct link is highlighted (in HTML for now, we'll style in lesson 32).

Задание 31.4: Accessibility audit Task 31.4: Accessibility audit
Сложное Hard 20 минут 20 min
Проверить доступность проекта инструментами
Verify project accessibility with tools

Условие:

Instructions:

  1. Lighthouse: Откройте DevTools (F12) → вкладка Lighthouse → Categories: Accessibility → Analyze page. Сделайте для главной страницы. Оценка должна быть 85+. Исправьте все красные пункты.
  2. Keyboard navigation: Зайдите на сайт, закройте мышь. Нажмите Tab — фокус должен переходить по ссылкам и кнопкам в логичном порядке. Все интерактивные элементы должны быть доступны с клавиатуры.
  3. Screen reader тест:
    • macOS: включите VoiceOver (Cmd + F5)
    • Windows: установите NVDA (бесплатно, nvaccess.org)
    • Прослушайте, как читается ваша страница. Понятно ли без визуала?
  4. aria-атрибуты: Добавьте aria-label к бургер-кнопке (пока она не видна без CSS, но уже в HTML). Добавьте aria-current="page" вместо/вместе с class="active".
  5. Отчёт: в plan.md добавьте раздел «Accessibility», запишите оценку Lighthouse и что улучшили.
  1. Lighthouse: Open DevTools (F12) → Lighthouse tab → Categories: Accessibility → Analyze page. Run on home page. Score should be 85+. Fix all red items.
  2. Keyboard navigation: Open the site, close the mouse. Press Tab — focus should move through links and buttons in a logical order. All interactive elements should be keyboard-accessible.
  3. Screen reader test:
    • macOS: enable VoiceOver (Cmd + F5)
    • Windows: install NVDA (free, nvaccess.org)
    • Listen to how your page is read. Is it understandable without visuals?
  4. aria attributes: Add aria-label to the burger button (not yet visible without CSS, but already in HTML). Add aria-current="page" instead of/alongside class="active".
  5. Report: in plan.md add an "Accessibility" section, record Lighthouse score and what you improved.
