1. Зачем нужны формы

1. Why we need forms

Формы — это способ получить данные от пользователя. Каждый раз, когда вы регистрируетесь на сайте, входите в аккаунт, пишете комментарий или оформляете заказ — вы заполняете форму.

Forms are a way to collect data from the user. Every time you register on a website, log in to an account, write a comment, or place an order — you're filling out a form.

До этого занятия мы учились показывать информацию пользователю: заголовки, абзацы, изображения, списки, таблицы. Но веб — это не телевизор, а диалог. Пользователь должен иметь возможность ответить, ввести данные, сделать выбор. Именно формы превращают статичную страницу в интерактивное приложение.

Until this lesson, we learned how to display information to users: headings, paragraphs, images, lists, tables. But the web is not a TV — it's a dialogue. Users need to be able to respond, enter data, make choices. Forms are what turn a static page into an interactive application.

Форма в HTML — это как бумажная анкета в поликлинике или банке. Есть пустые поля для заполнения (имя, дата рождения), варианты для выбора (пол: М / Ж), место для длинного текста (причина обращения) и кнопка «Отправить» (сдать анкету в окошко). В HTML всё то же самое, только вместо ручки и бумаги — теги.

An HTML form is like a paper questionnaire at a clinic or bank. There are blank fields to fill in (name, date of birth), choices to select (gender: M / F), a space for long text (reason for visit), and a "Submit" button (hand the form to the clerk). In HTML it's the same thing, but instead of pen and paper — we use tags.

Где вы видите формы каждый день:

Where you see forms every day:

  • Google — строка поиска (одно текстовое поле + кнопка)
  • Instagram / TikTok — форма регистрации (имя, email, пароль)
  • YouTube — комментарии (textarea + кнопка)
  • Wildberries / Amazon — оформление заказа (адрес, телефон, способ оплаты)
  • Gmail — написать письмо (кому, тема, текст)
  • Банковские приложения — переводы (номер карты, сумма)
  • Госуслуги — подача заявлений (десятки полей!)
  • Google — search bar (one text field + button)
  • Instagram / TikTok — registration form (name, email, password)
  • YouTube — comments (textarea + button)
  • Amazon — checkout (address, phone, payment method)
  • Gmail — compose email (to, subject, body)
  • Banking apps — transfers (card number, amount)
  • Government portals — applications (dozens of fields!)

Формы появились в HTML 2.0 в 1995 году — это один из самых ранних интерактивных элементов веба. Но настоящая революция произошла с HTML5, который добавил типы email, date, color, range и встроенную валидацию. До HTML5 разработчикам приходилось писать сотни строк JavaScript для проверки формата email!

Forms appeared in HTML 2.0 in 1995 — one of the earliest interactive web elements. But the real revolution came with HTML5, which added types like email, date, color, range, and built-in validation. Before HTML5, developers had to write hundreds of lines of JavaScript just to validate an email format!

2. Тег form

2. The form tag

Все поля ввода должны находиться внутри тега <form>. Это контейнер, который группирует поля и знает, куда отправлять данные:

All input fields must be inside a <form> tag. It's a container that groups fields and knows where to send the data:

<form action="/submit" method="POST">
    <!-- поля формы здесь / form fields here -->
</form>
АтрибутЧто делаетПример
actionКуда отправить данные (URL)action="/register"
methodКак отправить: GET или POSTmethod="POST"
AttributeWhat it doesExample
actionWhere to send data (URL)action="/register"
methodHow to send: GET or POSTmethod="POST"

Конверт с адресом. Тег <form> — это как конверт для письма. Внутри конверта — данные (поля формы). На конверте написан адрес (action) и способ доставки (method). Без конверта письмо никуда не отправится — так же и поля без <form> не будут знать, куда отправлять данные.

An envelope with an address. The <form> tag is like an envelope for a letter. Inside the envelope is the data (form fields). On the envelope is the address (action) and the delivery method (method). Without an envelope, the letter won't be sent — likewise, fields without <form> won't know where to send the data.

GET vs POST — когда что использовать?

GET vs POST — when to use which?

  • GET — данные видны в URL: google.com/search?q=html+forms. Подходит для поиска — можно скопировать ссылку и отправить другу.
  • POST — данные скрыты в теле запроса. Подходит для паролей, регистрации, оплаты — всё, что не должно быть в URL.
  • GET — data is visible in the URL: google.com/search?q=html+forms. Good for search — you can copy the link and send it to a friend.
  • POST — data is hidden in the request body. Good for passwords, registration, payments — anything that shouldn't appear in the URL.
На этом курсе мы пока не работаем с серверами, поэтому action и method можно не указывать. Мы сосредоточимся на HTML-разметке и CSS-стилизации форм. Серверная обработка — это следующий этап (JavaScript / backend).
In this course we don't work with servers yet, so action and method are optional. We'll focus on HTML markup and CSS styling of forms. Server-side processing is the next step (JavaScript / backend).

3. input type="text" и label

3. input type="text" and label

<input> — основной тег для полей ввода. Это самый универсальный элемент формы — меняя атрибут type, он превращается в текстовое поле, пароль, календарь, ползунок и даже палитру цветов!

<input> — the main tag for input fields. It's the most versatile form element — by changing the type attribute, it becomes a text field, password, calendar, slider, and even a color picker!

<label> — подпись к полю. Без неё пользователь не поймёт, что вводить.

<label> — a label for the field. Without it, users won't know what to enter.

<label for="username">Имя пользователя:</label>
<input type="text" id="username" name="username">

type="text"Тип поля — обычный текстИмя, фамилия, адрес
id="username"Уникальный идентификатор (связь с label)Одинаковый с for
name="username"Имя поля (отправляется на сервер)username=Мерген
for="username"Атрибут label — клик на подпись ставит фокус в полеСовпадает с id
AttributePurposeExample
type="text"Field type — plain textName, surname, address

Зачем связывать label и input? Связь через for + id даёт два преимущества:

Why link label and input? The for + id connection gives two advantages:

  • Удобство — клик на подпись «Имя пользователя» сразу ставит курсор в поле. Попробуйте на любом сайте — это работает!
  • Доступность — скринридеры (программы для незрячих) читают подпись, когда пользователь фокусируется на поле. Без label незрячий пользователь не знает, что вводить.
  • Usability — clicking the "Username" text immediately focuses the field. Try it on any website — it works!
  • Accessibility — screen readers (software for blind users) read the label when the user focuses on the field. Without a label, blind users don't know what to enter.

Доступность (Accessibility): по статистике 15% населения имеют ту или иную инвалидность. Связь <label> с <input> — это не просто «хорошая практика», это требование стандартов доступности WCAG. Многие крупные компании (Google, Apple, Microsoft) обязаны соблюдать эти стандарты по закону. Привыкайте писать доступный код с самого начала!

Accessibility: statistically, 15% of the population has some form of disability. Linking <label> with <input> is not just "best practice" — it's a requirement of WCAG accessibility standards. Many large companies (Google, Apple, Microsoft) are legally required to follow these standards. Get used to writing accessible code from the start!

Ситуация: новичок пишет label и input, но забывает связать их через for и id. Визуально всё выглядит нормально, но клик на подпись ничего не делает, а скринридер не понимает, какому полю принадлежит подпись.

Situation: a beginner writes a label and input but forgets to link them via for and id. Visually everything looks fine, but clicking the label does nothing, and screen readers can't tell which field the label belongs to.

<!-- НЕПРАВИЛЬНО / WRONG -->
<label>Имя:</label>
<input type="text" name="name">
<!-- for и id отсутствуют! Связи нет! -->

<!-- ПРАВИЛЬНО / CORRECT -->
<label for="name">Имя:</label>
<input type="text" id="name" name="name">
<!-- for="name" совпадает с id="name" ✔ -->

Правило: атрибут for у label всегда должен совпадать с id у input. Без этого связи нет.

Rule: the for attribute on a label must always match the id on the input. Without this, there's no connection.

Создай HTML-файл с формой, в которой есть label и input. Открой в браузере и кликни на текст подписи — курсор должен появиться в поле. Если не появился — проверь for и id!

Create an HTML file with a form that has a label and input. Open in the browser and click on the label text — the cursor should appear in the field. If it doesn't — check for and id!

4. Типы input

4. Input types

HTML5 предлагает множество типов <input>. Браузер сам подбирает клавиатуру на мобильном и проверяет формат!

HTML5 offers many <input> types. The browser automatically selects the keyboard on mobile and validates the format!

Почему важно использовать правильный тип? Потому что браузер делает работу за вас:

Why is it important to use the correct type? Because the browser does the work for you:

  • type="email" — на мобильном появится клавиатура с символом @, браузер проверит формат
  • type="tel" — на мобильном откроется цифровая клавиатура
  • type="date" — вместо текстового поля появится календарь
  • type="number" — появятся стрелки ▲▼ и нельзя будет ввести буквы
  • type="email" — on mobile, a keyboard with the @ symbol appears, browser validates format
  • type="tel" — on mobile, a numeric keyboard opens
  • type="date" — instead of a text field, a calendar appears
  • type="number" — arrows ▲▼ appear and letters can't be entered

Rule: always use the most appropriate type. This gives you free validation, the right keyboard on mobile, and better UX.

5. placeholder и value

5. placeholder and value

Два атрибута, которые часто путают новички:

Two attributes that beginners often confuse:

<!-- placeholder — подсказка (исчезает при вводе) -->
<input type="text" placeholder="Введите ваше имя">

<!-- value — значение по умолчанию (не исчезает) -->
<input type="text" value="Алексей">
placeholder

Серый текст-подсказка. Исчезает при вводе. Не отправляется на сервер. Используй для примеров: «user@mail.com», «+993 65...»

Gray hint text. Disappears on input. Not sent to server. Use for examples: "user@mail.com", "+993 65..."

value

Реальное значение поля. Остаётся в поле. Отправляется на сервер. Используй для значений по умолчанию: город, страна.

Actual field value. Stays in the field. Sent to server. Use for default values: city, country.

Бумажная анкета: placeholder — это как серый текст-образец, напечатанный в поле анкеты: «Фамилия Имя Отчество». Как только вы начинаете писать ручкой — образец «исчезает» (вы пишете поверх). А value — это как уже заполненное поле, где кто-то уже написал «Россия» — можно стереть и написать другое, но по умолчанию оно заполнено.

Paper form: placeholder is like the gray sample text printed in a form field: "First Last Middle name". As soon as you start writing with a pen — the sample "disappears" (you write over it). And value is like a pre-filled field where someone already wrote "Russia" — you can erase it and write something else, but by default it's filled in.

Распространённая ошибка: использовать placeholder вместо label. Placeholder исчезает при вводе — пользователь забывает, что нужно было вводить! Всегда используйте label + placeholder вместе.

Common mistake: using placeholder instead of label. Placeholder disappears on input — the user forgets what they were supposed to enter! Always use label + placeholder together.

<!-- НЕПРАВИЛЬНО / WRONG -->
<input type="text" placeholder="Ваше имя">
<!-- Нет label! При вводе подсказка исчезнет -->

<!-- ПРАВИЛЬНО / CORRECT -->
<label for="name">Ваше имя:</label>
<input type="text" id="name" placeholder="Мерген Атаев">
<!-- label остаётся, placeholder — пример формата -->

6. textarea — multi-line field

Для длинного текста (сообщения, комментарии, отзывы) используется <textarea>:

For long text (messages, comments, reviews) use <textarea>:

<label for="message">Сообщение:</label>
<textarea id="message" name="message" rows="5" cols="40"
          placeholder="Напишите ваше сообщение..."></textarea>

<input type="text">

Одна строка. Для коротких данных: имя, email, телефон.

Single line. For short data: name, email, phone.

<textarea>

Много строк. Для длинных текстов: сообщения, комментарии, описания. Парный тег — нужен </textarea>!

Multiple lines. For long texts: messages, comments, descriptions. Paired tag — needs </textarea>!

Ситуация: новичок пишет <textarea> как <input> — без закрывающего тега.

Situation: a beginner writes <textarea> like <input> — without a closing tag.

<!-- НЕПРАВИЛЬНО / WRONG -->
<textarea name="msg" />
<!-- textarea — НЕ самозакрывающийся тег! -->

<!-- ПРАВИЛЬНО / CORRECT -->
<textarea name="msg"></textarea>
<!-- Парный тег: открывающий + закрывающий -->

Правило: <input> — самозакрывающийся (нет </input>). <textarea> — парный (нужен </textarea>). Если забыть закрывающий тег — всё содержимое страницы после textarea попадёт «внутрь» поля!

Rule: <input> is self-closing (no </input>). <textarea> is paired (needs </textarea>). If you forget the closing tag, all page content after textarea will end up "inside" the field!

Совет: в CSS добавьте resize: vertical к textarea — тогда пользователь сможет тянуть поле только вверх/вниз, но не в стороны. Это сохраняет аккуратную вёрстку, но даёт гибкость.

Tip: in CSS, add resize: vertical to textarea — then users can only resize vertically, not horizontally. This keeps the layout clean while giving flexibility.

When you need the user to choose one option from several predefined choices — use <select>:

Меню в ресторане. <select> — это как меню, где вы выбираете одно блюдо. Каждый <option> — это одно блюдо. Пользователь видит название («Ашхабад»), а на сервер уходит код (value="ashgabat"). Это как в ресторане: вы говорите «Плов», а официант записывает номер блюда в системе.

Restaurant menu. <select> is like a menu where you choose one dish. Each <option> is one dish. The user sees the name ("Ashgabat"), but the server receives the code (value="ashgabat"). It's like in a restaurant: you say "Plov", but the waiter enters the dish number in the system.

Первый <option> с пустым value — это подсказка «Выберите...». Она нужна, чтобы при загрузке формы не было автоматически выбранного города. Если добавить required к <select>, то выбрать пустой вариант не получится — форма потребует реальный выбор.

The first <option> with an empty value is the "Select..." hint. It's needed so no city is automatically selected when the form loads. If you add required to <select>, the empty option won't be accepted — the form will require a real choice.

11. HTML validation

HTML5 позволяет проверять данные без JavaScript! Браузер сам покажет ошибку, если пользователь ввёл что-то не то:

HTML5 allows validating data without JavaScript! The browser will automatically show an error if the user enters something wrong:

Почему это важно? Представьте: пользователь заполнил длинную форму регистрации, нажал «Отправить», и только тогда сервер ответил «Неправильный email». Пользователь в бешенстве! С HTML-валидацией ошибка видна сразу — ещё до отправки. Это называется client-side validation (проверка на стороне клиента).

Why is this important? Imagine: a user fills out a long registration form, clicks "Submit," and only then the server responds "Invalid email." The user is frustrated! With HTML validation, the error is visible immediately — before sending. This is called client-side validation.

By default, forms look "system-like" — each browser renders fields differently. Let's style them so forms look consistently beautiful everywhere:

Зачем стилизовать формы? Потому что стандартные элементы форм — это самые некрасивые элементы в HTML. Каждый браузер рисует их по-разному: input в Chrome выглядит не так, как в Firefox. CSS позволяет сделать формы красивыми и единообразными на всех устройствах.

Why style forms? Because default form elements are the ugliest elements in HTML. Each browser renders them differently: input in Chrome looks different from Firefox. CSS lets you make forms beautiful and consistent across all devices.
