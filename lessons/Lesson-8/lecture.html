1. Что такое position и зачем он нужен

1. What position is and why we need it

Свойство position определяет, как браузер размещает элемент на странице. По умолчанию все элементы участвуют в нормальном потоке: блочные становятся друг под другом, строчные — в одну строку. position позволяет вынуть элемент из этого потока и поставить его в любое место.

The position property defines how the browser places an element on the page. By default, all elements participate in the normal flow: blocks stack vertically, inline elements line up horizontally. position lets you take an element out of this flow and put it anywhere.

Представь библиотеку. По умолчанию книги стоят на полках по порядку — это нормальный поток. Но иногда библиотекарь берёт книгу с полки и кладёт её на стол, или приклеивает к потолку, или прибивает к стене. Это и есть position — способ сказать «эта книга не на полке, она вон там».

Imagine a library. By default, books sit on shelves in order — that's the normal flow. But sometimes the librarian takes a book off the shelf and puts it on a desk, glues it to the ceiling, or nails it to the wall. That's position — a way to say "this book isn't on the shelf, it's over there."

У position 5 значений:

There are 5 values for position:

Значение Value Что делает What it does
static static По умолчанию. Элемент в обычном потоке. top/left не работают. Default. Element is in normal flow. top/left don't work.
relative relative Элемент остаётся в потоке (место сохраняется), но можно сдвинуть через top/left. Element stays in flow (its place is preserved), but you can shift it via top/left.
absolute absolute Вырывается из потока. Позиционируется относительно ближайшего relative-предка. Pulled out of flow. Positioned relative to the nearest relative ancestor.
fixed fixed Вырывается из потока. Позиционируется относительно окна браузера. Не двигается при скролле. Pulled out of flow. Positioned relative to the browser window. Doesn't move when scrolling.
sticky sticky Гибрид: ведёт себя как relative, пока не достигнет порога — потом «прилипает» как fixed. Hybrid: acts like relative until it hits a threshold — then "sticks" like fixed.

Что мы видим на реальных сайтах благодаря position:

  • YouTube — sticky-навигация сверху, плеер прилипает к низу при скролле комментариев
  • GitHub — sticky-табы «Code / Issues / Pull requests», бейджи с числами на иконках через absolute
  • Apple.com — fixed-шапка с прозрачным фоном (backdrop-filter) поверх hero-секции
  • Telegram Web — fixed-кнопка «Новое сообщение», кнопка «Прокрутить вниз» появляется при скролле
  • Любой интернет-магазин — бейджи «Скидка», «Новинка», «Хит» в углах карточек товаров

What we see on real websites thanks to position:

  • YouTube — sticky top navigation, the player sticks to the bottom when scrolling comments
  • GitHub — sticky tabs "Code / Issues / Pull requests", count badges on icons via absolute
  • Apple.com — fixed header with transparent background (backdrop-filter) over the hero section
  • Telegram Web — fixed "New message" button, "Scroll down" button appearing on scroll
  • Any online store — "Sale", "New", "Hit" badges in corners of product cards

2. position: static — значение по умолчанию

2. position: static — the default value

static — это значение по умолчанию для всех HTML-элементов. Оно означает «никакого специального позиционирования, просто обычный поток». Вы никогда не пишете position: static явно — оно стоит само по себе.

static is the default value for all HTML elements. It means "no special positioning, just the normal flow." You never write position: static explicitly — it's there by default.

/* Эти два правила ОДИНАКОВЫ */
.box {
    /* нет position — значит static */
}

.box {
    position: static;  /* явно, но бессмысленно */
}

Запомни главное: у static-элементов не работают свойства top, right, bottom, left, z-index. Если ты напишешь position: static; top: 50px; — top будет проигнорирован.

Remember the key fact: for static elements, the top, right, bottom, left, z-index properties don't work. If you write position: static; top: 50px; — top will be ignored.

Зачем тогда вообще знать про static? Иногда нужно сбросить позиционирование, которое было задано раньше или унаследовано из библиотеки CSS:

Why bother knowing about static? Sometimes you need to reset positioning that was set earlier or inherited from a CSS library:

/* Bootstrap задаёт всем .navbar значение sticky */
/* А я хочу отключить это для одной страницы */
.special-page .navbar {
    position: static;  /* возвращаем в поток */
}

3. position: relative — сдвиг от своего места

3. position: relative — shift from original place

relative делает две вещи:

  1. Элемент остаётся в потоке — его исходное место занято, другие элементы его «помнят» и не сдвигаются.
  2. Можно сдвинуть элемент относительно его исходного места через top/right/bottom/left.

relative does two things:

  1. The element stays in the flow — its original place is preserved, other elements "remember" it and don't shift.
  2. You can shift the element relative to its original place via top/right/bottom/left.
.shifted {
    position: relative;
    top: 20px;     /* сдвинут вниз на 20px от исходного места */
    left: 30px;    /* сдвинут вправо на 30px от исходного места */
}
БЕЗ relative: С relative top:20px left:30px: [ Блок 1 ] [ Блок 1 ] [ Блок 2 ] [ Блок 2 ] ← сдвинут, но место сохранено [ Блок 3 ] [ Блок 3 ] ← НЕ подъехал к 1 ↑ место Блока 2 пустует, но «занято»

Представь, что ты сидишь в классе на 5-й парте. Тебе сказали «сдвинь свой стул на 30см вправо». Ты сдвинулся, НО на полу осталась пометка мелом «здесь сидит Сапар». Никто другой на это место не сядет, даже если оно физически свободно. Это и есть relative: визуально сдвинут, но «место занято».

Imagine you're sitting in class at desk 5. You're told "move your chair 30cm to the right." You move, BUT a chalk mark remains on the floor "Sapar sits here." Nobody else will take that spot, even though it's physically empty. That's relative: visually shifted, but "place is taken."

Зачем используют relative на практике?

Чаще всего — НЕ для сдвига элемента, а как контейнер для absolute-потомков. Это самый важный паттерн всего занятия. Когда ты ставишь position: relative на родителя, ты говоришь: «дети с absolute, считайте свои координаты от меня». Без этого absolute уйдёт «в начало координат» страницы.

Why is relative used in practice?

Most often — NOT to shift the element, but as a container for absolute children. This is the most important pattern of the whole lesson. When you set position: relative on a parent, you're saying: "children with absolute, count your coordinates from me." Without this, absolute will go to the page's "origin point."

4. top, right, bottom, left — координаты

4. top, right, bottom, left — coordinates

Эти четыре свойства определяют, на сколько сдвинуть элемент от каждого края его системы отсчёта. Они работают только для элементов с position отличным от static.

These four properties define how far to shift an element from each edge of its reference frame. They only work for elements with position other than static.

Свойство Property Что значит What it means
top: 20px top: 20px Отступ от верхнего края 20px (элемент сместится вниз) Offset from the top edge 20px (element moves down)
right: 20px right: 20px Отступ от правого края 20px (элемент сместится влево от правого края) Offset from the right edge 20px (element moves left from the right edge)
bottom: 20px bottom: 20px Отступ от нижнего края 20px (элемент сместится вверх) Offset from the bottom edge 20px (element moves up)
left: 20px left: 20px Отступ от левого края 20px (элемент сместится вправо) Offset from the left edge 20px (element moves right)

top и bottom вместе? Если задать оба, выиграет top (для left-to-right языков). Если хочешь растянуть элемент — задай top: 0; bottom: 0; и НЕ задавай height. Тогда элемент займёт всю высоту контейнера.

top and bottom together? If you set both, top wins (in left-to-right languages). If you want to stretch the element — set top: 0; bottom: 0; and DON'T set height. The element will then fill the container's full height.

/* Растянуть элемент на всю высоту родителя */
.fullheight {
    position: absolute;
    top: 0;
    bottom: 0;
    width: 200px;  /* высота определится из top/bottom */
}

Можно использовать отрицательные значения — элемент уйдёт в противоположную сторону:

You can use negative values — the element will move in the opposite direction:

/* Бейдж торчит за угол карточки */
.badge {
    position: absolute;
    top: -10px;    /* сдвинут на 10px ВЫШЕ верхнего края родителя */
    right: -10px;  /* сдвинут на 10px ПРАВЕЕ правого края родителя */
}

5. position: absolute — вне потока

5. position: absolute — out of the flow

absolute — это «волшебное» значение, которое:

  1. Вырывает элемент из потока — другие элементы его «не видят», смыкаются на его месте, как будто его нет.
  2. Позиционирует относительно ближайшего предка с position: relative (или absolute, или fixed, или sticky).
  3. Если такого предка нет — относительно <html> (всей страницы).

absolute is the "magic" value that:

  1. Pulls the element out of the flow — other elements don't "see" it, they close together as if it's not there.
  2. Positions it relative to the nearest ancestor with position: relative (or absolute, or fixed, or sticky).
  3. If no such ancestor exists — relative to <html> (the whole page).
БЕЗ absolute: С absolute (родитель .card relative): .card .card ┌──────────────┐ ┌──────────────┐ ●—— badge top:-10 right:-10 │ Картинка │ │ Картинка │ │ Название │ │ Название │ │ Цена │ │ Цена │ │ [Бейдж] │ └──────────────┘ └──────────────┘ (бейдж "выпрыгнул" вверх-вправо)
/* HTML */
<div class="card">
    <img src="product.jpg">
    <span class="badge">-30%</span>
</div>

/* CSS */
.card {
    position: relative;     /* ВАЖНО: иначе badge "улетит" к углу страницы */
}

.badge {
    position: absolute;
    top: 10px;
    right: 10px;
    background: red;
    color: white;
    padding: 4px 8px;
    border-radius: 12px;
}

Главное правило absolute: 99% случаев на родителе ставят position: relative. Это «привязка». Без неё absolute считает координаты от <html> и улетает в угол страницы.

Main rule of absolute: in 99% of cases, the parent gets position: relative. This is the "anchor." Without it, absolute counts coordinates from <html> and flies to the corner of the page.

Что меняется при absolute:

What changes with absolute:

  • Элемент вырван из потока — другие подвинутся на его место
  • Если не задать width — ширина равна содержимому (как у строчных)
  • Можно задать любую ширину/высоту, в отличие от inline-элементов
  • Считает позицию от ближайшего position: relative/absolute/fixed/sticky-предка
  • Element is pulled out of flow — others move into its spot
  • If width isn't set — width equals content (like inline elements)
  • You can set any width/height, unlike inline elements
  • Counts position from the nearest position: relative/absolute/fixed/sticky ancestor

Где используется absolute в реальных проектах:

  • Бейджи «-30%», «New», «Hit» в углах карточек товаров
  • Иконка-крестик «Закрыть» в углу модалки или поп-апа
  • Подпись поверх фото (overlay с градиентом снизу)
  • Иконка лупы внутри input для поиска
  • Tooltip-подсказка над кнопкой
  • Кружок-уведомление с числом на иконке (например, на колокольчике)

Where absolute is used in real projects:

  • "-30%", "New", "Hit" badges in corners of product cards
  • Close-X icon in the corner of a modal or popup
  • Caption over a photo (overlay with bottom gradient)
  • Magnifier icon inside a search input
  • Tooltip hint above a button
  • Number-circle notification on an icon (e.g., on a bell)

6. Containing block — кто родитель для absolute

6. Containing block — who is the parent for absolute

Самая частая боль с absolute — он улетает не туда, куда ты ожидал. Причина почти всегда одна: не тот родитель сделан relative. Разберёмся, как браузер ищет «родителя».

The most common pain with absolute — it flies to the wrong place. The reason is almost always one: the wrong parent is made relative. Let's see how the browser finds the "parent."

Containing block — «контейнер», от которого absolute считает свои top/right/bottom/left. Это ближайший предок, у которого position отличен от static (то есть relative, absolute, fixed или sticky). Если такого нет — это <html>.

Containing block — the "container" from which absolute counts its top/right/bottom/left. It's the nearest ancestor whose position is not static (i.e., relative, absolute, fixed, or sticky). If there's no such ancestor — it's <html>.

/* HTML */
<body>
    <main>
        <section class="cards">
            <article class="card">
                <span class="badge">NEW</span>
            </article>
        </section>
    </main>
</body>

/* CSS вариант 1 — БЕЗ relative нигде */
.badge {
    position: absolute;
    top: 0;
    right: 0;
}
/* badge улетит в правый верхний угол ВСЕЙ страницы */

/* CSS вариант 2 — relative на .card (правильно) */
.card { position: relative; }
.badge { position: absolute; top: 0; right: 0; }
/* badge встанет в правый верхний угол .card ✓ */

/* CSS вариант 3 — relative на .cards (тоже работает, но не то) */
.cards { position: relative; }
.badge { position: absolute; top: 0; right: 0; }
/* badge встанет в правый верхний угол .cards (а не .card) */

Самая частая ошибка: ставят position: absolute на бейдж и забывают про relative на карточке. Бейдж улетает в правый верхний угол страницы. Симптом — открываешь сайт, видишь бейдж где-то рядом с шапкой, а должен быть на карточке.

Лечение: на родителе, относительно которого должен позиционироваться элемент, добавь position: relative. Никаких top/left на самом родителе писать не нужно — relative «без координат» ничего не двигает, только включает «привязку».

Most common mistake: they put position: absolute on a badge and forget relative on the card. The badge flies to the top-right corner of the page. The symptom — you open the site and see the badge somewhere near the header instead of on the card.

Fix: on the parent that the element should be positioned relative to, add position: relative. No need to write any top/left on the parent itself — relative "without coordinates" doesn't move anything, just turns on the "anchor."

7. position: fixed — относительно экрана

7. position: fixed — relative to the viewport

fixed похож на absolute, но привязан не к родителю, а к окну браузера (viewport). Что бы ты ни делал — скроллил, прокручивал, переключал страницы — элемент остаётся на одном и том же месте экрана.

fixed is similar to absolute, but it's anchored not to a parent, but to the browser window (viewport). No matter what you do — scroll, switch pages — the element stays in the same spot on the screen.

/* Кнопка "Наверх" в правом нижнем углу экрана */
.back-to-top {
    position: fixed;
    bottom: 24px;
    right: 24px;
    width: 50px;
    height: 50px;
    border-radius: 50%;
    background: #3b82f6;
    color: white;
}

Что важно про fixed:

  • Игнорирует relative-родителей. Привязан только к viewport.
  • Элемент вырван из потока — как absolute. Места не занимает.
  • Не двигается при скролле страницы — это его главная фишка.
  • На мобильных может «прыгать» из-за адресной строки браузера. Тестируй на телефоне!

What's important about fixed:

  • Ignores relative parents. Only anchored to the viewport.
  • Element is pulled out of flow — like absolute. Doesn't take up space.
  • Doesn't move when the page scrolls — this is its main feature.
  • On mobile, it may "jump" because of the browser's address bar. Test on a phone!

Что обычно делают через fixed:

  • Шапка сайта, которая всегда сверху (Apple, Stripe, GitHub)
  • Кнопка «Наверх» в углу
  • Кнопка «Чат / Помощь» в правом нижнем углу
  • Cookie-баннер внизу страницы
  • Модальные окна (поверх всего контента)
  • Floating Action Button на мобильных приложениях

What is typically done with fixed:

  • Site header that's always on top (Apple, Stripe, GitHub)
  • "Back to top" button in the corner
  • "Chat / Help" button in the bottom-right corner
  • Cookie banner at the bottom of the page
  • Modal windows (over all content)
  • Floating Action Button in mobile apps

Частая ошибка: делают position: fixed на шапке высотой 70px, а потом первые 70px контента оказываются под шапкой и не видны. Лечение — добавь padding-top: 70px на <main> или <body>, чтобы освободить место под шапку.

Common mistake: they make a 70px-tall header position: fixed, and then the first 70px of content ends up under the header and isn't visible. Fix — add padding-top: 70px to <main> or <body> to make room for the header.

8. position: sticky — гибрид relative и fixed

8. position: sticky — hybrid of relative and fixed

sticky — самое современное и удобное значение. Оно сочетает поведение relative и fixed:

  • Пока скролл не достиг порога — ведёт себя как relative (стоит на своём месте, скроллится вместе со страницей).
  • Когда дошёл до порога — «прилипает» как fixed (остаётся на экране при скролле).
  • Когда родитель ушёл с экрана — sticky уходит вместе с ним.

sticky is the most modern and convenient value. It combines the behavior of relative and fixed:

  • Before the scroll reaches the threshold — behaves like relative (stays in place, scrolls with the page).
  • When it hits the threshold — "sticks" like fixed (stays on the screen while scrolling).
  • When the parent leaves the screen — sticky leaves with it.
/* Самый частый пример — "липкая" шапка */
.site-header {
    position: sticky;
    top: 0;            /* прилипает на 0px от верха */
    background: white; /* ВАЖНО: фон, иначе текст под шапкой будет виден */
    z-index: 100;      /* поверх остального контента */
}

Без указания top sticky не работает! Тебе обязательно нужно сказать «прилипни на N px от верха». Самое частое: top: 0 (прилипнуть к самому верху).

Without specifying top, sticky doesn't work! You must say "stick to N px from the top." The most common: top: 0 (stick to the very top).

Почему sticky лучше fixed для шапок?

  • Не вырывается из потока — место занято, контент не «прячется» под шапкой
  • На мобильных не «прыгает» от адресной строки браузера
  • Можно ограничить «зону прилипания» родителем — например, прилипает только пока ты в одной секции

Why is sticky better than fixed for headers?

  • Doesn't get pulled from flow — place is preserved, content doesn't "hide" under the header
  • On mobile, doesn't "jump" from the browser address bar
  • You can limit the "sticky zone" by the parent — e.g., sticks only while you're in one section

Где используют sticky:

  • Шапки сайтов (YouTube, Twitter, GitHub)
  • Боковая навигация в документации (React docs, MDN)
  • Заголовки секций таблицы при скролле длинного списка
  • Кнопки «Купить» / «Записаться» в карточках товаров на мобильных
  • Sidebar с оглавлением в статьях блога

Where sticky is used:

  • Site headers (YouTube, Twitter, GitHub)
  • Side navigation in documentation (React docs, MDN)
  • Table section headers when scrolling a long list
  • "Buy" / "Sign up" buttons on product cards on mobile
  • Sidebar with table of contents in blog articles

Sticky не работает! 5 типичных причин:

  1. Не указан top (или bottom, left, right) — браузер не знает порог.
  2. На каком-то родителе стоит overflow: hidden, overflow: scroll или overflow: auto. Это ломает sticky. Убрать.
  3. Родитель не выше элемента — sticky прилипнет, но сразу же уедет с родителем.
  4. Старый IE — не поддерживает (но в 2026 это уже не проблема).
  5. Забыл про position: sticky — пишут просто top: 0, без position. Не работает.

Sticky doesn't work! 5 typical causes:

  1. Missing top (or bottom, left, right) — browser doesn't know the threshold.
  2. Some parent has overflow: hidden, overflow: scroll, or overflow: auto. This breaks sticky. Remove.
  3. Parent isn't taller than the element — sticky will stick, but immediately leave with the parent.
  4. Old IE — doesn't support it (but in 2026 this is no longer an issue).
  5. Forgot position: sticky — they write just top: 0, without position. Doesn't work.

9. z-index и stacking context

9. z-index and stacking context

Когда у тебя несколько позиционированных элементов и они перекрывают друг друга — кто будет сверху? Управляется свойством z-index.

When you have multiple positioned elements that overlap each other — which one will be on top? Controlled by the z-index property.

Представь, что страница — это лист бумаги. z-index — это номер слоя стопки над листом. Чем больше число — тем выше слой.

Imagine the page is a sheet of paper. z-index is the layer number in the stack above the sheet. The bigger the number — the higher the layer.

.modal {
    position: fixed;
    z-index: 1000;   /* высокое значение → сверху всего */
}

.dropdown {
    position: absolute;
    z-index: 50;     /* среднее значение → сверху обычного контента */
}

.background-image {
    position: absolute;
    z-index: -1;     /* отрицательное → ПОД остальным контентом */
}

z-index работает только если у элемента есть position отличный от static. Если ты пишешь z-index: 100 на статичном элементе — он будет проигнорирован.

z-index only works if the element has position other than static. If you write z-index: 100 on a static element — it will be ignored.

Типичные значения:

Typical values:

z-index Что обычно Typical use
-1 Декоративный фон, который должен быть под контентом Decorative background that should be under content
1-10 Бейджи, иконки в карточках, мелкие оверлеи Badges, icons in cards, small overlays
50-100 Sticky / fixed шапки, выпадающие меню Sticky / fixed headers, dropdown menus
1000+ Модальные окна, тостер-уведомления, поверх ВСЕГО Modal windows, toast notifications, above EVERYTHING

Не пиши z-index: 9999 «на всякий случай». В команде это превращается в гонку: один пишет 9999, другой 99999, третий 999999. Лучше держи общий список «ярусов» в комментарии CSS-файла или в дизайн-системе. Шкала 1, 10, 100, 1000 покрывает 99% задач.

Don't write z-index: 9999 "just in case." On a team this turns into a race: one writes 9999, another 99999, the third 999999. Better keep a shared list of "tiers" in a CSS file comment or in the design system. The scale 1, 10, 100, 1000 covers 99% of cases.

12. Итоги занятия

12. Lesson summary

Что мы узнали:

  • position — свойство, управляющее размещением элемента на странице
  • static — по умолчанию, в обычном потоке, top/left не работают
  • relative — сдвигает от исходного места, но место сохраняется. Главное применение — контейнер для absolute
  • absolute — вырывает из потока, считает от ближайшего relative-предка
  • fixed — относительно окна браузера, не двигается при скролле
  • sticky — гибрид: relative до порога, fixed после
  • top/right/bottom/left — координаты сдвига от соответствующего края
  • z-index — слой по оси Z, кто сверху. Работает только с position ≠ static
  • Containing block — родитель, от которого absolute считает координаты

What we learned:

  • position — the property that controls element placement on the page
  • static — default, normal flow, top/left don't work
  • relative — shifts from original place but place is preserved. Main use — container for absolute
  • absolute — pulled out of flow, counts from nearest relative ancestor
  • fixed — relative to browser window, doesn't move on scroll
  • sticky — hybrid: relative before threshold, fixed after
  • top/right/bottom/left — coordinates of shift from the corresponding edge
  • z-index — Z-axis layer, who's on top. Only works with position ≠ static
  • Containing block — parent from which absolute counts coordinates
