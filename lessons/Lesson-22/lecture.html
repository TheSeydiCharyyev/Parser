1. Что мы будем строить

1. What we will build

За последние 4 урока мы изучили очень много инструментов адаптивного дизайна: media queries, адаптивные единицы (%, vw, vh, rem), clamp(), адаптивные изображения, бургер-меню на чистом CSS. По отдельности каждый инструмент простой — но в реальном проекте их нужно собрать вместе. Именно это и сложнее всего для новичка.

Мини-проект «сайт ресторана» — классический первый коммерческий заказ junior-разработчика. Ресторанам нужен сайт-визитка, а у них маленький бюджет — идеальный вариант для фриланса. Поэтому мы строим именно ресторан: это реально оплачиваемый навык.

После этого занятия вы сможете:

  • Планировать макет под 3 разрешения ДО написания кода
  • Использовать CSS-переменные для единой цветовой схемы
  • Собрать fixed header с бургер-меню в реальном проекте
  • Сделать hero-секцию с фоновым изображением и overlay
  • Построить адаптивные сетки (grid) для меню блюд и галереи
  • Объединить контактную форму и блок контактов в одном ряду
  • Настроить breakpoints так, чтобы сайт выглядел аккуратно на телефоне, планшете и ПК

Over the last 4 lessons we learned a lot of responsive tools: media queries, responsive units (%, vw, vh, rem), clamp(), responsive images, CSS burger menu. Each tool is simple on its own — but in a real project you must put them together. That's what's hardest for beginners.

The "restaurant website" mini-project is a classic first commercial job for a junior developer. Restaurants need a business-card site with a small budget — perfect for freelancing. That's why we build a restaurant: it's an actually paid skill.

After this lesson you'll be able to:

  • Plan a layout for 3 resolutions BEFORE writing code
  • Use CSS variables for a unified color scheme
  • Assemble a fixed header with burger menu in a real project
  • Build a hero section with background image and overlay
  • Build responsive grids for the food menu and gallery
  • Combine a contact form and info block side-by-side
  • Set breakpoints so the site looks clean on phone, tablet and desktop
Секции сайта: Header (бургер-меню) → Hero → О нас → Меню блюд → Галерея → Контакты → Footer
Site sections: Header (burger menu) → Hero → About → Food Menu → Gallery → Contacts → Footer

Что ищет клиент-ресторатор на сайте? Исследования UX показывают: 90% посетителей сайта ресторана ищут всего 3 вещи — меню, адрес/часы работы, телефон. Всё остальное (история, галерея, отзывы) — приятный бонус. Поэтому наш сайт ставит именно эти блоки на видное место: меню — крупной сеткой, контакты — отдельной секцией с формой, телефон — в footer.

What does a restaurant client's user look for? UX research shows: 90% of restaurant-site visitors look for just 3 things — menu, address/hours, phone. Everything else (story, gallery, reviews) is a nice bonus. That's why our site highlights exactly those blocks: menu as a large grid, contacts as a dedicated section with a form, phone in the footer.

Сайт — это витрина. Hero-секция — большая вывеска над входом. Секция «Меню» — меню на столе. Секция «Галерея» — фото в окне. Footer — визитка, которую клиент забирает с собой. Каждый блок имеет конкретную работу в «воронке» посетителя.

A website is a storefront. The hero section is the big sign above the entrance. The "Menu" section is the menu on the table. The "Gallery" section is photos in the window. The footer is a business card customers take with them. Each block has a specific job in the visitor's funnel.

2. Планирование для 3 разрешений

2. Planning for 3 resolutions

Новички начинают писать HTML и CSS сразу — и через пару часов запутываются в media queries. Профессионалы делают наоборот: сначала рисуют макет для 3 разрешений (хотя бы в уме или на салфетке), а потом кодят. Это экономит часы переделок.

Вопрос, на который надо ответить ДО кода: «Как на каждом разрешении располагаются блоки?» Обычно меняется одно из трёх: количество колонок в сетке, расположение (ряд → стопка), и способ показа навигации (горизонтальная → бургер).

Beginners start writing HTML and CSS right away — and get lost in media queries within a couple of hours. Pros do the opposite: first sketch layouts for 3 resolutions (even mentally or on a napkin), then code. This saves hours of rework.

The question to answer BEFORE code: "How are blocks arranged at each resolution?" Usually one of three things changes: number of grid columns, arrangement (row → stack), and navigation style (horizontal → burger).

Мобильный-first vs Desktop-first. В этом проекте мы идём desktop-first: пишем основные стили под 1024px+, а потом @media (max-width: ...) меняет их на планшете и мобильном. Это проще для начинающих. В больших продакшен-проектах чаще делают наоборот — mobile-first (min-width), потому что мобильного трафика сейчас > 60%. Для вашего первого коммерческого заказа — desktop-first достаточно.
Mobile-first vs Desktop-first. In this project we go desktop-first: base styles for 1024px+, then @media (max-width: ...) adjusts them for tablet and mobile. Easier for beginners. In large production projects people more often go the other way — mobile-first (min-width), because mobile traffic is >60% now. For your first commercial job — desktop-first is enough.

Breakpoints — это не гаджеты, это контент. Не думайте «iPhone = 375px, iPad = 768px, ноутбук = 1366px». Думайте так: «при какой ширине мой макет начинает ломаться?» Сузьте окно медленно и смотрите. Когда заголовок переносится уродливо или карточки становятся слишком узкими — вот ваш breakpoint. У каждого проекта свои значения.

Breakpoints are about content, not devices. Don't think "iPhone = 375px, iPad = 768px, laptop = 1366px". Think: "at what width does my layout start breaking?" Slowly narrow the window and watch. When a heading wraps awkwardly or cards get too narrow — that's your breakpoint. Every project has its own values.

3. HTML-структура

3. HTML structure

HTML пишем до CSS. Сначала собираем «скелет» — все секции в правильном порядке, с семантическими тегами. Только когда скелет готов — начинаем стилизовать. Так легче: видишь структуру целиком и не путаешься в том, какой блок где.

Обратите внимание на семантические теги: <header>, <section>, <footer>, <nav> вместо везде <div>. Это важно для SEO (Google ранжирует такие сайты выше) и для скринридеров (слепые пользователи смогут навигировать по сайту).

Write HTML before CSS. First assemble the "skeleton" — all sections in the correct order with semantic tags. Only when the skeleton is ready — start styling. This is easier: you see the whole structure and don't get confused about which block goes where.

Note the semantic tags: <header>, <section>, <footer>, <nav> instead of <div> everywhere. Important for SEO (Google ranks such sites higher) and for screen readers (blind users can navigate the site).

<body>
    <!-- HEADER -->
    <header class="header">
        <a href="#" class="logo">La Cucina</a>
        <input type="checkbox" id="menu-toggle" class="menu-toggle">
        <label for="menu-toggle" class="burger">
            <span></span><span></span><span></span>
        </label>
        <nav class="nav">
            <a href="#about">About</a>
            <a href="#menu">Menu</a>
            <a href="#gallery">Gallery</a>
            <a href="#contact">Contact</a>
        </nav>
    </header>

    <!-- HERO -->
    <section class="hero">
        <h1>Welcome to La Cucina</h1>
        <p>Authentic Italian cuisine in the heart of the city</p>
        <a href="#menu" class="btn">View Menu</a>
    </section>

    <!-- ABOUT -->
    <section id="about" class="about">
        <div class="container">
            <div class="about-content">
                <h2>Our Story</h2>
                <p>Since 2005, we've been serving...</p>
            </div>
            <img src="https://picsum.photos/600/400?random=10" alt="Restaurant" class="about-img">
        </div>
    </section>

    <!-- MENU -->
    <section id="menu" class="menu-section">
        <div class="container">
            <h2>Our Menu</h2>
            <div class="menu-grid">
                <div class="menu-card">
                    <img src="https://picsum.photos/400/300?random=20" alt="">
                    <h3>Margherita Pizza</h3>

                <!-- ещё 5 карточек -->
            </div>
        </div>

    <!-- GALLERY -->
    <section id="gallery" class="gallery-section">

Суп из div'ов. Новички часто пишут так:

<div class="header">...</div>
<div class="hero">...</div>
<div class="menu">...</div>
<div class="footer">...</div>

Технически работает, но у Google, скринридеров и ваших будущих коллег нет способа понять, где шапка, где подвал. Используйте семантические теги там, где они есть: <header>, <nav>, <main>, <section>, <article>, <aside>, <footer>.

Div soup. Beginners often write:

<div class="header">...</div>
<div class="hero">...</div>
<div class="menu">...</div>
<div class="footer">...</div>

Technically works, but Google, screen readers and your future colleagues have no way to tell where the header or footer is. Use semantic tags when available: <header>, <nav>, <main>, <section>, <article>, <aside>, <footer>.

id="about" = якорная ссылка. Когда пользователь кликает <a href="#about"> в навигации, браузер прокручивает страницу к элементу с id="about". Добавьте scroll-behavior: smooth в html — и прокрутка будет плавной. Никакого JavaScript не нужно!

id="about" = anchor link. When the user clicks <a href="#about"> in the nav, the browser scrolls to the element with id="about". Add scroll-behavior: smooth to html — and scrolling becomes smooth. No JavaScript needed!

4. CSS: базовые стили и переменные

4. CSS: base styles and variables

Базовые стили — фундамент всего сайта. В этом блоке мы делаем 4 вещи: определяем дизайн-токены (цвета и шрифты в переменных), сбрасываем отступы браузера, задаём базовую типографику и повторно описываем container-паттерн (тот самый width: 90% + max-width: 1200px + margin: 0 auto из 20-го урока).

Все эти вещи «не видны» на странице, но без них невозможно собрать аккуратный макет. Представьте это как ремонт: до того как вешать картины, надо выровнять стены.

Base styles are the foundation. In this block we do 4 things: define design tokens (colors and fonts in variables), reset browser margins, set up base typography, and reapply the container pattern (width: 90% + max-width: 1200px + margin: 0 auto from lesson 20).

None of this is visible on the page, but without it you can't build a clean layout. Like renovating a room: before hanging pictures, level the walls.

:root {
    --color-primary: #b45309;
    --color-dark: #1c1917;
    --color-light: #faf7f2;
    --color-text: #44403c;
    --color-muted: #78716c;
    --font-heading: 'Georgia', serif;
    --font-body: 'Segoe UI', sans-serif;
}

* { margin: 0; padding: 0; box-sizing: border-box; }

body {
    font-family: var(--font-body);
    color: var(--color-text);
    line-height: 1.7;
}

img { max-width: 100%; height: auto; }

.container {
    width: 90%;
    max-width: 1200px;
    margin: 0 auto;
}

section { padding: 80px 0; }

h2 {
    font-family: var(--font-heading);
    font-size: clamp(1.8rem, 4vw, 2.5rem);
    color: var(--color-dark);
    text-align: center;
    margin-bottom: 40px;
}

CSS-переменные (--color-primary) позволяют менять цвета в одном месте! Если клиент захочет другой основной цвет — достаточно изменить одну строку. Используем их через var(--color-primary). Никакой препроцессор (SASS/LESS) для этого уже не нужен — переменные поддерживаются всеми современными браузерами с 2016 года.

CSS variables (--color-primary) let you change colors in one place! If the client wants a different primary color — just change one line. Use them via var(--color-primary). No preprocessor (SASS/LESS) needed anymore — variables are supported by all modern browsers since 2016.

Почему * { box-sizing: border-box }? По умолчанию браузер считает width БЕЗ учёта padding и border — и ширина «уплывает». С border-box padding и border включены в width. Этот сброс (reset) — практически индустриальный стандарт: его ставят в 99% коммерческих проектов. Никогда не забывайте!
Why * { box-sizing: border-box }? By default the browser calculates width WITHOUT padding and border — and widths "drift". With border-box, padding and border are included in width. This reset is practically an industry standard: used in 99% of commercial projects. Never forget it!

Дизайн-токены. Заметьте, как переменные названы: --color-primary, --color-dark, --color-muted. Это не случайные цвета — это роли. Клиент говорит «поменяйте основной цвет на зелёный» — вы меняете одну строку. Если бы цвет #b45309 был разбросан по 50 местам — пришлось бы править полчаса.

Design tokens. Notice how variables are named: --color-primary, --color-dark, --color-muted. Those aren't random colors — those are roles. Client says "change the primary color to green" — you change one line. If #b45309 were scattered across 50 places — you'd spend half an hour fixing it.

5. CSS: header с бургер-меню

5. CSS: header with burger menu

Header — первое, что видит пользователь. Хороший header делает три вещи одновременно: остаётся на экране при прокрутке (навигация всегда под рукой), не закрывает контент (прозрачный фон), и выглядит современно. Для этого мы используем position: fixed + backdrop-filter: blur() — так делают почти все современные сайты (Apple, Stripe, GitHub).

The header is the first thing the user sees. A good header does three things at once: stays on screen while scrolling (nav always at hand), doesn't block content (semi-transparent background), and looks modern. For this we use position: fixed + backdrop-filter: blur() — as almost all modern sites do (Apple, Stripe, GitHub).

.header {
    position: fixed;
    top: 0;
    left: 0;
    right: 0;
    height: 70px;
    background: rgba(255, 255, 255, 0.95);
    backdrop-filter: blur(10px);
    display: flex;
    align-items: center;
    padding: 0 5%;
    z-index: 100;
    border-bottom: 1px solid #e7e5e4;
}

.logo {
    font-family: var(--font-heading);
    font-size: 1.5rem;
    font-weight: 700;
    color: var(--color-primary);
    text-decoration: none;
}

.menu-toggle { display: none; }
.burger { display: none; }

.nav { display: flex; gap: 24px; margin-left: auto; }
.nav a {
    text-decoration: none;
    color: var(--color-text);
    font-weight: 500;
    transition: color 0.2s;
}
.nav a:hover { color: var(--color-primary); }

backdrop-filter: blur(10px) — матовое стекло. Представьте, что header сделан из матового стекла: контент под ним размыт, но угадывается. Это даёт современный премиум-вид и не требует непрозрачного фона (который бы закрывал фото под хедером в hero-секции).

backdrop-filter: blur(10px) — frosted glass. Imagine the header is made of frosted glass: content behind it is blurred, but hinted at. This gives a premium modern look without needing a solid background (which would hide the hero image behind the header).

Почему z-index: 100? position: fixed вынимает элемент из потока, но это не гарантирует, что он будет сверху остальных элементов. Если в секциях ниже будут свои z-index — они могут перекрыть header. Ставим большое значение (100, 999, 1000) — чтобы точно быть сверху.
Why z-index: 100? position: fixed takes an element out of flow, but doesn't guarantee it stays on top of others. If sections below have their own z-index — they could overlap the header. Set a large value (100, 999, 1000) — to definitely be on top.

Fixed header закрывает hero! Новички делают position: fixed; height: 70px; — и первые 70px hero-секции оказываются под хедером. Решение: либо добавьте padding-top: 70px к <main>, либо сделайте hero полноэкранным с height: 100vh, чтобы текст в центре не закрывался (как у нас — hero использует justify-content: center, так что содержимое в середине).

Fixed header covers the hero! Beginners set position: fixed; height: 70px; — and the first 70px of the hero ends up under the header. Fix: either add padding-top: 70px to <main>, or make hero full-screen with height: 100vh so centered text isn't covered (which is what we do — hero uses justify-content: center, so content stays in the middle).

Почему бургер прячется на десктопе? На десктопе достаточно места для горизонтальной навигации — прятать её в бургер было бы жестокостью к пользователю (лишний клик). На мобильном наоборот — 5 ссылок в ряд не помещаются. Поэтому: .burger { display: none } по умолчанию (десктоп), а внутри @media (max-width: 768px) мы её показываем и одновременно прячем .nav.

Why is the burger hidden on desktop? On desktop there's space for horizontal nav — hiding it in a burger would be cruel (extra click). On mobile — 5 links don't fit in a row. So: .burger { display: none } by default (desktop), and inside @media (max-width: 768px) we show it and simultaneously hide .nav.

6. CSS: hero-секция

6. CSS: hero section

Hero-секция — это «первый экран» сайта, то что пользователь видит до прокрутки. У рестораторов здесь одна задача: зацепить. Большое фото красивой еды + название ресторана + кнопка «Посмотреть меню». Никакой воды.

Технически здесь три приёма: height: 100vh (на весь экран), фон-картинка с тёмным overlay (чтобы белый текст читался), и flex-центрирование содержимого.

The hero section is the "first screen" the user sees before scrolling. Restaurant clients want one thing here: to hook. A big photo of beautiful food + restaurant name + "View menu" button. Nothing else.

Three techniques: height: 100vh (full screen), background image with a dark overlay (so white text is readable), and flex centering.

.hero {
    height: 100vh;
    background: linear-gradient(rgba(0,0,0,0.5), rgba(0,0,0,0.5)),
                url('https://picsum.photos/1600/900?random=1') center/cover;
    display: flex;
    flex-direction: column;
    align-items: center;
    justify-content: center;
    text-align: center;
    color: #fff;
    padding: 0 20px;
}

.hero h1 {
    font-family: var(--font-heading);
    font-size: clamp(2rem, 6vw, 4rem);
    margin-bottom: 16px;
}

.hero p {
    font-size: clamp(1rem, 2vw, 1.3rem);
    margin-bottom: 32px;
    opacity: 0.9;
}

.btn {
    display: inline-block;
    padding: 14px 36px;
    background: var(--color-primary);
    color: #fff;
    text-decoration: none;
    border-radius: 8px;
    font-weight: 600;
    transition: background 0.3s, transform 0.2s;
}
.btn:hover {
    background: #92400e;
    transform: translateY(-2px);
}

Два фона в одном background. Обратите внимание:

background: linear-gradient(rgba(0,0,0,0.5), rgba(0,0,0,0.5)),
            url('photo.jpg') center/cover;

Это два слоя: сверху — тёмный полупрозрачный градиент (одинаковый сверху и снизу = просто тёмная плёнка), снизу — фото. Градиент делает белый текст читаемым на любом фото. Без него — текст теряется на светлых участках.

Two backgrounds in one background. Note:

background: linear-gradient(rgba(0,0,0,0.5), rgba(0,0,0,0.5)),
            url('photo.jpg') center/cover;

Two layers: on top — a dark translucent gradient (same top and bottom = just a dark film), below — the photo. The gradient makes white text readable on any photo. Without it — text gets lost on bright areas.

Поиграйте с прозрачностью overlay. Откройте DevTools, найдите .hero и меняйте значение в rgba(0,0,0, X):

  • 0.3 — светлый overlay, текст еле читается на светлом фото
  • 0.5 — баланс (наш выбор)
  • 0.7 — тёмно, текст всегда чёткий, но фото почти не видно

Выберите под ваш фон. Для светлых фото берите 0.5-0.6, для тёмных — 0.3-0.4.

Play with overlay opacity. Open DevTools, find .hero and change the value in rgba(0,0,0, X):

  • 0.3 — light overlay, text is barely readable on bright photos
  • 0.5 — balanced (our pick)
  • 0.7 — dark, text always crisp, but the photo is barely visible

Pick based on your background. Light photos need 0.5-0.6, dark photos 0.3-0.4.

center/cover — два слова про позицию и масштаб. center = картинка выровнена по центру. cover = картинка покрывает весь блок, сохраняя пропорции (может обрезаться). Альтернатива: contain (вся картинка видна, могут быть поля). Для hero-секций почти всегда cover.

center/cover — two words about position and scale. center = image centered. cover = image covers the whole block, keeping proportions (may be cropped). Alternative: contain (full image visible, may have gaps). For hero sections, almost always cover.

clamp() — не забывайте про мобильные! Без clamp() на мобильном font-size: 4rem даст заголовок на пол-экрана. Поэтому пишем clamp(2rem, 6vw, 4rem) — на телефоне будет 2rem (~32px), на десктопе 4rem (64px), а между — плавно.

clamp() — don't forget mobile! Without clamp(), font-size: 4rem on mobile takes up half the screen. So we write clamp(2rem, 6vw, 4rem) — phone gets 2rem (~32px), desktop 4rem (64px), and in between — smooth.

7. CSS: меню блюд

7. CSS: food menu

Меню — главная секция ресторанного сайта (помните UX-статистику? 90% посетителей ищут именно меню). Поэтому мы делаем её визуально заметной: другой фон (--color-light), крупная сетка карточек с фото, hover-эффект подъёма.

Технически это CSS Grid: grid-template-columns: repeat(3, 1fr) — три колонки одинаковой ширины. Это самый удобный способ собрать равномерную сетку карточек. На планшете переходим на 2 колонки, на мобильном — на 1.

Menu is the main section of a restaurant site (remember UX stats? 90% of visitors look for the menu). So we make it visually prominent: different background (--color-light), large grid of photo cards, hover lift effect.

Technically this is CSS Grid: grid-template-columns: repeat(3, 1fr) — three equal columns. The most convenient way to build an even card grid. On tablet we drop to 2 columns, on mobile — to 1.

.menu-section { background: var(--color-light); }

.menu-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 24px;
}

.menu-card {
    background: #fff;
    border-radius: 16px;
    overflow: hidden;
    box-shadow: 0 2px 12px rgba(0,0,0,0.06);
    transition: transform 0.3s, box-shadow 0.3s;
}
.menu-card:hover {
    transform: translateY(-6px);
    box-shadow: 0 12px 32px rgba(0,0,0,0.12);
}

.menu-card img {
    width: 100%;
    height: 200px;
    object-fit: cover;
}

.menu-card h3 {
    padding: 16px 16px 4px;
    font-size: 1.1rem;
}
.menu-card p {
    padding: 0 16px;
    font-size: 0.9rem;
    color: var(--color-muted);
}
.price {
    display: block;
    padding: 8px 16px 16px;
    font-weight: 700;
    font-size: 1.1rem;
    color: var(--color-primary);
}
Зачем overflow: hidden + border-radius? border-radius скругляет сам блок, но не его содержимое. Фото внутри продолжают быть прямоугольными и вылезают за углы. overflow: hidden обрезает всё, что вылезает — получаем аккуратные скруглённые фото внутри карточки.
Why overflow: hidden + border-radius? border-radius rounds the block itself, but not its contents. Photos inside remain rectangular and stick out of the corners. overflow: hidden crops anything sticking out — and we get neatly rounded photos inside the card.

object-fit: cover — спасение для фото еды. Фотографии блюд всегда разных пропорций (одни квадратные, другие вертикальные). Без object-fit они сделают карточки разного размера — сетка сломается. height: 200px + object-fit: cover = все фото ровно 200px в высоту, обрезаются по центру, никакого искажения. Это индустриальный стандарт для любых каталогов.

object-fit: cover — a lifesaver for food photos. Dish photos come in all proportions (some square, some vertical). Without object-fit they'd make cards different sizes — grid breaks. height: 200px + object-fit: cover = all photos exactly 200px tall, cropped center, no distortion. Industry standard for any catalog.

1fr — волшебная единица grid. 1fr = «одна доля свободного места». repeat(3, 1fr) = три равных колонки. grid-template-columns: 2fr 1fr = первая колонка в 2 раза шире второй. В отличие от %, fr учитывает gap и не вызывает горизонтальный скролл.

1fr — the magic grid unit. 1fr = "one fraction of available space". repeat(3, 1fr) = three equal columns. grid-template-columns: 2fr 1fr = first column is 2× wider than the second. Unlike %, fr accounts for gap and never causes horizontal scroll.

8. CSS: галерея

8. CSS: gallery

Галерея — это «доказательство качества». Меню говорит что есть в ресторане, а галерея показывает атмосферу: интерьер, столы, люди, улыбки. По структуре похожа на меню (тоже grid), но более плотная (4 колонки против 3) и без текста — только фото.

The gallery is "proof of quality". The menu says what the restaurant has; the gallery shows the atmosphere: interior, tables, people, smiles. Structurally similar to the menu (also a grid), but denser (4 columns vs 3) and without text — just photos.

.gallery-grid {
    display: grid;
    grid-template-columns: repeat(4, 1fr);
    gap: 12px;
}

.gallery-grid img {
    width: 100%;
    height: 220px;
    object-fit: cover;
    border-radius: 12px;
    transition: transform 0.3s;
}
.gallery-grid img:hover {
    transform: scale(1.05);
}

transform: scale(1.05) на hover — классика галерей. Картинка слегка увеличивается при наведении, создаётся ощущение «живого» контента. Эффект работает только потому, что родитель карточки не имеет overflow: hidden — фото вылезает за границы на 5%. Хотите, чтобы оно обрезалось по рамке — оберните в <div> с overflow: hidden.

transform: scale(1.05) on hover — a gallery classic. Image slightly grows on hover, giving a "live" feel. Only works because the card's parent has no overflow: hidden — the photo extends 5% beyond bounds. If you want it cropped to the frame — wrap in a <div> with overflow: hidden.

Lazy-loading «из коробки». Добавьте loading="lazy" в <img>:

<img src="big-photo.jpg" alt="" loading="lazy">

Браузер загрузит фото, только когда пользователь прокрутит до него. Сайт грузится быстрее, трафик экономится. В галереях с 20+ фото — обязательно.

Lazy-loading out of the box. Add loading="lazy" to <img>:

<img src="big-photo.jpg" alt="" loading="lazy">

Browser loads the photo only when the user scrolls to it. Site loads faster, bandwidth is saved. For galleries with 20+ photos — a must.

9. CSS: контакты

9. CSS: contacts

Контактная секция — это конверсия. Ради неё всё остальное. Посетитель посмотрел меню, увидел галерею, теперь должен позвонить или написать. Поэтому здесь два блока в одном ряду: слева — информация (адрес, телефон, часы), справа — форма для сообщения. Пользователь выбирает удобный способ.

Технически это display: flex; gap: 40px — простой flex-ряд. На мобильном превращаем в стопку через flex-direction: column в media query.

The contact section is conversion. Everything else serves this moment. The visitor saw the menu, saw the gallery, now should call or write. So two blocks side by side: on the left — info (address, phone, hours), on the right — a message form. User picks their preferred way.

Technically this is display: flex; gap: 40px — a simple flex row. On mobile we stack with flex-direction: column in a media query.

.contact-section { background: var(--color-light); }

.contact-row {
    display: flex;
    gap: 40px;
    align-items: flex-start;
}

.contact-info { flex: 1; }
.contact-info p { margin: 12px 0; font-size: 1rem; }

.contact-form {
    flex: 1;
    display: flex;
    flex-direction: column;
    gap: 16px;
}

.contact-form input,
.contact-form textarea {
    padding: 12px 16px;
    border: 1px solid #d6d3d1;
    border-radius: 8px;
    font-size: 1rem;
    font-family: inherit;
}
.contact-form textarea { min-height: 120px; resize: vertical; }

.contact-form button {
    padding: 14px;
    background: var(--color-primary);
    color: #fff;
    border: none;
    border-radius: 8px;
    font-size: 1rem;
    font-weight: 600;
    cursor: pointer;
    transition: background 0.2s;
}
.contact-form button:hover { background: #92400e; }
flex: 1 у обоих блоков = равные половины. Оба элемента получают одинаковую долю свободного пространства. Хотите 60/40? Поставьте flex: 6 у первого и flex: 4 у второго. Хотите фиксированную ширину формы? .contact-form { flex: 0 0 400px }.
flex: 1 on both blocks = equal halves. Both elements get the same share of free space. Want 60/40? Set flex: 6 and flex: 4. Want a fixed form width? .contact-form { flex: 0 0 400px }.

textarea без resize: vertical — беда. По умолчанию textarea позволяет пользователю тянуть в любую сторону — в том числе вширь. Результат: пользователь случайно растягивает поле, и форма ломает макет. Решение: resize: vertical (только по высоте) или resize: none (вообще нельзя).

textarea without resize: vertical — trouble. By default textarea lets users drag in any direction — including horizontally. Result: user accidentally stretches the field and breaks your layout. Fix: resize: vertical (height only) or resize: none (not at all).

font-family: inherit у инпутов. Браузеры по умолчанию ставят в <input> и <textarea> системный шрифт (обычно другой, чем у вас на сайте). Результат: инпуты выглядят «чужеродно». font-family: inherit наследует шрифт от родителя — всё выглядит единообразно.

font-family: inherit for inputs. Browsers default <input> and <textarea> to a system font (usually different from your site's). Result: inputs look foreign. font-family: inherit inherits from parent — everything looks consistent.

10. CSS: footer

10. CSS: footer

Footer — «визитка» сайта. Если пользователь дочитал до конца — он уже заинтересован. В footer кладём всё, что может понадобиться: дублирующие ссылки, часы работы, адрес, соцсети, копирайт. Стандарт — 3 колонки: «О нас», «Контакты», «Соцсети».

Footer is the "business card" of the site. If the user scrolled this far — they're interested. Put everything useful here: duplicate links, hours, address, socials, copyright. Standard — 3 columns: "About", "Contact", "Socials".

Visually footer stands out from the rest — dark background, muted text colors. It's a visual "period at the end of a sentence" — the user knows the page is done.

Clickable phone. Always wrap the number in <a href="tel:...">. On mobile, tap opens the phone app — user calls in one tap. One of the simplest UX tricks that dramatically improves restaurant-site conversion.

11. CSS: media queries (планшет + мобильный)

11. CSS: media queries (tablet + mobile)

Это кульминация всего урока. До этого момента мы писали стили для десктопа. Теперь добавляем media queries — два блока, которые перенастраивают макет под планшет и мобильный. Весь десктопный CSS остаётся, media queries только перекрывают нужные свойства.

Обратите внимание на каскад: мы сначала пишем правила для экранов ≤992px (планшет и уже), а потом для ≤768px (только мобильный). Мобильный получает ОБА набора правил: и планшетные, и свои. Это работает, потому что в CSS правила применяются «сверху вниз» — более специфичное media query (меньше ширина) перекрывает общее.

This is the climax of the lesson. Until now we wrote desktop styles. Now we add media queries — two blocks that reconfigure the layout for tablet and mobile. All desktop CSS stays; media queries only override specific properties.

Note the cascade: first rules for ≤992px (tablet and narrower), then ≤768px (mobile only). Mobile gets BOTH sets: tablet rules plus its own. This works because CSS applies rules top-down — a more specific media query (smaller width) overrides the general one.

/* ========== ПЛАНШЕТ (≤ 992px) ========== */
@media (max-width: 992px) {
    .menu-grid { grid-template-columns: repeat(2, 1fr); }
    .gallery-grid { grid-template-columns: repeat(3, 1fr); }
}

/* ========== МОБИЛЬНЫЙ (≤ 768px) ========== */
@media (max-width: 768px) {
    /* Бургер-меню */
    .burger {
        display: flex;
        flex-direction: column;
        gap: 5px;
        cursor: pointer;
        margin-left: auto;
        padding: 8px;
    }
    .burger span {
        width: 24px; height: 3px;
        background: var(--color-dark);
        border-radius: 2px;
        transition: 0.3s;
    }
    .nav {
        position: absolute;
        top: 70px; left: 0; right: 0;
        background: #fff;
        flex-direction: column;
        padding: 16px 5%;
        border-bottom: 1px solid #e7e5e4;
        display: none;
    }
    .menu-toggle:checked ~ .nav { display: flex; }
    .menu-toggle:checked ~ .burger span:nth-child(1) {
        transform: rotate(45deg) translate(5px, 6px);
    }
    .menu-toggle:checked ~ .burger span:nth-child(2) { opacity: 0; }
    .menu-toggle:checked ~ .burger span:nth-child(3) {
        transform: rotate(-45deg) translate(5px, -6px);
    }

    /* Hero */
    .hero { height: 70vh; }

    /* About: стопка */
    .about .container { flex-direction: column; }
    .about-img { order: -1; }

    /* Menu: 1 колонка */
    .menu-grid { grid-template-columns: 1fr; }

    /* Gallery: 2 колонки */
    .gallery-grid { grid-template-columns: repeat(2, 1fr); }

    /* Contacts: стопка */
    .contact-row { flex-direction: column; }

    /* Footer: 1 колонка */
    .footer-grid { grid-template-columns: 1fr; }

    /* Отступы */
    section { padding: 48px 0; }
}
Разбор анимации бургера в крестик. Три <span> — это три палочки бургера. Когда чекбокс становится checked:
  • 1-я палочка поворачивается на 45° и сдвигается — становится диагональю «\»
  • 2-я палочка исчезает (opacity: 0)
  • 3-я палочка поворачивается на -45° и сдвигается — становится диагональю «/»
Вместе «\» + «/» = крестик «×». Пользователю понятно: меню открыто, можно закрыть. Без этой анимации бургер-меню будет казаться сломанным.
Burger-to-cross animation breakdown. Three <span>s — three burger bars. When the checkbox is checked:
  • 1st bar rotates 45° and shifts — becomes the "\" diagonal
  • 2nd bar disappears (opacity: 0)
  • 3rd bar rotates -45° and shifts — becomes the "/" diagonal
Together "\" + "/" = the "×" cross. User understands: menu is open, can close. Without this animation the burger menu feels broken.

Don't test only on your own monitor! Most common beginner mistake: "Looks great on my screen." But the client has a 13" laptop, a 6-year-old Samsung phone, an $80 tablet. Always check in DevTools emulator on at least 3 devices: iPhone SE (375px), iPad (768px), Desktop HD (1440px).

  8. Проверьте клавиатурную навигацию (Tab) — все ссылки и форма должны быть доступны
Step-by-step plan:
  1. Pick a theme (sushi / coffee shop / national cuisine — any)
  2. Sketch layouts on paper for 3 resolutions (5-10 min)
  3. Write HTML for all sections without styles
  4. Define CSS variables (colors for your theme)
  5. Style sections in order: header → hero → menu → gallery → contact → footer
  6. Add media queries — tablet first, then mobile
  7. Check in DevTools at 375px, 768px, 1440px
  8. Check keyboard navigation (Tab) — all links and form must be reachable
