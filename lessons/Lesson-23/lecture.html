Занятие 23: CSS Transitions и Transform

Lesson 23: CSS Transitions and Transform

Плавные переходы, трансформации: translate, rotate, scale, skew, hover-эффекты

Smooth transitions, transforms: translate, rotate, scale, skew, hover effects

До сих пор наши сайты были статичными. Пользователь наводит на кнопку — цвет меняется мгновенно. Нажимает — ничего не двигается. Это работает, но выглядит как сайт из 2005 года.

Современные сайты реагируют на действия: кнопка плавно меняет цвет, карточка приподнимается при наведении, иконка поворачивается на 45°, при нажатии элемент «утопает». Именно эти маленькие детали отличают профессиональный сайт от любительского.

Хорошая новость: для этого не нужен JavaScript. CSS даёт два мощных инструмента: transition (плавные переходы между состояниями) и transform (трансформации — сдвиг, поворот, масштаб, наклон). Вместе они покрывают 90% всех интерактивных анимаций на сайтах.

  • Управлять длительностью и «характером» анимации через timing-function
  • Двигать элементы без смещения соседей через translate
  • Увеличивать и уменьшать без искажений через scale
  • Вращать иконки через rotate
  • Комбинировать несколько трансформаций в одну
  • Собирать готовые hover-паттерны для карточек, кнопок, иконок

Until now our sites were static. User hovers a button — color changes instantly. Clicks — nothing moves. It works, but it looks like a 2005 website.

Modern sites react to actions: button smoothly changes color, card lifts on hover, icon rotates 45°, element "sinks" on click. Those small details separate a professional site from an amateur one.

Good news: no JavaScript needed. CSS gives two powerful tools: transition (smooth changes between states) and transform (transformations — move, rotate, scale, skew). Together they cover 90% of interactive animations on websites.

1. Зачем нужны анимации

1. Why animations matter

Анимации делают сайт живым и отзывчивым. Когда кнопка плавно меняет цвет при наведении — пользователь чувствует, что сайт реагирует на его действия.

Animations make a site lively and responsive. When a button smoothly changes color on hover — the user feels the site reacting to their actions.

❌ Без transition
❌ Without transition

Цвет меняется мгновенно. Резко, неприятно, дёшево.

Color changes instantly. Abrupt, unpleasant, cheap.

✅ С transition
✅ With transition

Цвет меняется плавно за 0.3s. Красиво, профессионально.

Color changes smoothly in 0.3s. Beautiful, professional.

Автомобильный тормоз. Когда вы нажимаете педаль тормоза в машине, она не блокируется мгновенно — это бы вас швырнуло в лобовое. Тормоз плавно увеличивает сопротивление, и машина замедляется комфортно. CSS-анимация — тот же принцип: мгновенное изменение «швыряет» взгляд пользователя, плавное — направляет его.

A car brake. When you press the brake pedal, it doesn't lock instantly — that would throw you through the windshield. The brake smoothly builds resistance, and the car slows comfortably. CSS animation is the same principle: instant changes "jolt" the user's eye, smooth ones guide it.

Анимации — это про восприятие качества. Исследования Nielsen Norman Group показывают: сайты с плавными transition воспринимаются пользователями как более качественные и дорогие, даже если содержимое у них идентичное. Для e-commerce это значит более высокую конверсию. Apple, Stripe, Airbnb — все известные своим дизайном сайты обильно используют transition.

Animations are about perceived quality. Nielsen Norman Group research shows: sites with smooth transitions are perceived by users as more high-quality and expensive, even with identical content. For e-commerce this means higher conversion. Apple, Stripe, Airbnb — all the design-famous sites use transitions heavily.

Главное правило: анимации — для фидбека, а не для развлечения. Каждая анимация должна сообщать что-то пользователю: «кнопка кликабельна» (hover), «я нажал кнопку» (active), «карточка — элемент меню» (hover lift). Анимации ради красоты раздражают и отвлекают.
Key rule: animations are for feedback, not entertainment. Every animation should tell the user something: "this button is clickable" (hover), "I pressed the button" (active), "this card is a menu item" (hover lift). Animations for looks alone are distracting and annoying.

2. transition — плавный переход

2. transition — smooth change

transition — свойство-анимация. Оно говорит браузеру: «когда это CSS-свойство меняется — меняй его не мгновенно, а за N секунд». Работает с любым свойством, которое имеет числовое значение: цвет, размер, положение, прозрачность.

Ключ к пониманию: transition не «создаёт» анимацию сам по себе. Он только замедляет переход между двумя состояниями, которые вы сами задаёте (базовое состояние и :hover, например).

transition is an animation property. It tells the browser: "when this CSS property changes — don't change it instantly, take N seconds". Works with any property that has a numeric value: color, size, position, opacity.

Key insight: transition doesn't "create" animation by itself. It only slows down transitions between two states you define yourself (base state and :hover, for example).

/* Без transition: мгновенное изменение */
.btn { background: #3b82f6; }
.btn:hover { background: #1d4ed8; }

/* С transition: плавное изменение за 0.3s */
.btn {
    background: #3b82f6;
    transition: background 0.3s;
}
.btn:hover { background: #1d4ed8; }
transition пишется на базовом состоянии (не на :hover!). Браузер будет плавно анимировать изменение при наведении И при уходе курсора.
transition is written on the base state (not on :hover!). The browser will smoothly animate the change on hover AND when the cursor leaves.

Типичная ошибка новичка:

.btn { background: #3b82f6; }
.btn:hover {
    background: #1d4ed8;
    transition: background 0.3s;  /* НЕПРАВИЛЬНО */
}

Если написать transition только в :hover — плавный переход сработает только при наведении. А когда курсор уходит — цвет вернётся мгновенно. Получится «въезжаю плавно, выскакиваю резко». Всегда ставьте transition на базовое состояние.

Classic beginner mistake:

.btn { background: #3b82f6; }
.btn:hover {
    background: #1d4ed8;
    transition: background 0.3s;  /* WRONG */
}

If you write transition only on :hover — smooth change only works on hover. When the cursor leaves — color snaps back instantly. You get "slide in smooth, snap out hard". Always put transition on the base state.

Откройте любой сайт (Google, YouTube, GitHub) и откройте DevTools. Наведите на любую кнопку, затем в Elements выберите её и на панели Styles ищите слово transition. Вы увидите, что почти все интерактивные элементы имеют transition — это индустриальный стандарт.

Open any site (Google, YouTube, GitHub) and open DevTools. Hover any button, then select it in Elements and look in Styles for the word transition. You'll see almost all interactive elements have transition — it's the industry standard.

3. Свойства transition

3. transition properties

Короткое transition: background 0.3s — это сокращённая запись. На самом деле у transition 4 параметра: что анимировать, как долго, с какой «кривой», и с какой задержкой. В порядке частоты использования: 95% случаев — первые два параметра, остальные — для сложных эффектов.

The short transition: background 0.3s is shorthand. Actually transition has 4 parameters: what to animate, how long, with what "curve", and with what delay. In order of usage frequency: 95% of cases — first two params, the rest — for complex effects.

transition: property duration timing-function delay;

/* Примеры: */
transition: background 0.3s ease;
transition: color 0.2s ease-in-out;
transition: transform 0.5s ease 0.1s;  /* с задержкой 0.1s */
transition: all 0.3s ease;             /* ВСЕ свойства */

delay полезен для «цепочки» анимаций. Представьте карточку, у которой при hover сначала увеличивается тень (0.2s), а потом (через 0.1s задержки) поднимается сама карточка (0.3s). Эффект «карточка сначала «вибрирует», потом поднимается». Реализуется через два разных значения delay в одном transition.

delay is useful for "chained" animations. Imagine a card: on hover the shadow grows first (0.2s), then (after 0.1s delay) the card itself lifts (0.3s). The effect: "card vibrates, then lifts". Achieved via two different delay values in one transition.

4. timing-function — кривые ускорения

4. timing-function — easing curves

Переход за 0.3 секунды — это не просто равномерное движение. Анимация может ускоряться в начале, замедляться в конце, или делать и то и другое. Это называется easing (смягчение) или timing-function.

Почему это важно? Потому что в реальном мире движение редко бывает равномерным. Машина трогается медленно, разгоняется и плавно тормозит — не скачет с места с постоянной скоростью. Анимации, повторяющие этот «естественный» паттерн, кажутся приятными. Линейные — роботизированными.

A 0.3s transition is not just uniform movement. Animation can accelerate at the start, slow at the end, or both. This is called easing or timing-function.

Why does it matter? Because in real life movement is rarely uniform. A car starts slowly, accelerates, and smoothly brakes — it doesn't jump from standing at constant speed. Animations that mimic this "natural" pattern feel pleasant. Linear ones feel robotic.

Разгон автомобиля.

  • linear — телепорт с постоянной скоростью (нереалистично)
  • ease-in — машина трогается: медленно, потом быстрее
  • ease-out — машина тормозит: быстро, потом замедляется
  • ease-in-out — полный цикл: разгон → торможение
  • ease — похоже на ease-in-out, но асимметрично (быстрее стартует)

Car acceleration.

  • linear — teleport at constant speed (unnatural)
  • ease-in — car starts: slow, then fast
  • ease-out — car brakes: fast, then slow
  • ease-in-out — full cycle: accelerate → brake
  • ease — similar to ease-in-out, but asymmetric (starts faster)

Правило выбора:

  • Hover-эффекты (кнопки, ссылки, карточки) → ease (по умолчанию)
  • Появление элемента (модальное окно, popup) → ease-out (начинается быстро, замедляется при появлении — внимание привлекается сразу)

Selection rule:

  • Hover effects (buttons, links, cards) → ease (default)

  • Element disappearing → ease-in (starts slow, flies out fast — "leaving" feel)
  • Progress bars, spinners, loaders → linear (uniform)

cubic-bezier() — свой собственный easing. Все эти ease, ease-in — это предустановки. На самом деле под капотом работает функция cubic-bezier(x1, y1, x2, y2) с 4 параметрами, определяющими форму кривой. Например, ease-in = cubic-bezier(0.42, 0, 1, 1). Можно рисовать свои «пружинящие» эффекты на сайте cubic-bezier.com.

cubic-bezier() — roll your own easing. All these ease, ease-in — are presets. Under the hood is cubic-bezier(x1, y1, x2, y2) with 4 params defining the curve shape. E.g., ease-in = cubic-bezier(0.42, 0, 1, 1). Design your own "springy" curves at cubic-bezier.com.

5. Несколько transition сразу

5. Multiple transitions

Обычно при hover меняется не одно, а несколько свойств сразу: цвет фона + положение + тень. Нужно анимировать их все одновременно, но иногда с разной длительностью (например, тень быстрее, положение медленнее). Для этого в CSS есть два способа.

Usually on hover several properties change at once: background + position + shadow. Need to animate all of them, sometimes with different durations (e.g., shadow faster, position slower). CSS provides two ways for this.

/* Способ 1: all (все свойства) */
transition: all 0.3s ease;

/* Способ 2: перечисление через запятую */
transition: background 0.3s ease,
            color 0.2s ease,
            transform 0.4s ease;
all — удобно, но менее производительно. Для простых hover-эффектов all вполне подходит. Для сложных анимаций лучше перечислять конкретные свойства.
all — convenient but less performant. For simple hover effects all is fine. For complex animations, list specific properties.

Опасность transition: all. Если у элемента при hover меняется только цвет, а ВДРУГ позже вы добавите margin в hover-состояние — all начнёт анимировать и margin, и это может «дёргать» макет. Безопаснее явно перечислить свойства. Для продакшен-кода правило: всегда перечисляйте свойства явно.

Danger of transition: all. If an element only changes color on hover, but later you add margin to the hover state — all will start animating margin too, which may "jerk" the layout. Safer to list properties explicitly. For production code: always list properties explicitly.

«Дешёвые» и «дорогие» свойства для анимации. Не все CSS-свойства одинаково быстро анимируются браузером:

  • Дёшево (GPU-ускорение, плавные 60fps): transform, opacity
  • Средне: color, background-color, box-shadow
  • Дорого (вызывает перерисовку всей страницы): width, height, top, left, margin

Правило: если нужно «подвинуть» элемент — используйте transform: translate(), а не left: .... Для «увеличить» — transform: scale(), а не width: .... Это покажется неважным на простой странице, но на странице с 100 карточек разница между 60fps и 20fps становится огромной.

"Cheap" and "expensive" properties to animate. Not all CSS properties animate equally fast:

  • Cheap (GPU-accelerated, smooth 60fps): transform, opacity
  • Medium: color, background-color, box-shadow
  • Expensive (triggers full-page repaint): width, height, top, left, margin

Rule: to "move" an element — use transform: translate(), not left: .... To "enlarge" — transform: scale(), not width: .... Won't matter on a simple page, but on a page with 100 cards the difference between 60fps and 20fps becomes huge.

6. transform — трансформации

6. transform — transformations

transform — второй мощный инструмент CSS-анимаций. Если transition замедляет переход, то transform двигает, крутит, масштабирует элементы. Вместе они — основа всех красивых hover-эффектов в интернете.

Ключевая особенность: transform НЕ влияет на соседей. Если вы напишете margin-top: -10px — все элементы ниже сдвинутся вверх, макет «поедет». А transform: translateY(-10px) — элемент визуально поднимется, но для макета он остался на месте. Соседи не двигаются. Это бесценно для hover-эффектов.

transform — the second powerful CSS animation tool. If transition slows down changes, transform moves, rotates, scales elements. Together they're the foundation of all nice hover effects on the web.

Key feature: transform does NOT affect neighbors. Write margin-top: -10px — all elements below shift up, layout jumps. But transform: translateY(-10px) — element visually lifts, but for the layout it stayed in place. Neighbors don't move. Invaluable for hover effects.

transform изменяет элемент визуально, не влияя на поток документа (соседние элементы не сдвигаются).

transform changes an element visually without affecting document flow (neighboring elements don't shift).

Голограмма vs физическое движение. Представьте элемент как голограмму. margin, width, top — это физическое перемещение объекта: он двигается, и всё вокруг реагирует. transform — это «голографическая» проекция: объект кажется смещённым, но физически он на месте. Именно поэтому transform — быстрый и не ломает макет.

Hologram vs physical motion. Picture the element as a hologram. margin, width, top — physical movement: object moves, everything around reacts. transform — a "holographic" projection: the object appears moved, but physically it's in place. That's why transform is fast and doesn't break layout.

7. translate — перемещение

7. translate — movement

translate — это перемещение. translateX(20px) сдвигает элемент на 20px вправо (в сторону положительной оси X), translateY(-10px) — на 10px вверх (в CSS ось Y направлена вниз, поэтому отрицательное значение = вверх).

Самое частое применение — эффект «подъёма карточки» при наведении: translateY(-10px). Карточка будто приподнимается со стола. Если добавить тень — эффект «левитации» готов.

translate means movement. translateX(20px) shifts the element 20px right (positive X), translateY(-10px) — 10px up (in CSS the Y axis points down, so negative = up).

Most common use — the "card lift" hover effect: translateY(-10px). The card seems to rise from the table. Add a shadow — and you have "levitation".

/* Поднять на 10px при hover */
.card {
    transition: transform 0.3s ease;
}
.card:hover {
    transform: translateY(-10px);
}

/* Варианты: */
transform: translateX(20px);    /* вправо на 20px */
transform: translateY(-10px);   /* вверх на 10px */
transform: translate(20px, -10px); /* вправо и вверх */

translateY(-10px) — самый популярный hover-эффект для карточек. Карточка «взлетает» при наведении. Добавьте box-shadow для усиления эффекта!

translateY(-10px) — the most popular hover effect for cards. The card "lifts off" on hover. Add box-shadow to enhance the effect!

8. scale — масштаб

8. scale — scaling

scale — это увеличение или уменьшение. Значение — коэффициент: 1 = нормальный размер, 1.1 = на 10% больше, 0.9 = на 10% меньше.

Главное применение: эффект «приближения» при hover (scale(1.05) — +5%) и эффект «нажатия» при active (scale(0.95) — −5%). Эти маленькие изменения дают пользователю тактильную обратную связь — ощущение, что он реально нажал на кнопку.

scale is enlarging or shrinking. The value is a coefficient: 1 = normal size, 1.1 = 10% larger, 0.9 = 10% smaller.

Main use: "zoom-in" effect on hover (scale(1.05) — +5%) and "press" effect on active (scale(0.95) — −5%). These small changes give users tactile feedback — feeling they actually pressed the button.

/* Увеличить на 10% */
.btn:hover { transform: scale(1.1); }

/* Уменьшить до 95% (эффект нажатия) */
.btn:active { transform: scale(0.95); }

/* Зум на изображении внутри карточки */
.card { overflow: hidden; }
.card img {
    transition: transform 0.4s ease;
}
.card:hover img {
    transform: scale(1.1);
}
scale(1) = обычный размер. scale(1.1) = на 10% больше. scale(0.95) = на 5% меньше.
scale(1) = normal size. scale(1.1) = 10% larger. scale(0.95) = 5% smaller.

Не переборщите с scale. Типичные значения для hover: 1.02–1.1. Значение scale(1.3) или scale(2) выглядит как ошибка — элемент «раздувается» и перекрывает соседей. Помните: scale НЕ двигает соседей, но визуально закрывает их. Меньше — лучше.

Don't overdo scale. Typical hover values: 1.02–1.1. Values like scale(1.3) or scale(2) look like a bug — the element "balloons" and covers neighbors. Remember: scale doesn't move neighbors, but visually covers them. Less is more.

Зум фото в карточке через overflow: hidden у родителя. Картинка увеличивается при hover, но не выходит за рамки карточки. Эффект «заглянуть поближе»:

.card {
    overflow: hidden;   /* отсекаем то, что вылезает */
    border-radius: 12px;
}
.card img {
    transition: transform 0.4s ease;
}
.card:hover img {
    transform: scale(1.1);  /* картинка увеличивается */
}

Работает, потому что родитель (.card) имеет overflow: hidden, и всё, что у картинки вышло за границу — обрезается.

Image zoom inside a card via overflow: hidden on the parent. The image enlarges on hover but doesn't leave the card. The "peek closer" effect:

.card {
    overflow: hidden;   /* crop what sticks out */
    border-radius: 12px;
}
.card img {
    transition: transform 0.4s ease;
}
.card:hover img {
    transform: scale(1.1);  /* image grows */
}

Works because the parent (.card) has overflow: hidden, so anything spilling out is cropped.

9. rotate — вращение

9. rotate — rotation

rotate — поворот элемента вокруг своего центра. Угол задаётся в градусах (deg). Положительный угол — по часовой стрелке, отрицательный — против.

Где используется:

  • Стрелочки-аккордеоны: стрелка вниз при закрытом состоянии, при открытии поворачивается на 180°
  • Иконка «гамбургер» → «крестик»: линии поворачиваются на 45° (это мы уже делали в уроке 21!)
  • Иконки-спиннеры: бесконечное вращение 0° → 360° для индикации загрузки
  • Декоративные элементы: слегка повёрнутый бейдж «NEW» или «SALE»

rotate — rotation around the element's center. Angle in degrees (deg). Positive = clockwise, negative = counter-clockwise.

Where it's used:

  • Accordion arrows: down arrow in closed state, rotates 180° when open
  • Burger-to-cross icons: lines rotate 45° (we already did this in lesson 21!)
  • Spinner icons: infinite 0° → 360° to indicate loading
  • Decorative elements: a slightly rotated "NEW" or "SALE" badge
/* Повернуть иконку на 90° */
.icon:hover { transform: rotate(90deg); }

/* Полный оборот */
.spinner { transform: rotate(360deg); }

/* Отрицательный угол = против часовой */
.arrow:hover { transform: rotate(-180deg); }

Единицы для угла. rotate() поддерживает 4 единицы: deg (градусы, 360 в полном круге), turn (обороты, 1turn = 360°), rad (радианы, 2π в полном круге), grad (грады, 400 в полном круге). В продакшене используют только deg — остальные слишком непривычны.

10. skew — наклон

10. skew — skewing

skew — это параллелограммный наклон. Представьте, что вы держите прямоугольную открытку за верхний и нижний края и сдвигаете их в противоположных направлениях — прямоугольник превратится в параллелограмм. Это и есть skew.

Из четырёх функций transform (translate, scale, rotate, skew) — skew используется реже всего. Но он полезен для декоративных элементов: полоски-разделители, динамичные бейджи, hover-эффекты типа «подъехал сбоку».

skew is a parallelogram tilt. Picture holding a rectangular card by its top and bottom edges and shifting them in opposite directions — the rectangle becomes a parallelogram. That's skew.

Out of the four transform functions (translate, scale, rotate, skew) — skew is least used. But it's handy for decorative elements: dividing stripes, dynamic badges, "slide in from the side" hover effects.

/* Наклон элемента */
.tag:hover { transform: skewX(-5deg); }

/* Декоративная полоска */
.decoration {
    transform: skewX(-15deg);
    background: #3b82f6;
}

skew используется реже, но хорош для декоративных элементов и необычных кнопок.

skew is used less often, but great for decorative elements and unique buttons.

11. Комбинирование трансформаций

11. Combining transforms

В реальных hover-эффектах редко используется только одна трансформация. Красивая кнопка обычно одновременно чуть поднимается (translateY), чуть увеличивается (scale) и получает тень — это создаёт эффект «кнопка нажимается и реагирует». Все эти трансформации записываются в одно transform через пробел.

Real hover effects rarely use just one transform. A nice button typically simultaneously lifts slightly (translateY), grows slightly (scale), and gains a shadow — creating the "button presses and responds" feel. All these go into a single transform separated by spaces.

/* Несколько transform через пробел */
.card:hover {
    transform: translateY(-8px) scale(1.02);
}

/* Кнопка: подъём + лёгкое увеличение + тень */
.btn {
    transition: all 0.3s ease;
}
.btn:hover {
    transform: translateY(-3px) scale(1.05);
    box-shadow: 0 8px 24px rgba(0, 0, 0, 0.15);
}
.btn:active {
    transform: translateY(0) scale(0.98);
    box-shadow: 0 2px 8px rgba(0, 0, 0, 0.1);
}
Порядок важен! translate + rotate ≠ rotate + translate. В большинстве случаев ставьте translate первым.
Order matters! translate + rotate ≠ rotate + translate. In most cases put translate first.

Почему порядок важен? Представьте: сначала вы поворачиваетесь на 90°, а затем шагаете вперёд. Вы окажетесь сбоку от исходной точки. А если сначала шагнёте вперёд, а потом повернётесь — окажетесь впереди с развернутым лицом. То же самое происходит с элементом: каждая последующая трансформация применяется в новой системе координат, созданной предыдущей.

Why does order matter? Imagine: first you rotate 90°, then step forward. You end up sideways from the start. But if you step forward first, then rotate — you're ahead, facing sideways. Same for elements: each subsequent transform applies in the new coordinate system created by the previous one.

Не пишите несколько transform через перевод строки.

.card:hover {
    transform: translateY(-8px);
    transform: scale(1.02);   /* ЭТО ПЕРЕКРОЕТ ПЕРВУЮ! */
}

Второй transform полностью заменит первый — сработает только scale. Всегда пишите все трансформации в одном transform через пробел:

.card:hover {
    transform: translateY(-8px) scale(1.02);  /* ПРАВИЛЬНО */
}

Don't write multiple transform on separate lines.

.card:hover {
    transform: translateY(-8px);
    transform: scale(1.02);   /* THIS OVERRIDES THE FIRST! */
}

The second transform completely replaces the first — only scale will apply. Always put all transforms in one transform separated by spaces:

.card:hover {
    transform: translateY(-8px) scale(1.02);  /* CORRECT */
}

Правило 3 анимаций на страницу. Не анимируйте ВСЁ — от этого устают глаза и замедляется браузер. Хорошее правило: максимум 3 типа hover-анимаций на одной странице. Например: карточки поднимаются, кнопки увеличиваются, ссылки подчёркиваются. Всё. Больше — мешанина.

Rule of 3 animations per page. Don't animate EVERYTHING — it tires the eyes and slows down the browser. Good rule: max 3 types of hover animations per page. For example: cards lift, buttons grow, links underline. That's it. More = a mess.

prefers-reduced-motion — доступность. Некоторые пользователи (с вестибулярными расстройствами, эпилепсией) отключают анимации в настройках ОС. Хорошая практика — уважать это:

@media (prefers-reduced-motion: reduce) {
    * {
        animation-duration: 0.01ms !important;
        transition-duration: 0.01ms !important;
    }
}

Этот код мгновенно отключает все анимации для таких пользователей. В коммерческих проектах — обязательно.

prefers-reduced-motion — accessibility. Some users (with vestibular disorders, epilepsy) disable animations in OS settings. Good practice is to respect this:

@media (prefers-reduced-motion: reduce) {
    * {
        animation-duration: 0.01ms !important;
        transition-duration: 0.01ms !important;
    }
}

This code instantly disables all animations for such users. In commercial projects — mandatory.
