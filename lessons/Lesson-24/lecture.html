В 22-м уроке мы научились делать transition — плавные переходы между двумя состояниями (например, hover). Но что если нужно сделать бесконечно вращающийся спиннер загрузки? Key difference: transition only runs on events (hover, focus), while animation runs automatically on page load, and can loop forever. Two different tools for two different jobs.

1. transition vs animation

1. transition vs animation

Перед тем как нырять в @keyframes, давайте чётко поймём: когда применять transition, а когда — animation. Новички часто путают, используют transition там, где нужна animation, и наоборот. Это важный выбор инструмента.

Before diving into @keyframes, let's clearly understand: when to use transition, and when — animation. Beginners often confuse them, using transition where animation is needed and vice versa. It's an important tool choice.

transitionanimation
ЗапускНужен триггер (:hover, :focus)Запускается сама (при загрузке)
СостоянияИз A в B (2 состояния)Любое количество шагов (@keyframes)
ПовторНетМожно повторять бесконечно
СложностьПростые hover-эффектыСложные многошаговые анимации
transitionanimation
TriggerNeeds trigger (:hover, :focus)Runs automatically (on load)
StatesFrom A to B (2 states)Any number of steps (@keyframes)
RepeatNoCan repeat infinitely

Правило: hover-эффекты → transition. Автоматические анимации (загрузчики, появление, пульсация) → animation.
Rule: hover effects → transition. Automatic animations (loaders, appearance, pulse) → animation.

Дверь и часы. transition — как дверь: она движется, только когда кто-то её толкает (hover). animation — как часы: стрелки двигаются сами, непрерывно. Для спиннера нужны «часы», а не «дверь».

Door and clock. transition is like a door: it moves only when someone pushes it (hover). animation is like a clock: hands move by themselves, continuously. For a spinner you need a "clock", not a "door".

2. @keyframes — определение анимации

2. @keyframes — defining animation

@keyframes — это сценарий анимации. Представьте мультфильм: есть ключевые кадры (в начале герой стоит, посередине бежит, в конце прыгает), а браузер сам рисует промежуточные. @keyframes — это и есть ключевые кадры.

Процесс из двух шагов: сначала описываем анимацию (@keyframes fadeIn {...}), потом применяем её к элементу (animation: fadeIn 1s). Разделение важно: одну анимацию можно применить ко многим элементам.

@keyframes is the animation script. Picture a cartoon: there are key frames (hero stands, then runs, then jumps), and the browser draws what's in between. @keyframes are those key frames.

Two-step process: first describe the animation (@keyframes fadeIn {...}), then apply it to an element (animation: fadeIn 1s). Separation matters: one animation can be applied to many elements.

/* Шаг 1: определяем анимацию */
@keyframes fadeIn {
    from {
        opacity: 0;
    }
    to {
        opacity: 1;
    }
}

/* Шаг 2: применяем к элементу */
.hero-title {
    animation: fadeIn 1s ease;
}

from = начальное состояние (0%). to = конечное (100%). Можно задать промежуточные шаги:

from = initial state (0%). to = final (100%). You can add intermediate steps:

@keyframes bounce {
    0%   { transform: translateY(0); }
    50%  { transform: translateY(-20px); }
    100% { transform: translateY(0); }
}

Мультипликация кадр за кадром. До 1990-х мультики рисовали так: художник рисовал ключевые кадры (1-й, 12-й, 24-й), а «inbetweeners» дорисовывали промежуточные. Браузер работает так же: вы пишете 0%, 50%, 100%, а он сам рисует все кадры между ними (60 в секунду).

Frame-by-frame animation. Pre-1990s cartoons were drawn this way: the artist drew key frames (1st, 12th, 24th), and "inbetweeners" filled in the rest. The browser works the same: you write 0%, 50%, 100%, it draws all frames between them (60 per second).

from/to vs 0%/100%. Это одно и то же. from = 0%, to = 100%. Используйте from/to, когда шагов два (простая анимация). Когда шагов больше — переходите на проценты.

from/to vs 0%/100%. These are the same thing. from = 0%, to = 100%. Use from/to for two-step animations. Switch to percentages when you need more steps.

3. Свойства animation

3. animation properties

У animation 7 параметров — больше, чем у transition. Звучит страшно, но на практике запоминать все не нужно. 90% времени вы пишете короткую форму: animation: name duration timing. Остальное добавляется по ситуации.

animation has 7 parameters — more than transition. Sounds scary, but in practice you don't need to memorize all. 90% of the time you write the short form: animation: name duration timing. The rest is added as needed.

animation: name duration timing-function delay iteration-count direction fill-mode;

/* Пример: */
animation: fadeIn 1s ease 0s 1 normal forwards;

/* Сокращённо (чаще всего): */
animation: fadeIn 1s ease;
animation: spin 1s linear infinite;

animation-timing-functionКриваяease, linear, ease-in-out
animation-delayЗадержка0s, 0.3s, 1s
animation-iteration-countСколько раз1, 3, infinite
animation-directionНаправлениеnormal, reverse, alternate
animation-fill-modeСостояние послеforwards, backwards, both
PropertyWhat it doesExamples
animation-name@keyframes namefadeIn, slideUp
animation-durationDuration1s, 0.5s, 2s
animation-timing-functionEasingease, linear, ease-in-out

Стандартный набор для 90% случаев:

/* Одноразовая (появление): */
animation: fadeIn 0.6s ease forwards;

/* Бесконечная (спиннер): */
animation: spin 1s linear infinite;

/* Бесконечная туда-обратно (пульс): */
animation: pulse 2s ease-in-out infinite alternate;

Три варианта покрывают почти всё. Запомните их.

Standard set for 90% of cases:

/* One-shot (appearance): */
animation: fadeIn 0.6s ease forwards;

/* Infinite (spinner): */
animation: spin 1s linear infinite;

/* Infinite back-and-forth (pulse): */
animation: pulse 2s ease-in-out infinite alternate;

Three variants cover almost everything. Memorize them.

4. animation-iteration-count и direction

4. animation-iteration-count and direction

По умолчанию анимация выполняется один раз и останавливается. Но 80% декоративных анимаций — бесконечные: спиннер крутится всегда, уведомление пульсирует всегда. Для этого два ключевых слова: infinite (бесконечно) и alternate (туда-обратно).

By default an animation runs once and stops. But 80% of decorative animations are infinite: spinners spin forever, notifications pulse forever. Two key words for this: infinite (forever) and alternate (back and forth).

/* Бесконечный цикл */
animation: spin 1s linear infinite;

/* Туда-обратно (пульсация) */
animation: pulse 2s ease-in-out infinite alternate;

/* 3 раза и стоп */
animation: bounce 0.5s ease 3;

alternate — анимация идёт вперёд, потом назад, потом вперёд... Идеально для пульсации!

alternate — animation goes forward, then backward, then forward... Perfect for pulsing!

normal (1,2,3)→(1,2,3)→(1,2,3) каждый раз перепрыг reverse (3,2,1)→(3,2,1)→(3,2,1) задом наперёд alternate (1,2,3)→(3,2,1)→(1,2,3) плавно туда-обратно ← лучший для пульса alternate-reverse (3,2,1)→(1,2,3)→...
normal (1,2,3)→(1,2,3)→(1,2,3) snap back each time reverse (3,2,1)→(3,2,1)→(3,2,1) backwards alternate (1,2,3)→(3,2,1)→(1,2,3) smooth back-and-forth ← best for pulse alternate-reverse (3,2,1)→(1,2,3)→...

Без alternate пульс выглядит сломанным. Если написать animation: pulse 2s ease infinite с анимацией from scale(1) to scale(1.1) — в конце каждого цикла элемент резко возвращается в scale(1) и начинает расти заново. Вместо плавного пульса получаются «прыжки». Решение: либо добавить alternate, либо описать анимацию симметрично через 0%/50%/100%.

Without alternate pulse looks broken. If you write animation: pulse 2s ease infinite with from scale(1) to scale(1.1) — at the end of each cycle the element snaps back to scale(1) and grows again. Instead of smooth pulse, you get "jumps". Fix: either add alternate, or describe the animation symmetrically via 0%/50%/100%.

5. animation-fill-mode

5. animation-fill-mode

Представьте: вы написали fadeIn с opacity: 0 → 1. Элемент плавно появляется, отлично. Но через 1 секунду после окончания анимации он моргает обратно в opacity: 0! Почему? Потому что по умолчанию браузер возвращает элемент в исходное (до-анимационное) состояние. Это и решает animation-fill-mode.

Imagine: you wrote fadeIn with opacity: 0 → 1. Element smoothly appears, great. But a second after the animation ends — it flashes back to opacity: 0! Why? By default the browser returns the element to its pre-animation state. animation-fill-mode solves this.

ЗначениеЧто происходит после анимации
noneЭлемент возвращается к исходному состоянию (по умолчанию)
forwardsЭлемент остаётся в конечном состоянии
backwardsЭлемент принимает начальное состояние до старта (при delay)
bothforwards + backwards
ValueWhat happens after animation
noneElement returns to original state (default)
forwardsElement stays in final state
backwardsElement takes initial state before start (with delay)
bothforwards + backwards
forwards — самый важный! Без него элемент «мигает» обратно после fadeIn. Всегда добавляйте forwards для анимаций появления.
forwards — the most important! Without it, the element "flashes" back after fadeIn. Always add forwards for appearance animations.

6. Примеры: загрузчики (spinners)

6. Examples: loaders (spinners)

Загрузчик (spinner) — это элемент, который сообщает пользователю «что-то происходит, подожди». Без него пользователь думает, что сайт сломался. По исследованиям, 40% пользователей закрывают вкладку, если она не реагирует 3 секунды без визуальной обратной связи. Спиннер покупает вам эти секунды.

Технически спиннер — просто элемент с animation: spin infinite. Это самая популярная CSS-анимация на планете.

A loader (spinner) tells the user "something's happening, wait". Without one, the user thinks the site broke. Research shows 40% of users close a tab if it doesn't react for 3 seconds without visual feedback. The spinner buys you those seconds.

Technically a spinner is just an element with animation: spin infinite. The most popular CSS animation on the planet.

/* Вращающийся спиннер */
@keyframes spin {
    from { transform: rotate(0deg); }
    to   { transform: rotate(360deg); }
}

.spinner {
    width: 40px;
    height: 40px;
    border: 4px solid #e2e8f0;
    border-top: 4px solid #3b82f6;
    border-radius: 50%;
    animation: spin 0.8s linear infinite;
}

/* Три пульсирующие точки */
@keyframes dotPulse {
    0%, 80%, 100% { transform: scale(0); }
    40% { transform: scale(1); }
}

.dot {
    width: 12px; height: 12px;
    background: #3b82f6;
    border-radius: 50%;
    animation: dotPulse 1.4s ease-in-out infinite;
}
.dot:nth-child(2) { animation-delay: 0.16s; }
.dot:nth-child(3) { animation-delay: 0.32s; }

Как работает спиннер технически. Это круг с прозрачными границами, только одна (border-top) — цветная. Когда круг вращается, видна только эта цветная линия — создаётся иллюзия движения. Четыре строчки CSS — и готов элемент, который увидят миллионы пользователей.

How the spinner works technically. It's a circle with transparent borders — only one (border-top) is colored. As the circle rotates, only that colored line is visible — creating the illusion of movement. Four lines of CSS — and you have an element seen by millions of users.

linear, не ease. Для спиннера используйте linear (равномерная скорость). С ease спиннер будет ускоряться и замедляться на каждом обороте — выглядит сломанным. Для вращения по кругу ТОЛЬКО linear.

linear, not ease. For spinners use linear (constant speed). With ease the spinner speeds up and slows down each rotation — looks broken. For circular motion use ONLY linear.

7. Появление элементов (fade-in)

7. Element appearance (fade-in)

Когда страница открывается — все элементы появляются мгновенно. Это функционально, но неинтересно. Профессиональные промо-сайты делают постепенное появление: сначала заголовок плавно выезжает, через 0.2 секунды — подзаголовок, ещё через 0.2 — кнопка. Это называется каскадный fade-in.

Эффект прост по механике (opacity 0→1 + translateY), но сильно повышает восприятие качества. Так делают Apple, Stripe, все лендинги на Product Hunt.

When a page opens — all elements appear instantly. Functional, but boring. Professional promo sites use staggered appearance: heading fades in first, 0.2s later — subheading, another 0.2s — button. This is called a cascading fade-in.

Simple mechanically (opacity 0→1 + translateY), but dramatically boosts perceived quality. Used by Apple, Stripe, every landing on Product Hunt.

@keyframes fadeIn {
    from { opacity: 0; }
    to   { opacity: 1; }
}

@keyframes fadeInUp {
    from {
        opacity: 0;
        transform: translateY(30px);
    }
    to {
        opacity: 1;
        transform: translateY(0);
    }
}

.hero h1 {
    animation: fadeInUp 0.8s ease forwards;
}
.hero p {
    animation: fadeInUp 0.8s ease 0.2s forwards;
    opacity: 0; /* начальное состояние до анимации */
}
.hero .btn {
    animation: fadeInUp 0.8s ease 0.4s forwards;
    opacity: 0;
}
Каскадная задержка: h1 = 0s, p = 0.2s, button = 0.4s. Элементы появляются друг за другом — красивый эффект!
Cascading delay: h1 = 0s, p = 0.2s, button = 0.4s. Elements appear one after another — beautiful effect!

Почему opacity: 0 в базовом состоянии? Если не указать opacity: 0, то во время animation-delay: 0.4s пользователь будет видеть элемент во всей красе первые 0.4 секунды — и только потом он «исчезнет и появится». Мигание! Решение: в базовом CSS элемента ставьте opacity: 0, чтобы до анимации он был невидимым. forwards + базовое opacity: 0 — обязательная пара.

Why opacity: 0 in base state? Without opacity: 0, during animation-delay: 0.4s the user would see the element fully visible for 0.4s — and only then it "disappears and reappears". A flash! Fix: set opacity: 0 in the element's base CSS so it's invisible before the animation. forwards + base opacity: 0 — a mandatory pair.

8. Выезжающие элементы (slide-in)

8. Sliding elements (slide-in)

Slide-in — вариант fade-in, но с движением сбоку: элемент «выезжает» слева или справа. Используется в секциях Features, где три блока: первый выезжает слева, второй поднимается снизу, третий — справа. Создаёт визуальный ритм.

Slide-in is a variant of fade-in but with side movement: the element "slides in" from left or right. Used in Features sections where three blocks: first slides from left, second rises from below, third — from right. Creates visual rhythm.

@keyframes slideInLeft {
    from { opacity: 0; transform: translateX(-60px); }
    to   { opacity: 1; transform: translateX(0); }
}

@keyframes slideInRight {
    from { opacity: 0; transform: translateX(60px); }
    to   { opacity: 1; transform: translateX(0); }
}

.feature:nth-child(1) { animation: slideInLeft 0.6s ease 0.1s forwards; opacity: 0; }
.feature:nth-child(2) { animation: fadeInUp 0.6s ease 0.2s forwards; opacity: 0; }
.feature:nth-child(3) { animation: slideInRight 0.6s ease 0.3s forwards; opacity: 0; }

9. Пульсирующие элементы

9. Pulsing elements

Пульс — это «визуальное сердцебиение». Используется для привлечения внимания: пульсирующая кнопка CTA, красная точка уведомления, индикатор «live» на стриминге. Глаз человека биологически реагирует на пульсацию — это древний механизм отслеживания движения.

Pulse is a "visual heartbeat". Used to grab attention: pulsing CTA button, red notification dot, "live" indicator on streams. The human eye biologically reacts to pulsing — an ancient motion-tracking mechanism.

@keyframes pulse {
    0%   { transform: scale(1); }
    50%  { transform: scale(1.05); }
    100% { transform: scale(1); }
}

.cta-btn {
    animation: pulse 2s ease-in-out infinite;
}

/* Пульсирующая тень (привлечение внимания) */
@keyframes glowPulse {
    0%   { box-shadow: 0 0 0 0 rgba(59, 130, 246, 0.5); }
    70%  { box-shadow: 0 0 0 15px rgba(59, 130, 246, 0); }
    100% { box-shadow: 0 0 0 0 rgba(59, 130, 246, 0); }
}

.notification-dot {
    animation: glowPulse 2s ease infinite;
}

Не переусердствуйте с пульсом. Одна пульсирующая кнопка на странице — хорошо. Пять — спам. Пульс как восклицательный знак: одно на предложение.

Don't overdo pulse. One pulsing button on a page — good. Five — spam. Pulse is like an exclamation mark: one per sentence.

10. CSS-переменные для анимаций

10. CSS variables for animations

Когда на странице 5-10 анимированных элементов с каскадными задержками — писать delay: 0.1s, 0.2s, 0.3s... вручную утомительно. А если клиент попросит замедлить всё вдвое — нужно менять 10 значений. Решение: CSS-переменные + calc(). Меняете одну переменную — анимация пересчитывается везде.

With 5-10 animated elements with cascading delays — writing delay: 0.1s, 0.2s, 0.3s... manually is tedious. And if the client asks to slow everything down by half — you'd change 10 values. Solution: CSS variables + calc(). Change one variable — animation recalculates everywhere.

:root {
    --anim-speed: 0.6s;
    --anim-ease: ease;
    --anim-delay-step: 0.15s;
}

.card:nth-child(1) { animation: fadeInUp var(--anim-speed) var(--anim-ease) calc(var(--anim-delay-step) * 1) forwards; }
.card:nth-child(2) { animation: fadeInUp var(--anim-speed) var(--anim-ease) calc(var(--anim-delay-step) * 2) forwards; }
.card:nth-child(3) { animation: fadeInUp var(--anim-speed) var(--anim-ease) calc(var(--anim-delay-step) * 3) forwards; }

calc() + CSS-переменные = автоматическая каскадная задержка! Каждая карточка появляется на 0.15s позже предыдущей.

calc() + CSS variables = automatic cascading delay! Each card appears 0.15s after the previous one.

Доступность: не забывайте про prefers-reduced-motion. Анимации появления могут вызывать проблемы у пользователей с вестибулярными расстройствами. Обязательно добавляйте в конец CSS:

@media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
    }
}

Это отключает анимации для пользователей, которые поставили соответствующий флаг в ОС.

Accessibility: don't forget prefers-reduced-motion. Appearance animations can cause issues for users with vestibular disorders. Always add at the end of your CSS:

@media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
    }
}

This disables animations for users who set the corresponding OS flag.
