1. Responsive-классы (sm, md, lg, xl)

1. Responsive classes (sm, md, lg, xl)

Адаптивность — без неё сайт бесполезен. Вспомните уроки 18-20: мы писали @media (min-width: 768px) { ... } вручную, отдельно для каждого свойства. Это было многословно.

В Tailwind адаптив — это префикс перед классом. text-xl = размер на мобильном. md:text-3xl = «на ≥ 768px — size 3xl». Один класс, одна строка. То же самое media queries, но в 10 раз короче.

Responsiveness — without it a site is useless. Remember lessons 18-20: we wrote @media (min-width: 768px) { ... } by hand, separately for each property. It was verbose.

In Tailwind, responsiveness is a prefix before a class. text-xl = size on mobile. md:text-3xl = "on ≥ 768px — size 3xl". One class, one line. Same media queries, but 10× shorter.

Tailwind использует mobile-first. Базовые классы = мобильный. Префиксы добавляют стили для бо́льших экранов:

Tailwind uses mobile-first. Base classes = mobile. Prefixes add styles for larger screens:

Наследование одежды. Mobile-first — это как старшая одежда в семье: сначала её носит мобильный (базовая), потом планшет (наследует мобильное + свои особенности), потом десктоп (наследует планшетное + свои). На каждом размере добавляете только то, что меняется. Если на md и lg выглядит одинаково — пишите только md:, lg автоматически наследует.

Family hand-me-downs. Mobile-first is like clothes passed down in a family: first the mobile wears it (base), then tablet (inherits mobile + its own additions), then desktop (inherits tablet + its own). At each size, you add only what changes. If it looks the same on md and lg — write only md:, lg inherits automatically.

2. Примеры адаптивности

2. Responsiveness examples

Теория ясна — давайте посмотрим на реальные паттерны, которые вы будете использовать постоянно. Эти 5 шаблонов покрывают 90% задач адаптива: плавный текст, плавные отступы, flex-направление, скрытие элементов, сетка колонок.

Theory is clear — let's see real patterns you'll use all the time. These 5 templates cover 90% of responsive tasks: fluid text, fluid spacing, flex direction, hiding elements, column grid.

<!-- Адаптивный текст -->
<h1 class="text-2xl md:text-4xl lg:text-5xl font-bold">
    Responsive Heading
</h1>

<!-- Адаптивные отступы -->
<div class="p-4 md:p-8 lg:p-12">...</div>

<!-- Flex → column на мобильном -->
<div class="flex flex-col md:flex-row gap-6">
    <div class="md:w-1/3">Sidebar</div>
    <div class="md:w-2/3">Content</div>
</div>

<!-- Скрыть на мобильном -->
<div class="hidden md:block">Только на десктопе</div>
<div class="block md:hidden">Только на мобильном</div>

<!-- Адаптивная сетка -->
<div class="grid grid-cols-2 md:grid-cols-3 lg:grid-cols-4 gap-4">
    ...
</div>

Два скрытия — вы запутаетесь, если не вызубрите:

  • hidden md:block = скрыт на мобильном, виден с md. Для desktop-only контента: декор, sidebar, длинные описания.
  • block md:hidden = виден на мобильном, скрыт с md. Для mobile-only: бургер-иконка, упрощённое меню.

Читайте буквально: hidden — скрыт, md:block — на md и выше показать.

Two hides — you'll get confused if you don't memorize:

  • hidden md:block = hidden on mobile, visible from md. For desktop-only content: decor, sidebar, long descriptions.
  • block md:hidden = visible on mobile, hidden from md. For mobile-only: burger icon, simplified menu.

Read literally: hidden — hidden, md:block — from md and up show.

Типовой паттерн «text + image»: на мобильном — стопка (текст сверху, картинка снизу), на десктопе — два столбца.

<div class="flex flex-col md:flex-row gap-8">
    <div class="md:w-1/2"><!-- Текст --></div>
    <div class="md:w-1/2"><!-- Картинка --></div>
</div>

Это половина hero-секций в интернете.

Typical "text + image" pattern: on mobile — stack (text above, image below), on desktop — two columns.

<div class="flex flex-col md:flex-row gap-8">
    <div class="md:w-1/2"><!-- Text --></div>

3. hover, focus, active

3. hover, focus, active

Интерактивность — это что отличает современный сайт от статичного документа. В Tailwind она встроена: любой класс можно «обвязать» состоянием через префикс. hover: — когда курсор на элементе. focus: — когда элемент в фокусе (важно для форм и доступности). active: — когда кнопка нажата (тактильный фидбэк).

Interactivity is what separates a modern site from a static document. In Tailwind it's built-in: any class can be "wrapped" in a state via prefix. hover: — when cursor is on element. focus: — when element is focused (critical for forms and accessibility). active: — when button is pressed (tactile feedback).

<!-- Hover -->
<button class="bg-blue-600 hover:bg-blue-700 text-white px-6 py-3 rounded-lg">
    Hover Me
</button>

<!-- Hover на карточке -->
<div class="bg-white rounded-xl shadow-md hover:shadow-xl
            hover:-translate-y-2 transition-all duration-300">
    ...
</div>

<!-- Focus (для input) -->
<input class="border border-gray-300 rounded-lg px-4 py-2
              focus:border-blue-500 focus:ring-2 focus:ring-blue-200
              focus:outline-none transition-all">

<!-- Active (при нажатии) -->
<button class="bg-blue-600 hover:bg-blue-700 active:scale-95
               transition-all">
    Click Me
</button>
Формат: hover:{класс}, focus:{класс}, active:{класс}. Работает с любым утилити-классом!
Format: hover:{class}, focus:{class}, active:{class}. Works with any utility class!

Не забывайте про focus:. Новички добавляют только hover:, но забывают про фокус. Результат: человек с клавиатуры (Tab для навигации) не видит, где он находится. Это провал по доступности. Правило: везде, где есть hover: — должен быть focus: с похожим стилем. Для инпутов обязательно focus:ring-2 focus:ring-blue-500.

Don't forget focus:. Beginners add only hover:, forgetting focus. Result: keyboard users (Tab navigation) can't see where they are. Accessibility fail. Rule: wherever there's hover: — add focus: with similar style. For inputs, always include focus:ring-2 focus:ring-blue-500.

Можно комбинировать префиксы! md:hover:text-blue-500 = «на md и выше, при hover — синий текст». dark:hover:bg-gray-800 = «в тёмной теме при hover — тёмный фон». Порядок важен: сначала responsive, потом состояние.

You can combine prefixes! md:hover:text-blue-500 = "on md and up, on hover — blue text". dark:hover:bg-gray-800 = "in dark theme on hover — dark bg". Order matters: responsive first, then state.

4. Transitions в Tailwind

4. Transitions in Tailwind

Без transition hover-эффект работает резко: цвет меняется мгновенно. Это «дёшево» выглядит. Добавили transition-colors duration-300 — плавно за 0.3 секунды. Это не мелочь, это разница между любительским и профессиональным сайтом.

Without transition, hover effects work abruptly: color changes instantly. Looks "cheap". Add transition-colors duration-300 — smooth over 0.3s. Not a detail — it's the difference between amateur and professional sites.

<!-- Transition на все свойства -->
<div class="transition-all duration-300 ease-in-out">...</div>

<!-- Только transform -->
<div class="transition-transform duration-300">...</div>

<!-- Только цвета -->
<div class="transition-colors duration-200">...</div>

Правило трёх:

<!-- Кнопки (простой hover) -->
class="transition-colors duration-200"

<!-- Карточки (трансформации) -->
class="transition-all duration-300"

<!-- Модалки, большие анимации -->

Rule of three:

<!-- Buttons (simple hover) -->
class="transition-colors duration-200"

<!-- Cards (transforms) -->
class="transition-all duration-300"

<!-- Modals, large animations -->
class="transition-all duration-500 ease-out"

Memorize these three — covers 95% of cases.

5. Градиенты

5. Gradients

Градиент — плавный переход между двумя/тремя цветами. Самый быстрый способ сделать сайт современным. Hero-секция с градиентом вместо обычного синего — разница драматическая. В 2025 году градиенты — тренд дизайна: Stripe, Linear, Vercel, Apple — все используют.

Tailwind даёт градиенты тремя классами: направление (bg-gradient-to-r) + стартовый цвет (from-blue-600) + конечный (to-purple-600). Можно добавить средний через via-.

A gradient — smooth transition between two/three colors. Fastest way to make a site look modern. Hero section with a gradient instead of plain blue — dramatic difference. In 2025, gradients are a design trend: Stripe, Linear, Vercel, Apple — all use them.

Tailwind gives gradients via three classes: direction (bg-gradient-to-r) + start color (from-blue-600) + end (to-purple-600). Add a middle via via-.

<!-- Градиент фона -->
<div class="bg-gradient-to-r from-blue-600 to-purple-600 text-white p-12">
    Gradient Section
</div>

<!-- Направления: -->
bg-gradient-to-r    /* слева → направо */
bg-gradient-to-l    /* справа → налево */
bg-gradient-to-t    /* снизу → вверх */
bg-gradient-to-b    /* сверху → вниз */
bg-gradient-to-br   /* в правый нижний угол */

<!-- 3 цвета -->
<div class="bg-gradient-to-r from-green-400 via-blue-500 to-purple-600">
    Three-color gradient
</div>

Живые примеры градиентов:

Live gradient examples:

from-blue-600 → to-purple-600
from-green-400 → via-blue-500 → to-purple-600
from-orange-500 → to-pink-500 (to-br)
from-slate-800 → to-slate-600

Рецепт красивого градиента: берите соседние или близкие цвета по hue (оттенку) — синий + фиолетовый, оранжевый + розовый, зелёный + синий. Очень яркие контрасты (красный + зелёный) выглядят аляповато. И используйте оттенки 500-700: слишком светлые или слишком тёмные теряют эффект.

Recipe for a pretty gradient: take adjacent or close colors by hue — blue + purple, orange + pink, green + blue. Very high contrast (red + green) looks gaudy. And use shades 500-700: too light or too dark loses the effect.

6. Dark mode

6. Dark mode

Dark mode — стандарт индустрии в 2025. Пользователи ждут переключателя темы. В обычном CSS для этого нужно написать два комплекта стилей: .card и .card.dark, или через CSS-переменные. В Tailwind — префикс dark:. Любой класс можно «раздвоить» для тёмной темы: bg-white dark:bg-gray-900. Пишете в одном месте, работает в двух режимах.

Dark mode is an industry standard in 2025. Users expect a theme toggle. In plain CSS this requires two sets of styles: .card and .card.dark, or via CSS variables. In Tailwind — dark: prefix. Any class can be "doubled" for dark: bg-white dark:bg-gray-900. Written in one place, works in two modes.

<!-- Тёмная тема через dark: префикс -->
<div class="bg-white dark:bg-gray-900 text-gray-800 dark:text-gray-100">
    <h1 class="text-gray-900 dark:text-white">Title</h1>
    <p class="text-gray-600 dark:text-gray-400">Text</p>
    <div class="bg-gray-100 dark:bg-gray-800 rounded-lg p-4">
        Card
    </div>
</div>

dark: классы активируются, когда у <html> есть class="dark" или системная тема тёмная.

dark: classes activate when <html> has class="dark" or the system theme is dark.

В Tailwind CDN можно включить dark mode через class стратегию: добавьте class="dark" на <html> — и все dark: стили активируются!

In Tailwind CDN you can enable dark mode via class strategy: add class="dark" to <html> — and all dark: styles activate!

Палитра для dark mode: вместо чистого чёрного (bg-black) используйте bg-gray-900 (#111827) или bg-slate-900. Чистый чёрный создаёт «выжженное» ощущение глаз. Для текста — text-gray-100, не text-white (слишком яркий на тёмном). Для карточек в тёмной теме — bg-gray-800, чуть светлее основного фона.

Palette for dark mode: instead of pure black (bg-black), use bg-gray-900 (#111827) or bg-slate-900. Pure black causes "eye burn". For text — text-gray-100, not text-white (too bright on dark). For cards in dark theme — bg-gray-800, slightly lighter than main bg.

Включите dark mode на своём сайте с Tailwind CDN: в <html> или <body> добавьте class="dark" и посмотрите, как все ваши dark: стили сразу активируются. Уберите — вернётся светлая тема. Это и есть переключатель (только без JS).

Turn on dark mode on your Tailwind CDN site: add class="dark" to <html> or <body> and watch all your dark: styles activate. Remove it — light theme returns. That's the toggle (minus the JS).

7. group-hover

7. group-hover

Классика UX: наводишь на карточку — картинка зумится И заголовок меняет цвет И кнопка меняется. То есть один hover на родителе триггерит анимации у нескольких детей. В CSS это .card:hover .image { ... } .card:hover h3 { ... }. В Tailwind — два ключевых слова: group (на родителе) и group-hover: (на детях).

UX classic: hover a card — image zooms AND title changes color AND button shifts. One hover on parent triggers animations on multiple children. In CSS that's .card:hover .image { ... } .card:hover h3 { ... }. In Tailwind — two keywords: group (on parent) and group-hover: (on children).

group-hover позволяет менять стили дочернего элемента при hover на родителе:

group-hover lets you change child element styles when hovering over the parent:

<div class="group bg-white rounded-xl shadow-md overflow-hidden
            hover:shadow-xl transition-all duration-300">
    <img src="..." class="w-full h-48 object-cover
                          group-hover:scale-110 transition-transform duration-500">
    <div class="p-5">
        <h3 class="font-bold group-hover:text-blue-600 transition-colors">Title</h3>
    </div>
</div>
Как работает: group на родителе, group-hover:{класс} на детях. При hover на карточку — картинка зумится И заголовок меняет цвет!
How it works: group on parent, group-hover:{class} on children. On card hover — image zooms AND title changes color!

Частая ошибка: забыли group на родителе. group-hover:scale-110 на картинке без group на карточке = ничего не работает. Если анимация не срабатывает — первым делом проверьте, стоит ли слово group на родителе.

Common mistake: forgot group on parent. group-hover:scale-110 on image without group on card = nothing happens. If animation doesn't fire — first check that group word is on the parent.
