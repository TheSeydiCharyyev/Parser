Занятие 5: Списки и семантика

Маркированные, нумерованные и описательные списки. Семантическая разметка страницы

Списки и семантические теги — это основа структуры любой веб-страницы. Без списков невозможно создать навигацию, меню, рейтинги. Без семантики — поисковики и скринридеры не понимают вашу страницу.

Представьте книгу без оглавления, без глав, без нумерации страниц. Найти нужную информацию практически невозможно. Семантика и списки — это «оглавление» и «нумерация» вашего сайта.

После этого занятия вы сможете:

  • Создавать маркированные, нумерованные и описательные списки
  • Вкладывать списки друг в друга (многоуровневые меню)
  • Строить страницу из семантических тегов (header, nav, main, footer)
  • Понимать, почему семантика важна для SEO и доступности

1. Маркированные списки <ul>

Маркированный список (unordered list) — список, в котором порядок пунктов не важен. Каждый пункт отмечается маркером (точкой).

<ul>
    <li>Молоко</li>
    <li>Хлеб</li>
    <li>Яйца</li>
    <li>Сыр</li>
</ul>
  • Молоко
  • Хлеб
  • Яйца
  • Сыр
  • <ul> — контейнер списка (unordered list)
  • <li> — элемент списка (list item)
Внутри <ul> могут быть только теги <li>. Нельзя напрямую вставлять <p>, <div> или текст — только <li>. А вот внутри <li> можно размещать что угодно: текст, ссылки, картинки, другие списки.

Маркированный список — это как список покупок на холодильнике: порядок не важен, главное — не забыть ни один пункт. Купите молоко первым или последним — результат одинаковый.

Когда использовать: список покупок, меню навигации, перечисление навыков, любой набор элементов, где порядок не имеет значения.

2. Нумерованные списки <ol>

Нумерованный список (ordered list) — список, в котором порядок важен. Пункты автоматически нумеруются.

<ol>
    <li>Включить духовку на 180°C</li>
    <li>Смешать муку и сахар</li>
    <li>Добавить яйца и молоко</li>
    <li>Вылить тесто в форму</li>
    <li>Выпекать 30 минут</li>
</ol>
  1. Включить духовку на 180°C
  2. Смешать муку и сахар
  3. Добавить яйца и молоко
  4. Вылить тесто в форму
  5. Выпекать 30 минут

Атрибуты <ol>

АтрибутЧто делаетПример
typeТип нумерации"1" (цифры), "A" (буквы), "a" (маленькие буквы), "I" (римские), "i"
startНачальное числоstart="5" — начнёт с 5
reversedОбратный порядок10, 9, 8, 7...
<!-- Буквенная нумерация -->
<ol type="A">
    <li>Первый пункт</li>
    <li>Второй пункт</li>
</ol>

<!-- Нумерация с 5 -->
<ol start="5">
    <li>Пятый пункт</li>
    <li>Шестой пункт</li>
</ol>

<!-- Обратный отсчёт -->
<h2>ТОП-3 фильмов</h2>
<ol reversed>
    <li>Интерстеллар</li>
    <li>Начало</li>
    <li>Матрица</li>
</ol>

Когда использовать: рецепты, инструкции, рейтинги, любые последовательности, где порядок имеет значение.

ul vs ol:

  • <ul> = список покупок (купить молоко, хлеб, сыр — порядок не важен)
  • <ol> = рецепт торта (сначала разогреть духовку, потом смешать, потом выпечь — порядок важен!)

На сайтах интернет-магазинов нумерованные списки часто используются для шагов оформления заказа: 1. Корзина, 2. Доставка, 3. Оплата, 4. Подтверждение. Порядок критически важен!

3. Вложенные списки

Списки можно вкладывать друг в друга — создавая многоуровневую структуру. Вложенный список размещается внутри тега <li>:

<ul>
    <li>Фрукты
        <ul>
            <li>Яблоки</li>
            <li>Бананы</li>
            <li>Апельсины</li>
        </ul>
    </li>
    <li>Овощи
        <ul>
            <li>Морковь</li>
            <li>Картофель</li>
        </ul>
    </li>
    <li>Молочные продукты</li>
</ul>
  • Фрукты
    • Яблоки
    • Бананы
    • Апельсины
  • Овощи
    • Морковь
    • Картофель
  • Молочные продукты

Обратите внимание: браузер автоматически меняет тип маркера для каждого уровня вложенности (●, ○, ■).

Можно комбинировать <ul> и <ol>:

<ol>
    <li>Подготовка
        <ul>
            <li>Помыть овощи</li>
            <li>Нарезать кубиками</li>
        </ul>
    </li>
    <li>Приготовление
        <ul>
            <li>Обжарить лук</li>
            <li>Добавить овощи</li>
        </ul>
    </li>
</ol>

Вложенный список нужно размещать внутри <li>, а не после него!

❌ Неправильно:
<ul>
  <li>Пункт 1</li>
  <ul>
    <li>Подпункт</li>
  </ul>
</ul>
✅ Правильно:
<ul>
  <li>Пункт 1
    <ul>
      <li>Подпункт</li>
    </ul>
  </li>
</ul>
Совет: Вложенные списки часто используются для меню навигации сайтов — основные разделы с подразделами.

4. Описательные списки <dl>

Описательный список (definition list) используется для пар «термин — определение». Он состоит из трёх тегов:

  • <dl> — контейнер списка (definition list)
  • <dt> — термин (definition term)
  • <dd> — определение (definition description)
<dl>
    <dt>HTML</dt>
    <dd>Язык гипертекстовой разметки для создания веб-страниц.</dd>

    <dt>CSS</dt>
    <dd>Каскадные таблицы стилей для оформления веб-страниц.</dd>

    <dt>JavaScript</dt>
    <dd>Язык программирования для создания интерактивных веб-страниц.</dd>
</dl>
HTML
Язык гипертекстовой разметки для создания веб-страниц.
CSS
Каскадные таблицы стилей для оформления веб-страниц.
JavaScript
Язык программирования для создания интерактивных веб-страниц.

Когда использовать: словарь терминов, FAQ (вопрос-ответ), характеристики товара, метаданные (автор, дата, категория).

<!-- FAQ -->
<h2>Частые вопросы</h2>
<dl>
    <dt>Сколько стоит доставка?</dt>
    <dd>Доставка бесплатна при заказе от 3000 руб.</dd>

    <dt>Как долго ждать?</dt>
    <dd>Доставка занимает 2-3 рабочих дня.</dd>
</dl>

<!-- Характеристики товара -->
<h2>Характеристики</h2>
<dl>
    <dt>Экран</dt>
    <dd>6.1 дюймов, OLED</dd>

    <dt>Аккумулятор</dt>
    <dd>4500 мА·ч</dd>

    <dt>Вес</dt>
    <dd>187 г</dd>
</dl>

На сайтах интернет-магазинов (ozon.ru, wildberries.ru) характеристики товаров часто реализованы именно через <dl>. Откройте DevTools на любом товаре и убедитесь сами!

5. Списки в реальной жизни

Списки — один из самых часто используемых элементов на сайтах. Вот реальные примеры:

ГдеТип спискаПример
Навигация<ul>Главная, О нас, Контакты
Меню ресторана<ul> + вложенныеСупы: борщ, солянка...
Рецепт<ol>1. Нарезать. 2. Обжарить...
ТОП-10<ol>Рейтинг фильмов
Словарь<dl>Термин — определение
FAQ<dl>Вопрос — ответ

Навигация почти каждого сайта в интернете — это <ul> внутри <nav>. Откройте DevTools на любом сайте и найдите <nav> — внутри почти наверняка будет <ul> с пунктами <li>, в которых лежат ссылки <a>. 
<!-- Типичная навигация сайта -->
<nav>
    <ul>
        <li><a href="index.html">Главная</a></li>
        <li><a href="catalog.html">Каталог</a></li>
        <li><a href="about.html">О нас</a></li>
        <li><a href="contacts.html">Контакты</a></li>
    </ul>
</nav>
  • <ul> — маркированный (порядок не важен): покупки, навыки, навигация
  • <ol> — нумерованный (порядок важен): рецепты, рейтинги, инструкции
  • <dl>/<dt>/<dd> — описательный: словари, FAQ, характеристики
  • Вложенные списки размещаются внутри <li>
  • Навигация = <nav> > <ul> > <li> > <a>

Какой тип списка выбрать?

  1. Список ингредиентов для пирога → <ul> (порядок не важен)
  2. Шаги приготовления пирога → <ol> (порядок важен!)
  3. Словарь кулинарных терминов → <dl> (термин + определение)
  4. Меню навигации сайта → <ul> внутри <nav>
  5. ТОП-10 лучших фильмов → <ol> (рейтинг, порядок важен)
  6. Характеристики телефона (экран, батарея, вес) → <dl>

6. Зачем нужна семантика

До HTML5 веб-разработчики строили страницы из <div> — универсального блока-контейнера. Проблема: <div> не несёт никакого смысла. Ни браузер, ни поисковик, ни скринридер не понимают, что внутри — шапка сайта, навигация или основной контент.

❌ Без семантики (до HTML5):
<div id="header">...</div>
<div id="nav">...</div>
<div id="main">...</div>
<div id="sidebar">...</div>
<div id="footer">...</div>

Все блоки одинаковые — <div>. Смысл понятен только по id.

✅ С семантикой (HTML5):
<header>...</header>
<nav>...</nav>
<main>...</main>
<aside>...</aside>
<footer>...</footer>

Каждый тег несёт смысл — даже без чтения содержимого.

Три причины использовать семантику

  1. SEO (поисковики) — Google лучше понимает структуру страницы и ранжирует выше.
  2. Доступность (accessibility) — скринридеры (программы для слабовидящих) используют семантику для навигации. Например, пользователь может сразу перейти к <main> или <nav>.
  3. Читаемость кода — разработчику проще понять структуру: <header> понятнее, чем <div class="header">.

Книга: <div> — это стопка неподписанных коробок. <header>, <nav>, <main> — это подписанные коробки: «Обложка», «Оглавление», «Содержание». Подписанные коробки легче найти и понять.

Представьте, что вы переехали и все вещи в одинаковых коробках без подписей. Найти тарелки? Книги? Одежду? Нужно открывать каждую! А если коробки подписаны — всё найдётся за секунды. Семантические теги — это подписи на коробках вашего кода.

8. header, footer и nav

<header> — шапка

Обычно содержит логотип, название сайта, навигацию. Может использоваться для шапки всей страницы или для шапки отдельной секции/статьи.

<header>
    <a href="index.html">
        <img src="images/logo.png" alt="Логотип" width="120">
    </a>
    <h1>Мой блог о путешествиях</h1>
</header>

<nav> — навигация

Блок с основными навигационными ссылками. На странице может быть несколько <nav> (основная навигация, навигация в подвале).

<nav>
    <ul>
        <li><a href="index.html">Главная</a></li>
        <li><a href="blog.html">Блог</a></li>
        <li><a href="gallery.html">Галерея</a></li>
        <li><a href="contacts.html">Контакты</a></li>
    </ul>
</nav>

<footer> — подвал

Подвал страницы: копирайт, контакты, социальные сети, дополнительные ссылки.

<footer>
    <p>&copy; 2026 Мой блог. Все права защищены.</p>
    <nav>
        <a href="privacy.html">Политика конфиденциальности</a> |
        <a href="terms.html">Условия использования</a>
    </nav>
</footer>
Символ &copy; — это HTML-сущность (entity). Она отображает знак копирайта ©. Есть и другие: &amp; — &, &lt; — <, &gt; — >, &nbsp; — неразрывный пробел.

Почти каждый современный сайт имеет структуру: <header> с логотипом сверху, <nav> с меню, основной контент, и <footer> с копирайтом внизу. Откройте любой крупный сайт (Google, YouTube, Wikipedia) и вы найдёте эти теги.

9. main, section и article

<main> — основной контент

Содержит уникальный контент страницы — то, что отличает эту страницу от других. Всё, что повторяется на каждой странице (шапка, навигация, подвал), не входит в <main>.

<main> должен быть один на странице. Не оборачивайте в него header, nav или footer.

<section> — тематический раздел

Группирует контент по теме. Обычно имеет свой заголовок.

<main>
    <section>
        <h2>О компании</h2>
        <p>Мы работаем с 2010 года...</p>
    </section>

    <section>
        <h2>Наши услуги</h2>
        <p>Мы предлагаем...</p>
    </section>
</main>

<article> — самостоятельный контент

Содержимое, которое имеет смысл отдельно от остальной страницы: статья, пост блога, комментарий, карточка товара.

Простой тест: Если вырезать этот блок и вставить на другую страницу — он будет понятен? Если да → <article>.

<article>
    <h2>Как выбрать ноутбук в 2026 году</h2>
    <p><small>Автор: Алексей | 10 марта 2026</small></p>
    <p>При выборе ноутбука обратите внимание на...</p>

    <section>
        <h3>Процессор</h3>
        <p>Для повседневных задач подойдёт...</p>
    </section>

    <section>
        <h3>Оперативная память</h3>
        <p>Минимум 8 ГБ, рекомендуется 16 ГБ...</p>
    </section>
</article>

Не путайте <section> и <article>:

  • <article> = может жить самостоятельно (пост блога, новость, карточка товара)
  • <section> = часть чего-то большего (раздел «О нас» на главной странице)

Подсказка: <article> часто содержит <section> внутри (разделы статьи).

10. aside, details и другие

<aside> — боковой контент

Содержимое, которое дополняет основной контент, но не является его частью: боковая панель, реклама, блок «Похожие статьи», биография автора.

<aside>
    <h3>Об авторе</h3>
    <p>Алексей — веб-разработчик с 5-летним опытом.</p>

    <h3>Похожие статьи</h3>
    <ul>
        <li><a href="article2.html">Как выбрать мышку</a></li>
        <li><a href="article3.html">Лучшие мониторы 2026</a></li>
    </ul>
</aside>

<details> и <summary> — раскрывающийся блок

Интересный интерактивный элемент — без JavaScript! Пользователь может раскрыть/скрыть содержимое кликом:

<details>
    <summary>Нажми, чтобы узнать больше</summary>
    <p>Этот текст скрыт по умолчанию.
    Он появится, когда пользователь нажмёт на заголовок.</p>
</details>
Нажми, чтобы узнать больше

Этот текст скрыт по умолчанию. Он появится, когда пользователь нажмёт на заголовок.

Отлично подходит для: FAQ, спойлеры, дополнительная информация, настройки.

<time> — дата и время

<p>Опубликовано <time datetime="2026-03-14">14 марта 2026</time></p>

Атрибут datetime содержит машиночитаемую дату — для поисковиков и скринридеров.

Тег <details> активно используется на GitHub для скрытия логов, длинного кода и описаний. На многих сайтах с FAQ каждый вопрос — это <details>, а текст вопроса — <summary>.

  • Семантика = теги со смыслом (вместо бессмысленных div)
  • 3 причины: SEO (Google), доступность (скринридеры), читаемость (разработчики)
  • <header> — шапка, <nav> — навигация, <footer> — подвал
  • <main> — основной контент (один на странице!)
  • <article> — самостоятельный контент (может жить отдельно)
  • <section> — тематический раздел (часть чего-то большего)
  • <aside> — боковой контент, <details> — раскрывающийся блок

Мысленно ответьте:

  1. Сколько <main> может быть на странице? (Один!)
  2. Чем <article> отличается от <section>? (article самостоятелен — можно вырезать и вставить в другое место. section — часть целого)
  3. Где размещать логотип сайта? (В <header>)
  4. Какой тег для бокового блока «Похожие статьи»? (<aside>)
  5. Как создать раскрывающийся FAQ без JavaScript? (<details> + <summary>)

11. Семантика vs div: сравнение

❌ Только div:

Правило: Используйте <div> только когда ни один семантический тег не подходит. Сначала подумайте: это шапка (header)? Навигация (nav)? Статья (article)? Раздел (section)? Если ничего не подходит — тогда div.

Новички часто оборачивают ВСЁ в <div> — даже когда есть подходящий семантический тег. Это как называть все блюда «еда»: «дайте мне еду» вместо «дайте мне борщ». Семантика делает код понятным.

12. Практика: семантическая страница блога

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Блог о технологиях</title>
</head>
<body>

    <!-- Шапка -->
    <header>
        <h1>TechBlog</h1>
        <p>Блог о технологиях и веб-разработке</p>
    </header>

    <!-- Навигация -->
    <nav>
        <ul>
            <li><a href="#">Главная</a></li>
            <li><a href="#">Статьи</a></li>
            <li><a href="#">О нас</a></li>
            <li><a href="#contacts">Контакты</a></li>
        </ul>
    </nav>

    <!-- Основной контент -->
    <main>

        <!-- Статья 1 -->
        <article>
            <h2>10 полезных HTML-тегов, о которых вы не знали</h2>
            <p><small>Автор: Мария | <time datetime="2026-03-10">10 марта 2026</time></small></p>

            <section>
                <h3>1. Тег &lt;details&gt;</h3>
                <p>Этот тег создаёт раскрывающийся блок без JavaScript...</p>
            </section>

            <section>
                <h3>2. Тег &lt;mark&gt;</h3>
                <p>Выделяет текст <mark>маркером</mark>...</p>
            </section>
        </article>

        <hr>

        <!-- Статья 2 -->
        <article>
            <h2>Как начать изучать веб-разработку</h2>
            <p><small>Автор: Алексей | <time datetime="2026-03-08">8 марта 2026</time></small></p>

            <p>Веб-разработка начинается с трёх технологий:</p>
            <ol>
                <li><strong>HTML</strong> — структура страницы</li>
                <li><strong>CSS</strong> — стилизация</li>
                <li><strong>JavaScript</strong> — интерактивность</li>
            </ol>

            <details>
                <summary>Полезные ресурсы для обучения</summary>
                <ul>
                    <li><a href="https://developer.mozilla.org">MDN Web Docs</a></li>
                    <li><a href="https://w3schools.com">W3Schools</a></li>
                </ul>
            </details>
        </article>

    </main>

    <!-- Боковая панель -->
    <aside>
        <h3>Популярные теги</h3>
        <ul>
            <li>HTML</li>
            <li>CSS</li>
            <li>JavaScript</li>
            <li>React</li>
        </ul>
    </aside>

    <!-- Подвал -->
    <footer id="contacts">
        <h3>Контакты</h3>
        <p>Email: <a href="mailto:blog@example.com">blog@example.com</a></p>
        <p>&copy; 2026 TechBlog. Все права защищены.</p>
    </footer>

</body>
</html>
  1. Создайте эту страницу и запустите через Live Server
  2. Откройте DevTools и найдите все семантические теги (header, nav, main, article, section, aside, footer)
  3. Измените тему блога на свою
  4. Добавьте третью статью (<article>) с разделами (<section>)
  5. Добавьте <details> с FAQ

Итоги занятия

  • <ul> — маркированный список (порядок не важен)
  • <ol> — нумерованный список (порядок важен). Атрибуты: type, start, reversed
  • <li> — элемент списка (используется в ul и ol)
  • Списки можно вкладывать друг в друга
  • <dl> + <dt> + <dd> — описательный список (термин-определение, FAQ, характеристики)
  • Навигация сайта = <nav><ul><li><a>
  • Семантика = теги со смыслом (вместо бессмысленных div)
  • <header> — шапка, <nav> — навигация, <main> — основной контент
  • <article> — самостоятельный контент, <section> — раздел
  • <aside> — боковой контент, <footer> — подвал
  • <details> + <summary> — раскрывающийся блок (без JS!)
  • &copy; — HTML-сущность для символа ©

Проверь себя перед заданиями:

  1. Какой тег используется для списка покупок? (<ul>)
  2. Какой тег для рецепта? (<ol>)
  3. Какой тег для словаря терминов? (<dl>)
  4. Сколько <main> может быть на странице? (Один!)
  5. Чем <article> отличается от <section>? (article самостоятелен, section — часть целого)
  6. Какой тег создаёт раскрывающийся блок без JS? (<details>)
