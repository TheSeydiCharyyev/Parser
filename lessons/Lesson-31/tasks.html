🎯 Lesson 31.1: TOPIC CHOICE AND INSPIRATION

Задание 30.1: Матрица выбора + сбор референсов Task 30.1: Choice matrix + reference collection
Лёгкое Easy 45 минут 45 min
Определиться с темой и собрать визуальную базу для проекта
Decide on a topic and collect visual reference for the project

Условие:

Instructions:

  1. Матрица выбора: Оцените каждую из 6 идей (портфолио, лендинг, музыка, магазин, фестиваль, туризм) по 5 критериям (интересна / есть контент / сложность / полезна карьере / работать 3 недели) от 1 до 5. Выберите идею с максимальной суммой.
  2. Конкретизация темы: Если выбрали «лендинг бизнеса» — уточните, какой именно бизнес (кофейня «Sladko», студия татуировок «InkLab», школа программирования «CodeAkhal»). Придумайте название, слоган.
  3. Сбор референсов: Откройте минимум 3 ресурса (Awwwards, Dribbble, Landbook, Pinterest, Figma Community). Соберите 10+ скриншотов сайтов по вашей теме.
  4. Папка: Создайте локальную папку проекта. Внутри — папка inspiration/. Сохраните туда все скриншоты с осмысленными именами (ref-01-awwwards.jpg, не Screenshot 2026-...).
  5. Анализ: Что общего у собранных референсов? 2-3 общих черты. Это будет ваш стиль.
  1. Choice matrix: Rate each of 6 ideas (portfolio, landing, music, store, festival, travel) on 5 criteria (interested / have content / complexity / career / 3 weeks work) from 1 to 5. Pick the idea with the max total.
  2. Specify topic: If you picked "business landing" — specify which business (coffee shop "Sladko", tattoo studio "InkLab", coding school "CodeAkhal"). Come up with a name, tagline.
  3. Collect references: Open at least 3 resources (Awwwards, Dribbble, Landbook, Pinterest, Figma Community). Collect 10+ screenshots of sites on your topic.
  4. Folder: Create a local project folder. Inside — inspiration/ folder. Save all screenshots there with meaningful names (ref-01-awwwards.jpg, not Screenshot 2026-...).
  5. Analysis: What do references have in common? 2-3 common traits. That will be your style.
Как брать скриншот с Awwwards: откройте сайт → увидели интересный пример → F12 → iPhone режим (или 1440px для десктопа) → Cmd/Ctrl + Shift + S → Capture full size screenshot.

Pinterest-лайфхак: «web design [ваша тема]» в поиске → выбираете 10 лучших → правый клик → Сохранить картинку.

🎯 УРОК 31.2: SITEMAP + WIREFRAMES + ПАЛИТРА

🎯 Lesson 31.2: SITEMAP + WIREFRAMES + PALETTE

Задание 30.2: Спланировать структуру и дизайн Task 30.2: Plan structure and design
Среднее Medium 45 минут 45 min
Создать полный план проекта: страницы, wireframes, палитра, шрифты
Create a full project plan: pages, wireframes, palette, fonts

Условие:

Instructions:

  1. plan.md: Создайте файл в корне проекта. Внутри должно быть:
    • Название проекта + слоган
    • Sitemap: список страниц (3-5 штук) + что на каждой
    • Описание компонентов, повторяющихся на разных страницах
  2. Wireframes: Нарисуйте скелеты всех страниц. Инструменты:
    • Бумага + ручка (сфотографируйте → inspiration/wireframes/)
    • ИЛИ tldraw.com / excalidraw.com (экспорт в PNG)
    • ИЛИ Figma с прямоугольниками
    Без цветов, без красоты — только прямоугольники для каждого блока.
  3. Палитра (5-8 цветов): Откройте coolors.co или tailwindcss.com/docs/customizing-colors. Выберите:
    • Primary (основной цвет бренда)
    • Primary Dark (hover-состояние)
    • Accent (для выделений, редко)
    • Text (основной текст)
    • Text Muted (второстепенный)
    • Background (белый или очень светлый)
    • Background Alt (для альтернативных секций)
    • Border
    Все в HEX.
  4. Шрифты из Google Fonts: Выберите 1-2 шрифта. Для начинающих рекомендуется Inter (один шрифт на всё). Продвинутый вариант: Poppins для заголовков + Inter для текста.
  5. Размеры шрифтов: Определите размеры для h1, h2, h3, body, small. Типовые: 48/32/20/16/14.
  6. Запишите всё в конспект (student.html) в соответствующие write-box поля.
  1. plan.md: Create the file at the project root. Should contain:
    • Project name + tagline
    • Sitemap: page list (3-5 pages) + what's on each
    • Description of components shared across pages
  2. Wireframes: Draw skeletons of all pages. Tools:
    • Paper + pen (photograph → inspiration/wireframes/)
    • OR tldraw.com / excalidraw.com (export to PNG)
    • OR Figma with rectangles
    No colors, no beauty — just rectangles for each block.
  3. Palette (5-8 colors): Open coolors.co or tailwindcss.com/docs/customizing-colors. Pick:
    • Primary (main brand color)
    • Primary Dark (hover state)
    • Accent (for highlights, rare)
    • Text (main text)
    • Text Muted (secondary)
    • Background (white or very light)
    • Background Alt (for alternate sections)
    • Border
    All in HEX.
  4. Fonts from Google Fonts: Pick 1-2 fonts. For beginners — Inter (one font for everything). Advanced: Poppins for headings + Inter for body.
  5. Font sizes: Define sizes for h1, h2, h3, body, small. Typical: 48/32/20/16/14.
  6. Record everything in notes (student.html) in the corresponding write-box fields.

🎯 Lesson 31.3: PROJECT STRUCTURE + GIT

Задание 30.3: Настроить проект и загрузить на GitHub Task 30.3: Set up the project and push to GitHub
Среднее Medium 45 минут 45 min
Создать структуру проекта, tokens.css, git-репозиторий на GitHub
Create project structure, tokens.css, GitHub repo

Условие:

Instructions:

  1. Структура папок: Создайте все нужные папки и пустые файлы: 
    my-project/
├── index.html       (пустой с базовым HTML)
├── about.html       (пустой)
├── contact.html     (пустой)
├── css/
│   ├── tokens.css
│   ├── base.css
│   ├── components.css
│   └── style.css
├── images/          (пока пусто)
├── icons/           (пока пусто)
├── inspiration/     (уже есть)
├── README.md
├── plan.md          (уже есть)
└── .gitignore
  2. tokens.css: Заполните всё, что определили в задании 30.2:
    • Все цвета как CSS-переменные в :root
    • Шрифты и размеры (--font-primary, --fs-h1, ...)
    • Spacing (--space-sm, --space-md, ...)
    • Radii и shadows
  3. base.css: Базовые стили: 
    * { margin: 0; padding: 0; box-sizing: border-box; }

html { scroll-behavior: smooth; }

body {
    font-family: var(--font-primary);
    font-size: var(--fs-body);
    color: var(--color-text);
    line-height: 1.6;
}

img { max-width: 100%; height: auto; display: block; }

.container {
    width: 90%;
    max-width: 1200px;
    margin: 0 auto;
}
  4. README.md: Черновая версия по шаблону из лекции (название, demo-placeholder, страницы, tech stack, автор).
  5. .gitignore: 
    .DS_Store
node_modules/
*.log
.vscode/
.idea/
  6. Git: 
    git init
git add .
git commit -m "Initial setup: plan, tokens, folder structure"
  7. GitHub-репозиторий:
    • Зайдите на github.com → New repository
    • Имя = название проекта
    • Visibility: Public (важно для GitHub Pages)
    • НЕ создавайте README (он уже есть локально)
    • Нажмите Create
  8. Push на GitHub: 
    git remote add origin https://github.com/USERNAME/PROJECT.git
git branch -M main
git push -u origin main
  9. Проверка: Откройте репозиторий в браузере — все файлы должны быть видны. README.md должен отображаться на главной странице.
  1. Folder structure: Create all needed folders and empty files: 
    my-project/
├── index.html       (empty with base HTML)
├── about.html       (empty)
├── contact.html     (empty)
├── css/
│   ├── tokens.css
│   ├── base.css
│   ├── components.css
│   └── style.css
├── images/          (empty for now)
├── icons/           (empty for now)
├── inspiration/     (already exists)
├── README.md
├── plan.md          (already exists)
└── .gitignore
  2. tokens.css: Fill in everything from task 30.2:
    • All colors as CSS variables in :root
    • Fonts and sizes (--font-primary, --fs-h1, ...)
    • Spacing (--space-sm, --space-md, ...)
    • Radii and shadows
  3. base.css: Base styles: 
    * { margin: 0; padding: 0; box-sizing: border-box; }

html { scroll-behavior: smooth; }

body {
    font-family: var(--font-primary);
    font-size: var(--fs-body);
    color: var(--color-text);
    line-height: 1.6;
}

img { max-width: 100%; height: auto; display: block; }

.container {
    width: 90%;
    max-width: 1200px;
    margin: 0 auto;

  4. README.md: Draft version per lecture template (name, demo placeholder, pages, tech stack, author).
  5. .gitignore: 
    .DS_Store
node_modules/
*.log
.vscode/
.idea/
  6. Git: 
    git init
git add .
git commit -m "Initial setup: plan, tokens, folder structure"
  7. GitHub repo:
    • Go to github.com → New repository
    • Name = project name
    • Visibility: Public (important for GitHub Pages)
    • DON'T create README (already exists locally)
    • Click Create
  8. Push to GitHub: 
    git remote add origin https://github.com/USERNAME/PROJECT.git
git branch -M main
git push -u origin main
  9. Check: Open the repo in the browser — all files should be visible. README.md should display on the main page.

Задание 30.4: Детальный mood-board в Figma Task 30.4: Detailed mood-board in Figma
Сложное Hard 30 минут 30 min
Собрать визуальную доску в Figma для дизайн-направления
Assemble a visual mood-board in Figma for design direction

Условие:

Instructions:

  1. Создайте новый Figma-файл с именем вашего проекта
  2. Разместите на одной странице:
    • Референсы: 10+ скриншотов из inspiration/ рядом друг с другом
    • Палитра: 8 цветных квадратов (каждый с HEX-подписью)
    • Типографика: «The quick brown fox» в 5 размерах (h1-small) выбранным шрифтом
    • Компоненты: нарисуйте 3 варианта кнопок (primary, secondary, outline) и 1 карточку
  3. Дайте ссылку на Figma-файл преподавателю
  4. Экспортируйте mood-board как PNG в inspiration/mood-board.png
  1. Create a new Figma file with your project name
  2. Place on one page:
    • References: 10+ screenshots from inspiration/ side by side
    • Palette: 8 colored squares (each labeled with HEX)
    • Typography: "The quick brown fox" in 5 sizes (h1-small) with your chosen font
    • Components: draw 3 button variants (primary, secondary, outline) and 1 card
  3. Share the Figma link with the instructor
  4. Export the mood-board as PNG to inspiration/mood-board.png
Mood-board нужен не только вам, но и дизайнеру/преподавателю. Один взгляд — и ясно, в каком направлении проект. Профессиональная практика.
A mood-board is needed not only by you but also by the designer/instructor. One look — and it's clear which direction the project is taking. Professional practice.
