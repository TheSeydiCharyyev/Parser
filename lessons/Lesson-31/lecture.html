1. Зачем вообще планировать

1. Why plan at all

«Не буду тратить время на планирование — сразу начну кодить, разберусь по ходу!» — классическое заблуждение новичка. Правда в том, что час планирования экономит 3 часа разработки. Это не моё мнение — это статистика любой команды разработки.

Без плана вы сталкиваетесь с одним и тем же сценарием: начали делать header → понял, что нужна отдельная страница About → переделал навигацию → логотип не смотрится с новой палитрой → перекрасил всё → 4 часа прошло, готова только половина одной страницы.

"I won't waste time planning — I'll just start coding and figure it out!" — classic beginner mistake. Truth: one hour of planning saves three hours of development. Not my opinion — it's the statistics of any dev team.

Without a plan you hit the same scenario: start building header → realize you need a separate About page → redo navigation → logo doesn't fit the new palette → recolor everything → 4 hours gone, half a page is done.

❌ Без плана
❌ No plan

3 недели работы:
• Переделывали palette 3 раза
• Менять навигацию пришлось 5 раз
• Половина страниц не согласованы стилистически
• К концу не хватило времени на адаптив
• Проект «собран на скотче» — стыдно показывать

✅ С планом
✅ With plan

3 недели работы:
• 2 дня на планирование
• Решения приняты один раз
• Все страницы в одном стиле
• Хватило времени на полировку
• Есть что показать работодателю

Строительство дома vs постройка скворечника. Скворечник собирают «на глаз» — ошибка стоит дерева. Дом строят по чертежу — ошибка стоит миллионов. Финальный проект — это не скворечник. Это ваша визитка. План обязателен.

Building a house vs a birdhouse. Birdhouse gets thrown together "by eye" — mistake costs wood. House is built from blueprints — mistake costs millions. Your final project isn't a birdhouse. It's your business card. Planning is mandatory.

2. 5 критериев хорошего проекта для портфолио

2. 5 criteria of a good portfolio project

Не каждый проект одинаково хорош для портфолио. Работодатель смотрит на ваш GitHub — и должен увидеть, что вы не просто повторили урок, а способны самостоятельно довести проект до конца. Есть 5 чётких критериев, которые отличают хороший портфолио-проект от слабого.

Not every project is equally good for a portfolio. An employer looks at your GitHub — and should see that you didn't just repeat a lesson, but can take a project to completion independently. There are 5 clear criteria that separate a good portfolio project from a weak one.

#КритерийПочему важно
1Многостраничность (3+ страницы)Показывает, что вы умеете навигацию, общие компоненты, роутинг
2Адаптив (3 breakpoint'а)Mobile, tablet, desktop — без этого 2025 год непростим
3ИнтерактивностьHover, transition, формы, бургер — сайт не «картонный»
4Реальная темаНе «lorem ipsum» — реальные тексты, реальные фото
5ЗадеплоенПубличная ссылка — работодатель сможет открыть за 1 клик
#CriterionWhy it matters
1Multi-page (3+ pages)Shows you can do navigation, shared components, routing
2Responsive (3 breakpoints)Mobile, tablet, desktop — unforgivable in 2025 without it
3InteractiveHover, transition, forms, burger — the site isn't "cardboard"
4Real contentNot "lorem ipsum" — real text, real photos
5DeployedPublic URL — employer opens it in one click

Бонусы, которые выделяют портфолио:

  • Dark mode (переключатель темы)
  • Анимации при загрузке и скролле (scroll-based)
  • Бургер-меню на CSS (без JS)
  • Читаемый код с комментариями
  • README.md в репозитории с описанием и скриншотами

Bonuses that make a portfolio stand out:

  • Dark mode (theme toggle)
  • Load and scroll animations
  • CSS-only burger menu (no JS)
  • Clean code with comments
  • README.md in the repo with description and screenshots

3. 6 идей финального проекта (разбор)

3. 6 final project ideas (breakdown)

Вот 6 проверенных идей. Они разной сложности, но все подходят для портфолио junior-разработчика. Под каждой я напишу плюсы, минусы и примеры реальных сайтов для вдохновения. Выберете одну — её и будете делать 3 недели.

Here are 6 proven ideas. Different complexity, but all suitable for a junior portfolio. Under each — pros, cons, and examples of real sites for inspiration. Pick one — that's what you'll build for 3 weeks.

3.1. Сайт-портфолио (ваш личный)

3.1. Personal portfolio site

Страницы: Главная, About, Projects (список), Project Detail, Contact.

Плюсы: Реальный контент (ваш) — показываете работодателю сразу две вещи: навыки и сам сайт. «Убиваете двух зайцев». Самый практичный выбор.

Минусы: Нужны реальные проекты для раздела Projects. Если их нет — делайте раздел «Learning» с курсовыми заданиями.

Вдохновение: brittanychiang.com, bencubbage.com, любой сайт разработчика на Awwwards.

Pages: Home, About, Projects (list), Project Detail, Contact.

Pros: Real content (yours) — you show the employer two things at once: skills and the site itself. Practical choice.

Cons: Needs real projects for the Projects section. If you don't have any — make a "Learning" section with course exercises.

Inspiration: brittanychiang.com, bencubbage.com, any dev site on Awwwards.

3.2. Лендинг для бизнеса

3.2. Business landing page

Страницы: Главная (все секции), Services (детали), Pricing, Contact.

Плюсы: Классика вёрстки. Много hero-секций, features, cards, форм. Тренирует все навыки. Легко найти Figma-макет в Community.

Минусы: «Как у всех» — не выделяется. Компенсируйте оригинальной темой: не «компания по разработке», а «студия татуировок» или «мастерская ножей».

Вдохновение: landbook.com, awwwards.com.

Pages: Home (all sections), Services (details), Pricing, Contact.

Pros: Coding classic. Lots of hero sections, features, cards, forms. Trains all skills. Easy to find Figma mockups in Community.

Cons: "Like everyone else" — doesn't stand out. Compensate with an original theme: not "dev agency" but "tattoo studio" or "knife workshop".

Inspiration: landbook.com, awwwards.com.

3.3. Сайт музыкальной группы / исполнителя

3.3. Music band / artist site

Страницы: Главная (обложка), Music (альбомы), Tour (даты концертов), About, Contact.

Плюсы: Эмоциональный, красочный. Много работы с изображениями, типографикой, видео. Запоминается на собеседовании.

Минусы: Нужны качественные фото группы/музыки — можно взять любой реальной группы с их пресс-кит.

Вдохновение: официальные сайты крупных артистов (Billie Eilish, Arctic Monkeys, HOZIER), Bandcamp-страницы.

Pages: Home (cover), Music (albums), Tour (concert dates), About, Contact.

Pros: Emotional, colorful. Lots of work with images, typography, video. Memorable at interviews.

Cons: Needs good band/music photos — can use any real band's press kit.

Inspiration: official sites of major artists (Billie Eilish, Arctic Monkeys, HOZIER), Bandcamp pages.

3.4. Интернет-магазин (вёрстка)

3.4. E-commerce (markup only)

Страницы: Главная (витрина), Catalog (категории), Product Detail, Cart, Checkout.

Плюсы: Показывает серьёзную вёрстку: карточки товаров, фильтры, формы, таблицы. Реалистичный проект.

Минусы: Сложнее других. Корзина и checkout требуют времени. Внимание: только вёрстка, без реального функционала — это HTML/CSS-курс.

Вдохновение: реальные магазины (ASOS, Amazon, ZARA), Dribbble «e-commerce».

Pages: Home (showcase), Catalog (categories), Product Detail, Cart, Checkout.

Pros: Shows serious coding: product cards, filters, forms, tables. Realistic project.

Cons: More complex than others. Cart and checkout take time. Important: markup only, no real functionality — this is an HTML/CSS course.

Inspiration: real stores (ASOS, Amazon, ZARA), Dribbble "e-commerce".

3.5. Сайт мероприятия / фестиваля

3.5. Event / festival site

Страницы: Главная (дата + кнопка Register), Schedule (программа), Speakers (спикеры), Venue (место), Tickets, Contact.

Плюсы: Яркий дизайн, таблицы с расписанием, карточки спикеров, карта. Интересно верстать.

Минусы: Нужна креативная идея (конференция, фестиваль, выставка). Придумайте что-то местное: «Ашхабад JS Conf», «Ковровый фестиваль в Мары».

Вдохновение: сайты React Summit, JSConf, любой IT-конференции.

Pages: Home (date + Register button), Schedule, Speakers, Venue, Tickets, Contact.

Pros: Vivid design, schedule tables, speaker cards, maps. Fun to code.

Cons: Needs a creative idea (conference, festival, exhibition). Come up with something local: "Ashgabat JS Conf", "Mary Carpet Festival".

Inspiration: React Summit, JSConf, any IT conference site.

3.6. Туристический сайт

3.6. Travel site

Страницы: Главная (направления), Destinations (каталог стран), Destination Detail (страна/город), Blog, Contact.

Плюсы: Красивые фотографии, галереи, много свободы дизайна. Легко сделать «вау-эффект».

Минусы: Фото нужны реальные качественные. Берите с Unsplash (бесплатно, 4K качество).

Вдохновение: airbnb.com, booking.com, национальные тур-сайты.

Pages: Home (destinations), Destinations (country catalog), Destination Detail, Blog, Contact.

Pros: Beautiful photos, galleries, lots of design freedom. Easy to create a "wow" effect.

Cons: Needs real quality photos. Grab from Unsplash (free, 4K quality).

Inspiration: airbnb.com, booking.com, national tourism sites.

4. Матрица выбора: какой проект ваш?

4. Choice matrix: which project is yours?

Не можете выбрать? Это нормально. Используйте матрицу: оцените каждую идею по 5 критериям от 1 до 5. Идея с максимальной суммой — ваш проект. Это не наука, а инструмент чтобы перестать колебаться и начать.

Can't decide? Normal. Use the matrix: rate each idea on 5 criteria from 1 to 5. The idea with the max total is your project. Not science — a tool to stop hesitating and start.

Если нет очевидного лидера — берите сайт-портфолио. Это универсальный выбор. Плюсы для карьеры: покажете сразу на собеседовании. Минусы: нужны реальные проекты — но у вас есть 29 уроков курса, превратите их в секцию «Learning».

No clear winner? Go with the portfolio site. Universal choice. Career benefit: show it immediately at interviews. Downside: needs real projects — but you have 29 course lessons, turn them into a "Learning" section.

Не выбирайте тему, которая вам не интересна. «Тренажёрный зал» звучит классно, но если вы 3 недели должны работать над сайтом фитнеса — а спорт не любите — вы возненавидите проект на 4-й день. Выбирайте то, что реально нравится. Работа в удовольствие = лучший результат.

Don't pick a theme you don't care about. "Gym" sounds cool, but if you have to work on a fitness site for 3 weeks — and you don't like sports — you'll hate the project by day 4. Pick what you actually enjoy. Work with pleasure = best result.

5. Где брать вдохновение

5. Where to find inspiration

«Придумать всё из головы» — плохая стратегия. Дизайнеры смотрят десятки примеров перед тем как рисовать. Вы — тем более. Собирайте визуальный референс в папку или Pinterest-доску до того, как начнёте вёрстку. Чем больше насмотренность — тем лучше дизайн.

"Make it up from scratch" is a bad strategy. Designers look at dozens of examples before drawing. You — even more so. Collect a visual reference in a folder or Pinterest board before coding. The more examples you see — the better the design.

Процесс сбора референсов:

  1. Создайте папку inspiration/ в проекте
  2. Соберите 10-15 скриншотов с разных ресурсов — что вам нравится
  3. Определите общие черты: «везде крупный hero», «минимализм», «большие фото»
  4. Это будет ваш стиль

Reference collection process:

  1. Create an inspiration/ folder in the project
  2. Collect 10-15 screenshots from different resources — what you like
  3. Identify common traits: "big hero everywhere", "minimalism", "large photos"
  4. That's your style
Вдохновляться ≠ копировать! Если скопируете дизайн 1 в 1 — это плагиат. Берите из одного сайта цветовую палитру, из другого — типографику, из третьего — структуру hero. Ваш проект = микс идей, а не копия.
Inspiration ≠ copying! If you copy a design 1:1 — that's plagiarism. Take a color palette from one site, typography from another, hero structure from a third. Your project = a mix of ideas, not a clone.

7. Sitemap — карта страниц

7. Sitemap — page map

Sitemap — это список всех страниц вашего сайта и связи между ними. Рисуется за 10 минут на бумаге. Даёт чёткое понимание: сколько HTML-файлов нужно создать, какая навигация, что содержит каждая страница.

Sitemap — a list of all pages on your site and the links between them. Drawn in 10 min on paper. Gives a clear picture: how many HTML files to create, what navigation, what each page contains.

Пример sitemap для сайта-портфолио: ┌─────────────┐ │ Главная │ (index.html) │ (Home) │ └──┬───┬───┬──┘ │ │ │ ┌──▼─┐ │ ┌─▼────┐ │About│ │ │Contact│ └─────┘ │ └──────┘ │ ┌────▼────┐ │Projects │ (projects.html) └────┬────┘ │ ┌────▼──────┐ │Project │ (project.html, детальная) │Detail │ └───────────┘

8. Wireframe — скелет каждой страницы

8. Wireframe — skeleton of each page

Wireframe — это схематичный набросок страницы: прямоугольники вместо реальных блоков, без цветов, без красоты. Цель — увидеть структуру. Делается на бумаге или в Figma/tldraw за 15-30 минут на страницу.

Зачем? Когда структура ясна — вёрстка идёт в 3 раза быстрее. Не нужно думать «а где разместить features» — решение принято заранее.

Wireframe — a schematic sketch of a page: rectangles instead of real blocks, no colors, no beauty. Goal — see the structure. Done on paper or in Figma/tldraw in 15-30 min per page.

Why? When structure is clear — coding is 3× faster. No need to think "where to place features" — decided in advance.

Инструменты для wireframe (на выбор):

  • Бумага + ручка — самый быстрый способ (5 минут на страницу)
  • tldraw.com — онлайн, простой как бумага, бесплатно

Не тратьте время на красивые wireframe. Ваша задача — быстро накидать структуру, не делать произведение искусства.

Wireframe tools (pick one):

  • Paper + pen — fastest (5 min per page)
  • tldraw.com — online, simple as paper, free
  • Excalidraw.com — online sketching, free
  • Figma — if already in Figma, use rectangles

Don't waste time on pretty wireframes. Your goal — quickly sketch the structure, not make art.

9. Design tokens: цвета, шрифты, spacing

9. Design tokens: colors, fonts, spacing

Помните урок 29? Design tokens — это визуальный словарь вашего проекта: цвета, шрифты, отступы. Определите их до написания HTML/CSS, сохраните в tokens.css, используйте только через переменные.

Remember lesson 29? Design tokens — the visual vocabulary of your project: colors, fonts, spacing. Define them before writing HTML/CSS, save in tokens.css, use only via variables.

Цветовая палитра — шаблон:

:root {

    --color-accent: #F59E0B;        /* Акцент (редко, для выделений) */

    /* Текст */
    --color-text: #1E293B;          /* Основной текст */

10. Настройка проекта: git + структура папок

10. Project setup: git + folder structure

Финальный проект должен быть в git-репозитории с первого дня. Почему? Чтобы показать на собеседовании GitHub-ссылку. Чтобы видеть историю изменений. Чтобы деплоить через GitHub Pages.

The final project must be in a git repo from day one. Why? To show a GitHub link at an interview. To see change history. To deploy via GitHub Pages.
